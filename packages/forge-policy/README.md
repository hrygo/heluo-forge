# @heluo/forge-policy

状态：可用（受控动作目录与统一门禁骨架；未接企业环境，未做双端实机）

一句话：把"哪些动作可做"登记成目录，并在宿主工具管线与命令面上用同一判定兑现；目录无效、未登记、未开放、目标缺失或确认通道不可用时一律拒绝。

| 项 | 内容 |
|---|---|
| 形态 | Host 插件（提供 `policy` 服务） |
| 职责 | 工具门禁、路径规则、`$DSH_HOME` 硬拒绝、客户数据外发确认、决策审计 |
| 不负责 | 不替代服务端鉴权，不维护独立 hook 引擎 |
| 衔接点 | `tools.guard`（单调硬拒绝）、`tools/pre-execute`（需确认动作）、`ctx.commands`（命令面）、`otel` |
| 详细设计 | [详细设计](../../docs/design/plugins/forge-policy.md)（草案；§5.1 受控动作目录与统一门禁） |
| 实现状态 | 目录编译与判定、guard 与确认阶段、命令包装、卸载清理已实现并有离线用例；审计落点（P03）、路径规则与 C3 外发（P04）未实现 |

## 当前实现

| 项 | 状态 |
|---|---|
| 目录 | `compileCatalog`：字段校验、重复动作拒绝、缺省 `retry` 按 kind 推导；无效目录抛错而不是静默缩小 |
| 判定 | `decideAction`：未登记 / 未开放 / 目标缺失 / 出网禁止一律拒绝；`confirm` 类返回需确认；**自报 `readOnly` 等声明不参与任何规则** |
| 工具面 | `ctx.tools.guard` 单调拒绝；`confirm` 动作若未经确认阶段一律拒绝（fail closed） |
| 命令面 | `policy.registerCommand`：未登记动作拒绝注册；处理前走同一判定，拒绝或未确认时**不执行**处理函数 |
| 覆盖范围 | 只处理被显式登记为业务动作的工具，以及显式声明的类别（如 `bash → shell.exec`）；未登记的工具不属于本门禁作用域，不声称覆盖 |
| 生命周期 | `ctx.effect` 登记卸载：guard、确认阶段与 `policy` 服务一并撤销；已挂载时拒绝再次挂载 |
| 安全 | 目录无效或宿主缺少 `tools.guard` 时拒绝挂载；**不提供 fail-open、通用 `run(command)` 或正则黑名单式保证** |

## 边界

- 工具自报的 `mutating` 仅作提示，读写与环境按可信目标与受控清单判定；无法分类的风险工具拒绝。
- 客户数据外发（C3）转本机确认，`never`、无 UI、取消、超时或异常均不视为确认。
- 审计记录主体、工具、决策、原因码与耗时，不记参数正文（落点由 P03 实现）。
- 客户端策略不能替代服务端授权；本机管理员可改配置，因此服务端仍须独立鉴权。
- 命令面：宿主当前版本没有全局命令拦截 seam，本包只能对**经本包登记**的命令兑现同一判定；其他插件注册的命令不在其内，不声称已覆盖。
