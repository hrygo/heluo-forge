# 企业私有 npm 接入

状态：正式技术方案已形成评审稿；企业接入、配置资产和安装开放仍待 G1/G2 核验。

[ADR-11/12](<../../docs/architecture/plugin-registry-source-decision.md>)确定企业 npm 为唯一插件制品源，仓库可同步公网，内部定制源码固定 Gitee group；管理员维护源地址和精确插件包名两层白名单，不逐版本审批。**首版只自动收录自包含、Windows/麒麟双端通用稳定包**，不由终端另行解析 npm 运行时依赖。

本仓库不自研 registry，不据方案宣称企业产品、认证或全通道白名单已验证。当前代码仍是 Gitee tag 归档参考；此处不是已可执行的生产配置。字段和安装流程分别见[索引生成契约](<../../docs/design/services/market-index.md>)与[插件设计](<../../docs/design/plugins/forge-market.md>)。

## 职责

| 对象 | 负责什么 | 不负责什么 |
|---|---|---|
| 企业 npm 维护方 | 公网同步、内部制品、下载/发布权限、不可变包体、保留恢复与实际可证明的 ACL | 不把所有同步包自动当市场准入，不向终端开放公网备用源 |
| 管理员/平台组 | 双层清单；平台方另维护目标 DSH/终端发行矩阵、profile 基线与适配 | 不人工逐版录版本/摘要，不建默认审批数据库 |
| CI/索引生成器 | 只读企业源、检查真实发布包/自包含/稳定版/双端交集，发布原生索引与独立控制证据 | 不构建候选源码、不改写包体，不把 sidecar 当原生 schema |
| 内部构建发布方 | 固定 Gitee 源码构建自包含产物，保留 repo/commit/包版本/摘要与发布关联 | 不因源码浏览权取得任意 npm 发布权 |
| DSH 受管入口 | UI/工具共用 Host，在线核对当前授权后调用官方管理器，准确呈现阶段与恢复状态 | 不自造安装器、不私写 profile，不把缓存或 pnpm 成功当激活成功 |

## 已定运行契约

1. **单 profile 单规范源。** 每个环境可选不同白名单入口，但同一 profile 只绑定一个规范 HTTPS 企业聚合 registry，官方 `fallbackRegistries` 必须为空。后端多仓优先由既有私服聚合，不跨源混装来绕过缺包。
2. **自包含和发行基线。** 实际包不声明需要终端取包的运行/optional/bundled 依赖；peer 只能由已核验 DSH 基线满足，不自动补装。禁止终端触发的安装脚本、隐式 native 编译与外部 CDN；普通上游 build/test 不按键名误拒。profile 的既有依赖、manifest/lock、pnpmfile/override 与配置覆盖均须通过基线核对，存量不自动清理。
3. **联网是企业内网，不是公网。** registry、metadata/tarball、索引、当前授权与展示资源只走获准内网 HTTPS/企业 CA，不关闭证书校验。内部 scope 缺包拒绝，不代理公网同名包；本机 HTTP 仿服务仅属隔离测试。
4. **浏览与安装分离。** 缓存可过期浏览，每次写前必须在线取得当前可信授权；控制产物过期、许可未知或输入变更时拒绝。准入决定不超过 60 秒且不得超过当前控制许可期限。CI 续期或发布失败不能使旧授权永久有效。
5. **物理边界另验。** 原生任意 spec、本地路径/Git/tarball、CLI、其他市场、角色及撤回必须列实际覆盖与拒绝证据；隐藏 UI 或禁单一工具不是服务端授权。无法等价治理时市场只读，但不能因此判 REQ-14/G2 已通过，不承诺防恶意本机管理员。
6. **更新不是原子替换。** 按官方移除后安装精确目标版，保存启用意图、披露层顺序变化；移除失败即停，后续失败标记旧版已移除/待恢复，按当前许可恢复精确旧版。启动包按官方停机/CLI/重启路径，不手改 profile。
7. **发布不回退许可。** 既有 CI 单写串行、发布前复核当前输入，候选完整校验后原子切换；旧慢任务不能覆盖新删除/隔离。恢复历史制品先按当前许可重验并升发布代次，不恢复已撤销包。

## 企业事实与责任核验

| 接入事实 | 回答责任方 | 关闭要求 |
|---|---|---|
| 产品、单环境规范 registry、metadata/tarball/存储出口、企业 CA/代理与容量 | 企业仓库维护方、IT | G1 契约；G2 单 profile 正反向取包证据 |
| 同步范围/节奏、预热留存、上游失败/缺包、内部 scope 权威解析 | 仓库维护方，安全核验 | 公网不可达但内网及当前授权可达时可装已留存自包含包；缺包不换源 |
| 逻辑视图/ACL 与终端策略对源/包/版本/角色/本地 spec/缓存的实际强制覆盖 | 仓库维护方、IT、安全、平台 | 按正式方案列允许/拒绝/未覆盖；不足只读，不把目录过滤当强授权 |
| 下载与发布身份、受控凭据注入/轮换/撤销 | 仓库维护方、IAM/安全 | 最小权限；不假设 IAM token 通用于 npm |
| 同名同版本不可覆盖、隔离/撤回阻断、制品/元数据/证据恢复 | 仓库维护方、IT、平台 | 负向取包、旧缓存与两步恢复演练，不以 deprecate 或删索引代替 |
| 既有 CI、HTTPS 静态托管、当前控制许可续期、串行/原子切换与防陈旧发布 | 平台与 CI/分发维护方 | G1 配置核验；G2 故障后授权到期只读及发布竞态证据 |
| 目标 DSH/Node/pnpm/SDK、Windows 参数、麒麟矩阵和受管 profile | 平台发行方、IT | 生成与安装开启前冻结，双端入口及生命周期实测 |
| tarball 日志与指标、归因、保留和支持 | 仓库维护方、安全、平台 | 可选展示时再接入，区分同步/下载/安装/激活；缓存不冒充下载 |

来源、自包含双端首版和恢复行为不再待决；上表仅核实企业能力、运行责任与证据。紧急撤回优先执行既有 registry/终端止损，当前策略更新后核对生效，不能把 Git 合并或索引删除当成已完成撤权。

不在本仓库保存真实地址、token、证书私钥或生产配置；敏感参数经批准的受控渠道提供。正式技术方案发布不触发真实同步、安装、部署或 npm 发布。
