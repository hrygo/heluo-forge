| 项 | 内容 |

| 目标 | 承载 `@corp/dsh-*` 内部包的私有 npm 制品存储 |
| 首选 | 复用企业现有 registry，不自研 |
| 备选 | 经评审的私有部署方案（如 Verdaccio 等），仅在企业无可用服务时考虑 |

## 需要确认

| 问题 | 需要谁回答 |
|---|---|
| 现有 registry 产品、可用性与容量 | IT |
| 认证方式、令牌签发与轮换 | IT、安全 |
| 备份、恢复与保留策略 | IT |
| 包命名空间与访问控制（按团队或全员可读） | 平台、IT |
| 是否允许代理公网包，以及白名单规则 | 安全、平台 |

## 边界

- 不在仓库写入 registry 地址、令牌或证书；由部署环境注入。
- 已发布版本不可变；撤回通过市场目录与通道完成，不删除历史制品。
- 制品上传前须通过构建与测试检查，上传权限与发布批准分离。
- 恢复演练证据属于 G2 门禁，不以配置文本替代。
