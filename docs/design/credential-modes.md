## 1. 结论

“双模式”表示选路评估，不表示运行时自动切换。个人候选 A 使用网关目标 Access Token，候选 B 同时使用该令牌及本人 Key。两者均需 DSH 用途、服务端模型/额度/网络授权、五分钟撤权及当前授权退出能力。成本接近优先 A，显著降低总成本且安全等效时可选 B；现阶段均未获能力验证。

原设计的 `static-key`、`token` 二选一提供者、`resolve(): { value }` 示意不能表达 B 的双凭据 AND 及归属校验，不作为本轮冻结接口。已有实现仍属原基线，状态以[设计索引](README.md#22-实现与验证入口)为准。

## 2. 职责与依赖

| 组件 | 本轮目标职责 | 待核验 |
|---|---|---|
| IAM 接入 | 获取可信人员及网关目标授权、刷新、当前授权退出、如实展示状态 | 公共客户端、AT 格式/受众、单授权及后代生命周期 |
| 模型接入 | 每次模型请求取所选路线所需凭据，保证用途元数据和错误/取消边界 | 实际 DSH seam 能否承载 A 或 B，是否需要最小适配 |
| 网关 | 验证当前人员、用途及策略；B 比较 Key owner，应用按受控主体授权 | 所有路由和认证入口覆盖、稳定映射、撤权及故障窗口 |
| 网关控制台 | 签发可选 Key、应用审批、IP/责任归属、人工更换 | 不要求额外签发 API；一次性展示及实际权限待确认 |

项目范围始终见[需求基线 §2](../requirements/requirements-baseline.md#2-范围边界唯一真源)。不默认新建身份代理、机器身份平台、自动轮换服务或修改 DSH 核心。

## 3. 凭据取用与一致性

A 仅发送面向网关的 Access Token，不用 ID Token。B 同时取得 IAM 授权与当前人绑定的个人 Key，缺一不可，不允许“有 Key 就忽略令牌”或“令牌失败就试 Key”。具体头、参数、资源名及配置值在提供方确认前不冻结，不虚构双凭据 API。

现有 `CredentialKey` / `CredentialRef` 与 `ENTERPRISE_STATIC_KEY` 是原接入依据；存储了录入时 `ownerSubject` 只记录“谁录入”，不能证明实际 Key 创建人或当前请求身份。真正归属比较必须在网关基于可信主体与服务端 owner 映射执行。选 A 后不要求用户创建个人静态 Key。

## 4. 存储与刷新

IAM 会话与可选 Key 分开管理，刷新结果不得覆盖静态 Key；秘密进入系统凭据库，不进配置明文、模型上下文、日志或诊断。生产 OS provider、迁移与双端隔离要求按 IAM 详细设计及 A4 核验，本轮不改变现有存储实现。

按操作解析凭据，检查/刷新/写回在锁内复核并单飞；网络刷新超时 ≤5 秒为原目标，不据此宣称锁等待上界。IAM 的轮换、重用检测、失败分类及多授权隔离须正式回函；锁只保护本地并发，不能替代服务端撤销刷新后代。

## 5. 用途识别与应用路径

个人请求携带轻量应用标识、接入协议版本及随机安装实例标识，字段名/位置待核验。不采集 MAC 或硬件序列号，不内置通用秘密作为强证明。实例用于关联，不是人的身份或撤销权限，接受授权者刻意仿冒风险。

无人值守 Agent 由网关按应用/环境受控开通，创建人用于治理而非运行时登录校验。DSH 内交互式 Agent 仍走个人路线。应用身份不加入个人请求的自动 fallback；具体管理入口及权限见网关契约。

## 6. 状态与失败

| 状态/事件 | 应有行为 |
|---|---|
| 未登录/授权缺失/目标资源错误 | 停止企业模型调用，说明是登录还是网关授权未就绪 |
| B 缺 Key 或人员不一致 | 停止调用，提示配置本人 Key 或联系管理员；不能据客户端比较就放行 |
| 用途/IP/模型未授权 | 展示可靠类别及处理入口，不无限刷新或换凭据绕过 |
| 到期/撤销/停用 | 按已确认生命周期处理，不把所有 401 统一解释为需重建 Key |
| IAM/验证/状态故障 | 只有能证明授权有效且仍守住五分钟时限才可继续，否则停止 |
| 429/未知执行结果 | 按预算或限流契约处置；已接收、已输出或未知结果不自动重放 |

续期和重新发送是两个决定；取得新令牌不能证明上一模型请求尚未执行。

## 7. 退出与撤权

遵循[评审稿 §4](../architecture/gateway-identity-review.md#4-撤权退出与故障的时间语义)与[网关契约 §4.1.1](../contracts/gateway-contract.md#411-生命周期与失败约束)。本地立即停止企业调用、清会话及副本、取消本地在途连接；默认只退出当前授权，不全局登出 SSO，不影响其他设备、应用 Agent 或默认撤销长期个人 Key。

服务端接受撤销后五分钟内，该授权及所有刷新后代不能继续访问，窗口内新发的 AT 同样受限；离线退出显示服务端未确认，不能从离线点击开始承诺五分钟。已接收流可按既有截止时间结束，后续模型调用重新判断。本地取消不保证上游停工或零费用。

## 8. 选路与验证前置

| 评审项 | A / B 共同要求 | 差异 |
|---|---|---|
| 身份与生命周期 | 网关目标授权、稳定人员、五分钟和单授权隔离 | B 另需 Key owner 比较 |
| 授权策略 | 模型、预算、IP、审计和正文关闭 | A 需要无 Key 等效挂载点，B 核验既有 Key 策略复用 |
| DSH 取用 | 请求级解析、错误分流、取消和安全重试 | B 双凭据承载尚未证明 |
| 成本 | 配置/开发/许可/联调/持续维护的实际评估 | A 省长期 Key 运维，B 可能省网关策略改造，待量化 |

用例沿用[评审稿 §7](../architecture/gateway-identity-review.md#7-验收细化)，挂既有 A1/A2/A3/A13/A14。路线未选定、契约未冻结前不把旧配置认定为新方案可用；关键能力不支持则相应路径不开放。
