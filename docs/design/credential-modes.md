## 1. 结论

本设计定义的“双模式”指系统支持的两类客户端身份运行态，而非运行时的自动降级切换：
1. **模式一（受管个人助手，路线 B 目标契约）**：受管研发与办公终端发起模型推理调用时，应执行双因子凭据协同认证。客户端在请求中同时携带个人长效凭据（`Authorization: Bearer uag-sk-u-...`）与员工当前有效的 IAM 身份令牌（`X-IAM-Token: <JWT>`）。网关按上游规范与企业 IAM 接入规范校验令牌有效性并比对 `sub` 与凭据绑定 `member_id`；在身份令牌能力尚未具备时，依据账号状态事件通道判定当前人存续状态，客户端上送的身份信息头不参与授权判定。
2. **模式二（无人值守应用 Agent）**：部署在服务器端后台运行的自动化流水线与批处理 Agent，使用经过申请审批的应用凭据（`uag-sk-a-...`），通过受限的 IP/CIDR 白名单和系统代码完成身份认证与调用，不强求实时人员在线交互。

两者均要求满足网关团队预算与个人配额管控、私有化私网部署（C1）与全程零正文日志留存（C4），并在 IAM 停用或凭据吊销后满足 5 分钟全网拦截的联调验收判据。

## 2. 职责与依赖

| 组件 | 核心职责 | 依赖与保障 |
|---|---|---|
| IAM 核心模块（`forge-iam`） | 负责管理用户统一登录会话，安全保管与刷新 IAM 令牌，向网关适配层提供当前会话令牌读取能力（接口形态待设计准入核验） | 依赖企业统一 OIDC / IAM 平台；令牌形态与取用接口待 IAM 书面确认 |
| 网关适配层（`forge-gateway`） | 负责组装双因子请求头，处理可配置的 `baseUrl` 相对拼接，拦截并解析网关流式保活心跳与标准错误码 | 依赖 `forge-iam` 注入的凭据与配置中心的 `baseUrl` 参数 |
| 企业级 AI 网关 | 验证个人长效凭据有效性，按上游规范校验身份令牌并比对工号，接收账号状态事件完成撤权；执行配额核算与模型路由 | 依赖网关数据面与 IAM 账号状态事件通道；验签能力待提供方书面确认 |
| 凭据安全存储 | 本地安全凭据存储层（macOS 加密后端、Windows DPAPI 等），安全托管长效个人 Key，阻断明文落盘 | 依赖客户端安全加密凭据服务 |

## 3. 凭据协同验证与数据流

在模式一（受管个人助手）下，客户端请求发起时的数据流如下：

1. **本地凭据读取**：网关适配层从安全凭据库读取当前绑定的长效凭据 `uag-sk-u-...`。
2. **IAM 令牌获取**：调用 IAM 模块获取当前员工有效的身份令牌（形态与取用接口待 IAM 书面确认）；若令牌已处于临期状态，优先触发后台静默刷新。
3. **请求头组装**：
   - `Authorization: Bearer <uag-sk-u-...>`
   - `X-IAM-Token: <IAM-JWT>`
   - `X-Consumer-Type: personal`
   - `User-Agent: Heluo-Client/<version>`
4. **网关端核验**：
   - 提取 `Authorization` 确认长效凭据在有效期内，读取对应的限流配额与模型白名单。
   - 提取 `X-IAM-Token`，按上游规范与企业 IAM 接入规范校验签名、`iss` / `aud` / 时效；验签内部机制不在本设计范围。
   - 严格比对 `sub` 与凭据绑定的 `member_id`；任一校验不通过拒绝放行。

## 4. 存储隔离与平滑轮换

- **存储物理隔离**：IAM 登录态与网关长效个人凭据在本地物理隔离存储。IAM 登录刷新与登出清理不会破坏或冲掉本地保存的长效个人凭据；长效个人凭据的重置亦不影响全局 IAM 登录状态。
- **平滑轮换机制**：
  - 个人长效凭据支持基于网关自服务轮换端点（`POST ${baseUrl}/credentials/self-service/rotate`）进行在线轮换。
  - 轮换后网关控制面保障新旧凭据在 24 小时内并行有效，客户端在平滑更新本地凭据库后无感切换，避免出现模型调用瞬断。

## 5. 错误分类与状态机协同

网关适配层严格根据网关下发的标准化错误码进行状态机分流：

| 错误码 | 含义 | 状态机流转 |
|---|---|---|
| `401 invalid_iam_token` | IAM 身份令牌失效、验签失败或过期 | 停止请求并标记会话失效，引导用户重新登录 IAM 刷新身份令牌；不自动重试（上游规范将该错误码登记为不可重试） |
| `401 invalid_api_key` | 长效个人凭据无效或被删除 | 提示凭据配置错误，引导用户进入凭据设置界面或自服务申领页面 |
| `401 credential_revoked` | 长效凭据已被安全管理员吊销 | 立即抹除本地存储的当前长效凭据，弹窗提示凭据已被注销，阻断后续调用 |
| `403 iam_token_mismatch` | IAM 登录工号与长效凭据所属工号不一致 | 弹出告警框，明确指出“当前登录用户工号与凭据归属员工工号不匹配”，杜绝凭据跨人借用 |
| `429 budget_exhausted` | 预算或个人额度用尽 | 提取响应中的重置时间 `reset_at` 进行展示，中止调用且不进行无效重试 |
| `429/503` 限流与过载 | 触发网关并发限流或网关暂时过载 | 解析 `Retry-After` 响应头，按指定秒数执行带抖动（Jitter）的退避重试 |

## 6. 退出与生命周期时限

- **客户端本地退出**：当用户在客户端主动点击登出或注销时，客户端立即在内存中销毁在途会话与身份令牌缓存，并向本地正在执行的模型长连接发送取消信号，彻底切断本地链路。
- **全网 5 分钟下线红线**：当员工在 IAM 触发离职、转岗注销或管理员吊销网关凭据时，网关应依据账号状态事件通道在集群内使相关凭证失效，在不超过 5 分钟内拒绝对该主体的一切新请求；事件通道不可用期间不得放行。该时限为联调验收判据，可达性待网关团队书面确认。
