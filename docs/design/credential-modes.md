## 1. 结论

**V1 只启用静态 Key 模式，不启用令牌直通，也不做 `auto` 自动选路。** 用户经企业 IAM 登录 DSH 后，到 UAG 控制台创建个人凭证并粘贴；DSH 将其写入 `CredentialRef: ENTERPRISE_STATIC_KEY`，模型调用只解析该引用。IAM access token 仅用于登录/身份，不再镜像为模型网关凭据。

保留统一的 `GatewayCredentialProvider` 接口，是为了让未来若启用令牌直通时不必改模型调用链；**这不代表 V1 是双轨**。`token` 提供者标记为保留、不注册；`auto` 配置值保留但拒绝启用，避免同一会话两种凭据交替。

## 2. 目标与非目标

**目标**

- V1 用同一份安装包支持 UAG 个人凭证的录入、更新、清除、探测与错误提示。
- 静态 Key 模式不启动令牌刷新链，IAM 刷新不得覆盖用户凭据。
- 凭据与 IAM 主体绑定；换账号不得沿用上一账号的 Key。
- 切换/清除凭据不要求重装、不要求清空用户数据。

**非目标**

- 不在客户端实现 Key 签发；Key 由 UAG 控制台签发。
- 不并行使用两种凭据调同一个请求。
- 不实现自动轮换、自动重建或 401 后的自动重放。
- 不改变服务端鉴权、额度与日志规则。

## 3. 统一凭据接口

```ts title="凭据提供者（示意）"
interface GatewayCredentialProvider {
  readonly id: 'static-key' | 'token';
  /** 取当前可用于 Authorization 的值；失败抛出可归因错误 */
  resolve(): Promise<{ value: string; expiresAt?: number }>;
  /** 是否允许在 401 后自动刷新并重试一次 */
  canRefresh(): boolean;
  /** 401 后的处置建议，驱动界面与重试策略 */
  onUnauthorized(): 'reissue' | 'relogin' | 'fatal';
  /** 启动、录入或切换时的一次性可用性探测 */
  probe(): Promise<
    | 'ok'
    | 'missing'
    | 'invalid'
    | 'suspended'
    | 'policy_denied'
    | 'model_not_allowed'
    | 'unreachable'
  >;
}
```

V1 只注册 `static-key`：`canRefresh=false`，`onUnauthorized='reissue'`。`token` 提供者的 `canRefresh=true` 与 `relogin` 仅作为未来定义保留，未注册、不可配置启用；若未来启用刷新，再扩展动作枚举。

## 4. 两个提供者

| 能力 | `static-key`（V1 启用） | `token`（保留，不启用） |
|---|---|---|
| 取值来源 | 凭据存储中的 `ENTERPRISE_STATIC_KEY` | IAM 插件的按资源令牌 |
| 签发方 | UAG 控制台，用户手工创建 | 企业 IAM |
| 有效期 | 有，建议 90 天；不主动刷新 | 有，到期前预刷新 |
| 401 处置 | 提示到控制台核查/重建，不重试 | 刷新后至多重试一次 |
| 账号切换 | 清理运行时副本；凭据仅对录入时主体可用，否则要求重新粘贴/清除 | 清理运行时副本与按资源缓存 |
| 探测方式 | 一次最小模型调用 | 令牌有效性与到期时间 |
| 存储位置 | 系统凭据库；仅 dev/pilot 可显式接受 0600 fallback | `CredentialKey` 记录 |

两者都不把值写进日志、配置明文或模型上下文。

## 5. 凭据汇合点：V1 的唯一写入路径

`llm-pi-ai` 解析 `CredentialRef: ENTERPRISE_STATIC_KEY`。V1 只存在一条写入路径：

```text
静态模式：用户粘贴/更新 Key → 写 CredentialRef（写入一次，直到更换或清除）
IAM 刷新：只更新 IAM GrantRecord，不写模型网关引用
```

汇合组件禁止跨模式写入：静态模式下 IAM 刷新结果不得覆盖用户 Key；保留的令牌模式也不允许手工写入。`ENTERPRISE_ACCESS_TOKEN` 不再作为模型网关引用；若未来启用 MCP 按资源令牌，另行定义引用与缓存，不复活模型镜像。

## 6. 模式选择

| 配置值 | 行为 | V1 处置 |
|---|---|---|
| `static-key` | 只用 Key 提供者；无 Key 即未就绪 | **默认且唯一启用** |
| `token` | 只用令牌提供者；无令牌即未就绪 | 保留值，启动时拒绝并提示“V1 未启用” |
| `auto` | 有 Key 用 Key，否则用令牌 | 保留值，启动时拒绝，避免同一会话两种凭据交替 |

切换模式视为配置变更：清理旧运行时副本，重新探测，记录审计事件。V1 不支持在会话内切换；修改配置后需重启并重新探测。

## 7. 状态机

```flow TB
(1 未配置) -> {2 已登录?}
{2 已登录?} -> [3 引导登录]: 否
{2 已登录?} -> {4 有网关凭据?}: 是
{4 有网关凭据?} -> [5 引导配置]: 否
{4 有网关凭据?} -> [6 探测中]: 是
[6 探测中] -> {7 探测结果}
{7 探测结果} -> [8 就绪]: ok
{7 探测结果} -> [9 需重新签发]: invalid
{7 探测结果} -> [10 已挂起，联系管理员]: suspended
{7 探测结果} -> [11 策略/模型未授权]: policy_denied / model_not_allowed
{7 探测结果} -> [12 网络不可达，退避重试]: unreachable
```

状态只影响界面提示与是否允许发起调用，不改变模型调用的结果语义。`model_not_allowed` 表示凭据可能有效但模型授权/白名单不匹配，不能提示“Key 无效”。

## 8. 错误与用户动作

| 场景 | V1 静态 Key 模式 |
|---|---|
| 401 | 提示检查 Key 完整性，并到 UAG 控制台查看状态或重建；不自动刷新、不重试 |
| 403 挂起 | 提示联系团队管理员；恢复后原 Key 可用 |
| 403 策略拒绝/待审批 | 展示原因；待审批去控制台跟进 |
| 400 模型未授权/不可路由 | 检查模型名或申请权限；不静默换模型 |
| 422 无路由策略 | 联系管理员 |
| 429 预算 | 展示 `reset_at`；不重试；无法区分层级时提示到控制台查看 |
| 429 RPM/TPM | 按 `Retry-After` 退避；不重放已输出内容 |
| 5xx/超时 | 先确认结果，不盲重放；已输出内容不重放 |
| 凭据缺失 | 引导登录后配置；不是“登录失败” |

V1 不再有“401 刷新后重试一次”的分支；该分支只保留在未来令牌模式。

## 9. 安全边界

- 凭据值只存在于系统凭据库与该引用；生产必须由 keychain provider 保护，keychain 不可用时 fail closed；仅 dev/pilot 可显式接受 `dsh-credentials-local` 的 0600 明文 YAML 或 `allowInsecureFile` backend，并配合 A4 的文件/子进程拒绝。旧 0600 记录在 keychain 可用后迁移，成功才删除明文。
- 静态 Key 不参与刷新，避免“用长期凭据兑换短期凭据”的混合路径。
- 凭据记录带 `ownerSubject`（录入时 IAM 主体）与设备标签；仅作账号切换保护，不作服务端授权依据。换账号登录时，凭据不匹配则不自动使用，提示重新粘贴或清除。
- 退出清理运行时副本与内存值；默认不删除已保存 Key，显式“清除网关凭据”才删除。**退出不宣称已吊销 UAG Key**，撤销在 UAG 控制台。
- 切换模式或清除凭据必须留下审计事件：时间、操作、旧状态、新状态；不记录 Key 明文。

## 10. 测试矩阵

| 层级 | 用例 |
|---|---|
| 单元 | 模式选择；`token`/`auto` 拒绝；凭据写入方向（IAM 刷新不得覆盖 Key）；401/403/400/422/429 映射 |
| 契约 | Bearer 与 apikey 两种头；错误体解析；预算 `reset_at`；RPM `Retry-After` |
| 集成 | 粘贴后探测成功/失败；挂起后 403；撤销后 401；账号切换不沿用；清除后未就绪 |
| 端到端 | 双端各完成一次真实 UAG Key 登录、录入、调用、取消与退出 |

## 11. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 手工签发/轮换 | 用户不会建、过期后中断 | 首启引导 + 账户页入口 + 90 天提醒 + 支持 runbook |
| 401 不可细分 | 用户无法自助判断 | 引导到控制台看状态；探测结果区分挂起/模型未授权 |
| 长期 Key 被复制/共用 | 无法区分实际操作人 | 每设备一把、名称可读、审计与批量撤销；共用场景需安全接受 |
| 换账号沿用旧 Key | 跨账号越权 | `ownerSubject` 绑定；不匹配即要求重新粘贴/清除 |
| Kong 明文 | 库泄露即 Key 泄露 | 安全书面接受 + DB/备份访问控制、静态加密评估、审计、短 TTL |
