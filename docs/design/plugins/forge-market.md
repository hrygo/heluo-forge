## 1. 结论

本插件是市场的前端：在 DSH 里完成浏览、详情、安装、提交、查看未收录原因。

实现路线是 fork 上游 `DSH-Plugins-Marketplace` 后做四件事：换数据源、换下载源、加提交页、加诊断页。上游的卡片、搜索、安装与更新链路保留，不重写。

边界：不存插件源码，不做评审判定，不做构建。评审与目录在服务端（DESIGN-012）。

## 2. 目标与非目标

**目标**

- 一个界面完成发现、安装、提交、自查。
- 安装可复现：同一版本装到同样的字节。
- 未收录有明确原因，开发者不用猜。
- 与官方市场并存，不接管官方源。

**非目标**

- 不重写市场 UI 框架。
- 不做在线构建与代码编辑。
- 不做离线安装包分发。

## 3. 需求与依赖

| 需求/验收 | 关系 | 说明 |
|---|---|---|
| REQ 可治理分发 | 支撑 | 只能从受信 group 安装 |
| REQ 推荐能力落地 | 直接实现 | 浏览器与提交入口 |
| 验收 A10 分发 | 支撑 | 安装可复现、可回退 |

| 依赖 | 类型 | 版本约束 | 缺失时的行为 |
|---|---|---|---|
| 市场服务 | 服务 | DESIGN-012 同批次 | 只显示本地已装 |
| 企业 Gitee | 服务 | 企业现有 | 不能安装，展示缓存 |
| `dsh-plugin-manager` | 上游包 | 随目标 DSH | 无安装能力，降级为提示 |
| `dsh-host-plugin-inventory` | 上游包 | 随目标 DSH | 无法区分已装与可装 |

## 4. fork 基线与改造点

| 上游部分 | 处理 | 说明 |
|---|---|---|
| `cordis.patch.yml`（单行 `inject: [webServer]`） | 保留 | 挂载方式不变，包名改为内部命名 |
| 卡片列表、搜索、详情页 | 保留 | 增加"下载量 / star"两个角标 |
| 一键安装、版本检测、更新提示 | 保留 | 下载地址改由服务返回 |
| `registry.json` 与生成脚本 | 删除 | 数据改由服务提供，避免 18 MB 生成物 |
| `skills.json` 与技能索引 | 删除 | 本期不做技能市场 |
| GitHub topic 抓取 | 删除 | 改为按 group 发现 |
| 提交页、诊断页 | 新增 | 本设计主要工作量 |
| 服务客户端层 | 新增 | 统一超时、重试、错误码 |

包名保持内部独立，不沿用上游名称，避免与官方市场插件冲突。

## 5. 模块结构

```text
plugin/
├── cordis.patch.yml          挂载声明（保留）
├── src/
│   ├── index.mjs             注册面板与路由
│   ├── client.mjs            服务客户端：超时、重试、错误码
│   ├── catalog.mjs           列表、筛选、排序
│   ├── detail.mjs            详情与版本选择
│   ├── installer.mjs         下载、校验、解包、挂载
│   ├── submit.mjs            提交表单与校验前置
│   └── diagnostics.mjs       未收录清单与原因
└── ui/                       卡片、列表、详情、表单
```

`client.mjs` 是唯一访问网络的模块，其余模块只依赖它的返回结构。

## 6. 页面与交互

| 页面 | 内容 | 关键交互 |
|---|---|---|
| 市场列表 | 卡片：名称、一句话说明、下载量、star、版本 | 搜索、按下载量或 star 排序 |
| 插件详情 | 说明、适用场景、维护人、版本、`engines.dsh`、仓库链接 | 选版本、安装、更新 |
| 提交 | 仓库地址、版本标签、说明、场景 | 提交后显示待审状态 |
| 我的提交 | 条目与状态：待审、通过、退回（附理由） | 退回可改后重提 |
| 未收录诊断 | 扫描到但未通过校验的仓库与错误码 | 仅管理员可见 |

排序默认按 star，其次下载量；不提供"编辑推荐"这类人工位，避免排序口径争议。

## 7. 与服务端的契约

前端只依赖以下字段，字段含义以 DESIGN-012 为准。

| 用途 | 端点 | 关键字段 |
|---|---|---|
| 列表 | `GET /api/plugins` | `name`、`title`、`summary`、`version`、`downloads`、`stars`、`engines` |
| 详情 | `GET /api/plugins/{name}` | 上列字段 + `scenarios`、`maintainer`、`repo`、`versions[]` |
| 提交 | `POST /api/plugins` | `repo`、`tag`、`title`、`summary`、`scenarios` |
| 我的提交 | `GET /api/plugins?mine=1` | `state`、`reason` |
| 诊断 | `GET /admin/unindexed` | `repo`、`errors[]` |

## 8. 安装链路

1. 详情页选定版本，向服务请求解析结果（含归档地址与期望摘要）。
2. 下载归档，计算摘要并与服务返回值比对；不一致即中止。
3. 解包到临时目录，只接受白名单路径（`package.json`、`cordis.patch.yml`、`src/`、`ui/`、`README.md`）。
4. 校验 `package.json` 的 `name` 与 `engines.dsh`，与详情页展示一致才继续。
5. 写入 profile 的 bundle 列表并触发挂载。
6. 成功后上报一次下载计数；失败不计数。

任何一步失败都回滚临时目录，不留半装状态。

## 9. 权限与安全

| 项 | 处理 |
|---|---|
| 身份 | 复用 IAM 会话；未登录只读本地已装 |
| 令牌 | 经环境注入，不写配置文件、不落日志 |
| 归档来源 | 仅接受服务返回的 group 内地址，拒绝任意 URL |
| 解包 | 白名单路径 + 拒绝绝对路径与 `..` |
| 供应链 | 摘要比对；声明安装脚本的包在校验阶段已被排除 |
| 计数 | 只上报条目与版本，不上报用户标识 |

## 10. 状态与回退

| 对象 | 状态 |
|---|---|
| 条目 | 待审 → 已上架 → 已撤回 |
| 版本 | 可用 / 被替代 / 已撤回 |
| 本地安装 | 未装 / 已装 / 有更新 / 安装失败 |

回退：详情页可选历史版本重装；服务端保留已撤回版本的归档，允许回退 30 天。

## 11. 失败模式

| 场景 | 行为 | 用户可见结果 | 是否可重试 |
|---|---|---|---|
| 服务不可用 | 显示缓存列表 + 已装 | 提示目录可能过期 | 可重试 |
| 未登录 | 只读本地已装 | 引导登录 | 登录后重试 |
| 归档下载失败 | 中止并清理 | 提示网络问题 | 可重试 |
| 摘要不一致 | 中止 | 提示包校验失败 | 联系维护人 |
| 解包含非法路径 | 中止 | 提示包结构异常 | 否 |
| 版本与 DSH 不兼容 | 拒绝安装 | 列出要求版本 | 升级后重试 |
| 计数上报失败 | 忽略 | 无影响 | — |

## 12. 可观测性

| 事件 | 字段 | 去向 | 保留 |
|---|---|---|---|
| 列表与详情访问 | 条目、是否命中缓存 | 服务日志 | 90 天 |
| 安装 | 条目、版本、耗时、结果 | 本机日志 + 服务计数 | 180 天 |
| 提交 | 条目、状态 | 服务日志 | 长期 |
| 校验失败 | 条目、错误码 | 诊断页 + 服务日志 | 90 天 |

## 13. 测试矩阵

| 层级 | 覆盖 | 命令 |
|---|---|---|
| 单元 | 排序、版本选择、路径白名单、摘要比对 | `node --test` |
| 契约 | 与 DESIGN-012 的字段一致 | 契约用例 |
| 集成 | 服务不可用、摘要不一致、非法路径 | 本地仿服务 |
| 端到端 | 浏览 → 装 → 更新 → 回退 → 提交 | 手工 + 脚本 |

## 14. 分包、升级与回退

包名内部独立，`private: true`，声明 `engines.dsh`，仅本仓库分发。

跟随上游策略：每季度评估一次上游变更，只吸收影响浏览与安装链路的补丁；上游改动集中在已删除模块时不合入。

回退：禁用本插件回到只有官方市场的状态，已装插件不受影响。

## 15. 里程碑

| 阶段 | 交付 | 判据 |
|---|---|---|
| M1 | fork 可跑，列表与安装走通 | 本地装上一个自建插件 |
| M2 | 接市场服务，列表来自 group | 新仓库 5 分钟内可搜到 |
| M3 | 提交与评审状态可见 | 提交到上架闭环 |
| M4 | 未收录诊断 | 错误码可定位到文件 |

### 需用户确认的设计选项（增益不明确，暂不采用，保留待定）

| 选项 | 可能的增益 | 代价 | 当前处理 |
|---|---|---|---|
| 完全自研前端 | 交互自由 | 重写浏览与安装 | 不采用，fork 改造 |
| 只做 Gitee 扫描、不做服务 | 最轻 | 无上传、无审核、无计数 | 不采用 |
| 市场内在线构建 | 一条龙 | 与企业流水线重复 | 不采用 |
| 人工推荐位 | 可控曝光 | 排序口径争议 | 不采用 |
| 技能与插件合并展示 | 一处入口 | 两类生命周期不同 | 不采用 |

以上五项均不影响主链路；若后续确认增益，再单独评估。
