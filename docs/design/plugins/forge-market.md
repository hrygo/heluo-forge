## 1. 结论

本插件是市场的前端：在 DSH 里完成浏览、详情、安装、提交、查看未收录原因。

实现路线是参考上游实现（`dsh-market/dsh-market`），拷贝必要代码后自研适配层：数据源、下载源、提交页、诊断页；浏览与安装交互按需借鉴，不复制整仓。

安装来源唯一：只从企业 Gitee 的专门 group 安装。其它插件须由有权限人员上传进该 group，再经上架评审后才能被安装。

边界：不存插件源码，不做评审判定，不做构建。评审与目录在服务端（DESIGN-012）。

## 2. 目标与非目标

**目标**

- 一个界面完成发现、安装、提交、自查。
- 安装可复现：同一版本装到同样的字节。
- 未收录有明确原因，开发者不用猜。
- 安装来源唯一：企业 Gitee 的专门 group。

**非目标**

- 不重写市场 UI 框架。
- 不做在线构建与代码编辑。
- 不做离线安装包分发。
- 不提供官方市场或公网源安装入口（对应 REQ-14）。

## 5. 模块结构

```text
packages/forge-market/
├── cordis.patch.yml          挂载声明：serviceUrl、allowedHosts、cachePath
├── client.js                 客户端面板：列表、加载与缓存状态
├── src/
│   ├── index.mjs             插件入口：注册工具与 HTTP 路由
│   ├── market-tools.mjs      六个工具的定义与执行
│   ├── client.mjs            服务客户端：超时、错误码映射
│   ├── catalog.mjs           条目与版本归一化、排序、过滤
│   ├── installer.mjs         版本规划、域名白名单、摘要、路径白名单
│   ├── install.mjs           安装流水线：下载、摘要、解包、清单比对
│   ├── tarball.mjs           tar.gz 解包：体积上限、截断与路径校验
│   ├── persist.mjs           落盘：目标目录约束
│   ├── cache.mjs             离线缓存：时间戳与过期判定
│   ├── local-catalog.mjs     离线目录：从 JSON 文件读取条目
│   ├── live-check.mjs        真实仓库验收：拉归档并按规则判定
│   ├── routes.mjs            宿主路由：catalog、detail、缓存回退
│   ├── registration.mjs      生成 profile 登记行与说明
│   ├── validate.mjs          包格式与 patch 内容校验
│   └── policy.mjs            安装策略与 engines 范围判定
├── scripts/live-check.mjs    验收脚本入口（手动执行，不进 CI）
└── test/                     单元、契约、端到端与测试支撑
```

离线目录模式（`catalogFile`）与服务模式二选一：前者从本地 JSON 读条目，供演示、隔离网与 CI 跑通全链路；该模式只读，提交返回 `read-only`。

网络访问只出现在两处：`client.mjs` 调市场服务，`install.mjs` 的下载器取归档。其余模块是纯计算或纯文件操作，可单独测试。

`detail`、`submit`、`diagnostics` 三个页面尚未实现；当前客户端只有列表面板，提交与诊断走工具而非界面。

## 6. 页面与交互

| 页面 | 内容 | 关键交互 |
|---|---|---|
| 市场列表 | 卡片：名称、一句话说明、下载量、star、版本 | 搜索、按下载量或 star 排序 |
| 插件详情 | 说明、适用场景、维护人、版本、`engines.dsh`、仓库链接 | 选版本、安装、更新 |
| 提交 | 仓库地址、版本标签、说明、场景 | 提交后显示待审状态 |
| 我的提交 | 条目与状态：待审、通过、退回（附理由） | 退回可改后重提 |
| 未收录诊断 | 扫描到但未通过校验的仓库与错误码 | 仅管理员可见 |

排序默认按 star，其次下载量；不提供"编辑推荐"这类人工位，避免排序口径争议。

## 7. 与服务端的契约

检索结果带 `source`，取值 `service`、`local`（离线目录）或 `cache`（服务不可达时的上次结果，附 `stale`），排障时据此判断数据来源。

检索结果另有 `total`（命中总数）、`returned`（本页条数）、`truncated`（是否被 `limit` 截断）；`limit` 默认 20、上限 200，非数值按默认处理。`total` 不得被理解为已返回条数。


前端只依赖以下字段，字段含义以 DESIGN-012 为准。

| 用途 | 端点 | 关键字段 |
|---|---|---|
| 列表 | `GET /api/plugins` | `name`、`title`、`summary`、`version`、`downloads`、`stars`、`engines` |
| 详情 | `GET /api/plugins/{name}` | 上列字段 + `scenarios`、`maintainer`、`repo`、`versions[]` |
| 提交 | `POST /api/plugins` | `name`、`repo`、`tag`、`summary`、`scenarios` |
| 我的提交 | `GET /api/plugins?mine=1` | 按调用方身份过滤；`state`、`reason` |
| 诊断 | `GET /api/admin/unindexed` | `repo`、`errors[]` |

## 8. 安装链路

1. 详情页选定版本，向服务请求解析结果（含归档地址与期望摘要）。
2. 下载归档，计算摘要并与服务返回值比对；不一致即中止。
3. 解包到临时目录，剥离归档顶层目录后按白名单写入（`package.json`、`cordis.patch.yml`、`src/`、`ui/`、`locale/`、`lib/`、`README.md`），其余文件跳过并上报。
4. 校验 `package.json` 的 `name` 与 `engines.dsh`，与详情页展示一致才继续。
5. 返回可直接使用的 loader 行与登记步骤，并附 `version`、`tag`、`directory`，使登记对象与实装版本一一对应；插件不写 profile，由操作者或 `plugin_manager` 完成登记。
6. 下载计数由服务端在发放归档地址时自增，插件不上报，也不因安装失败回退。

任何一步失败都回滚临时目录，不留半装状态。

落盘按包名分目录（`targetDir/<scope-name>/`），否则第二个插件会覆盖第一个的 `package.json`；同一目录下的 `package.json` 也是 `market_check_update` 省略 `installedVersion` 时的来源。

包内 `cordis.patch.yml` 会被 loader 执行，因此第 3 步之后还要做内容校验：拒绝 `!!js` 表达式、`disabled: true`、`cordis:include`、包外相对路径，以及覆盖 IAM、策略、凭据、沙箱、权限预设等行 id。判定逻辑见 `packages/forge-market/src/validate.mjs`。

## 8.1 失败原因

安装、校验与登记失败时返回 `reason`，取值如下；调用方据此决定是否重试与提示什么。

| 原因 | 阶段 | 含义 | 是否可重试 |
|---|---|---|---|
| `archive-too-large` | 解包 | 解压后超过体积上限 | 否 |
| `bad-archive` | 解包 | 不是可解压的 tar.gz | 否 |
| `bad-cache` | 配置 | 缓存文件不是预期结构 | 可忽略 |
| `bad-entries` | 配置 | 写缓存的内容不是数组 | 否 |
| `bad-id` | 登记 | 无法从包名推导 loader 行 id | 否 |
| `bad-manifest` | 清单 | package.json 不是合法 JSON | 否 |
| `bad-name` | 登记 | 包名不是 @scope/name | 否 |
| `bad-plan` | 规划 | 安装计划缺仓库或标签 | 否 |
| `bad-repo` | 规划 | 仓库地址不是合法 URL | 否 |
| `bad-tag` | 提交 | 标签不是 vX.Y.Z | 否 |
| `digest-mismatch` | 下载 | 归档摘要与声明不一致 | 否 |
| `download-failed` | 下载 | 下载归档失败，含连接中断 | 可重试 |
| `empty-archive` | 解包 | 归档里没有文件 | 否 |
| `extract-failed` | 解包 | 解包抛错 | 否 |
| `host-not-allowed` | 规划 | 仓库域名不在 allowedHosts 内 | 否 |
| `install-script-blocked` | 策略 | 包含安装脚本被策略禁止 | 否 |
| `invalid-name` | 策略 | 包名不符合 @scope/name | 否 |
| `missing-dependency` | 下载 | 未注入下载或解包实现 | 否 |
| `missing-engines` | 条目 | 未声明 engines.dsh | 否 |
| `missing-fields` | 条目 | 条目缺 name 或 version | 否 |
| `missing-manifest` | 清单 | 归档里没有 package.json | 否 |
| `name-mismatch` | 清单 | 清单包名与规划不一致 | 否 |
| `no-allowed-host` | 提交 | 未配置 allowedHosts，拒绝提交 | 否 |
| `no-digest` | 下载 | 服务未给出摘要，无法校验 | 否 |
| `no-installed-version` | 更新 | 未提供已安装版本 | 否 |
| `no-latest-version` | 更新 | 目录里没有可用版本（含全部已撤回） | 否 |
| `installed-revoked` | 更新 | 已安装的版本被撤回，建议换到可用版本 | 是（换版本） |
| `no-path` | 配置 | 缓存或落盘未配置路径 | 否 |
| `no-registry` | 策略 | 策略未配置制品源 | 否 |
| `no-repo` | 规划 | 条目没有仓库地址也没有归档地址 | 否 |
| `no-service-url` | 配置 | 既没有 serviceUrl 也没有 catalogFile | 否 |
| `no-target` | 配置 | 落盘未配置目录 | 否 |
| `not-installed` | 登记 | 目标目录里没有该包，或版本与请求不符 | 先安装 |
| `no-version` | 规划 | 条目没有可用版本，或请求的版本不存在 | 否 |
| `outside-range` | 条目 | 当前 DSH 超出声明范围 | 否 |
| `outside-target` | 落盘 | 目标路径解析后跑出落盘目录 | 否 |
| `prerelease-blocked` | 策略 | 预发布版本被策略禁止 | 否 |
| `requires-newer-dsh` | 条目 | 当前 DSH 低于声明下限 | 升级后重试 |
| `scope-not-allowed` | 策略 | 包名不在受信范围 | 否 |
| `truncated-archive` | 解包 | 文件体短于头部声明长度 | 可重试 |
| `unparsable` | 条目 | engines 或当前 DSH 版本无法解析 | 否 |
| `unsafe-path` | 解包 | 条目含越界或非白名单路径 | 否 |
| `version-mismatch` | 清单 | 清单版本与规划不一致 | 否 |
| `version-pinned` | 策略 | 版本与钉住的版本不符 | 否 |
| `verification-failed` | 提交 | 提交前自检未通过，见返回的 `steps` | 修正后重试 |
| `version-revoked` | 规划 | 该版本已撤回，不再发放归档地址 | 否 |
| `write-failed` | 落盘 | 写缓存或文件失败 | 可重试 |

未知原因按不可重试处理；新增原因必须同步本表与 `test/reasons.test.mjs`。

服务端拒绝时（4xx）透传其错误码作为 `reason`，并把原始响应体放在 `server` 字段；因此 `reason` 的取值可能来自 DESIGN-012 §5.1 的校验码，不以本表为限。

失败结果同时给出 `action`，把错误翻译成下一步：

| `action` | 含义 |
|---|---|
| `re-login` | 令牌失效，重新登录 |
| `request-access` | 有身份但无权限，申请范围或角色 |
| `retry` | 服务不可达或超时，稍后重试 |
| `choose-another-version` | 目标版本已撤回，选别的版本 |
| `fix-the-package` | 包本身不合格，按 `steps` 修正 |
| `contact-admin` | 未归类的失败，交平台组 |

## 9. 权限与安全

| 项 | 处理 |
|---|---|
| 身份 | 复用 IAM 会话；未登录只读本地已装 |
| 令牌 | 经环境注入，不写配置文件、不落日志 |
| 归档来源 | 仅接受服务返回的 group 内地址，拒绝任意 URL |
| 解包 | 先剥离 Gitee 的 `<repo>-<tag>/` 顶层；白名单内文件写入，其余（`LICENSE`、`docs/` 等）跳过并列入 `skipped`；绝对路径与 `..` 一律拒绝 |
| 供应链 | 摘要比对；声明安装脚本的包在校验阶段已被排除 |
| 体积 | 下载按 `content-length` 与流式读取双重限制 64 MB；解压用 `maxOutputLength` 限制，避免 gzip 炸弹 |
| 计数 | 插件不上报；服务端在发放归档地址时按（条目, 机器哈希, 日）去重，缺少机器哈希时按（条目, 日） |

### 9.1 受保护的行 id

`cordis.patch.yml` 里禁止覆盖以下行 id；命中即判 `patch-overrides-protected`，包不进入索引：

| 行 id | 保护对象 |
|---|---|
| `forge-iam` | 身份与会话 |
| `forge-policy` | 策略判定 |
| `dsh-credentials` | 凭据存储 |
| `dsh-sandbox-policy` | 沙箱策略 |
| `dsh-permission-presets` | 权限档位 |

判定不依赖书写风格：块式、流式（`- {id: forge-iam}`）、键序不同都能命中，宁可误报不可漏报。代价是正文里出现形如 `id: forge-iam` 的字符串也会被判违规，属刻意取舍。行 id 的最终取值须在 M1 用真实 profile 的补丁核对；名单变更须同步 `validate.mjs` 与本表。

## 10. 状态与回退

| 对象 | 状态 |
|---|---|
| 条目 | 待审 → 已上架 → 已撤回 |
| 版本 | 可用 / 被替代 / 已撤回 |
| 本地安装 | 未装 / 已装 / 有更新 / 安装失败 |

回退：详情页可选**被替代**的历史版本重装；已**撤回**的版本不可安装，归档只保留用于审计，不提供 30 天可安装窗口。

## 11. 失败模式

| 场景 | 行为 | 用户可见结果 | 是否可重试 |
|---|---|---|---|
| 服务不可用 | 显示缓存列表 + 已装 | 提示目录可能过期 | 可重试 |
| 未登录 | 只读本地已装 | 引导登录 | 登录后重试 |
| 归档下载失败 | 中止并清理 | 提示网络问题 | 可重试 |
| 摘要不一致 | 中止 | 提示包校验失败 | 联系维护人 |
| 解包含非法路径 | 中止 | 提示包结构异常 | 否 |
| 版本与 DSH 不兼容 | 拒绝安装 | 列出要求版本 | 升级后重试 |
| patch 含提权或禁用行为 | 拒绝安装并记录 | 提示包未通过安全校验 | 联系维护人 |
| profile 正被编辑 | 等待后重试 | 提示稍后再试 | 可重试 |
| 版本已撤回 | 拒绝安装 | 提示已撤回并给替代版本 | 否 |
| 计数上报失败 | 忽略 | 无影响 | — |

| 单元 | 排序、版本选择、路径白名单、摘要比对、patch 内容规则 | `node --test` |
| 契约 | 与 DESIGN-012 的字段一致 | 契约用例 |
| 集成 | 服务不可用、摘要不一致、非法路径 | 本地仿服务 |
| 端到端 | 浏览 → 装 → 更新 → 回退 → 提交 | 手工 + 脚本 |

## 14. 分包、升级与回退

包名内部独立，`private: true`，声明 `engines.dsh`，仅本仓库分发。

跟随上游策略：每季度评估一次上游变更，只吸收影响浏览与安装链路的补丁；上游改动集中在已删除模块时不合入。

回退：禁用本插件回到只有官方市场的状态，已装插件不受影响。
