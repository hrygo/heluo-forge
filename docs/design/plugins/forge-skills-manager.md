## 1. 定位与准入

`@heluo/forge-skills-manager` 是独立 Host + Client 插件，由企业组合包装配；界面名称为 技能管理。范围以[需求基线 §2](../../requirements/requirements-baseline.md#2-范围边界唯一真源)为准。来源是 MapleLoop1013/dsh-skills-manager 的 `d20fb1a`。源码迁入工作区，原仓库不是运行依赖。

装载沿用源插件的 `connection.fetch`、`skills.registerProvider`、会话及浏览器 slots/locale/primitives 接缝；目标版本从根 `.dsh-version` 读取。上游及本机历史记录不证明企业组合兼容。准入按[插件高阶规范](../../engineering/dsh-plugin-conventions.md)逐项建立可失败的判据，组合安装另以实际制品验证。

## 2. 结构与所有权

入口只装配。Host 分为本地技能及状态、安装记录与恢复、Nacos 会话、provider、HTTP 路由；每份可写状态只由对应模块持有。跨轴通过参数端口协作，纯类型、路径与摘要函数可共享。浏览器交付一个 ModuleLoader bundle，保留原有构建技术；生成物提交入库并校验与源码一致。源文件按常量、IO、状态、视图分段，结构守卫按符号归属判断。

管理策略由独立存储所有者持有，提供快照读取和事务更新；事务在同一状态文件的进程内队列中完成读取、迁移、校验、修改及原子提交。启停、分类、备注、来源清理和安装恢复均使用该入口，业务模块不得自行读取旧快照后整份写回。目录相关的 schema 判定经显式端口注入存储；`core` 保留本地业务兼容出口。安装记录事务可以等待策略事务，策略事务不得反向等待安装队列；远端下载不持有策略写入队列。同账户其他进程的写入不在进程内串行保证范围内。

HTTP 只负责准入、协议适配和调用，查询快照在本地恢复后生成；安装管理器和 HTTP 仅依赖各自使用的窄端口。路由注册逐项取得清理责任，中途失败按逆序释放已注册项并保留原异常。业务及可识别的文件系统失败在对应适配器转换，未知程序异常保留为服务端异常，不进入普通导入失败明细。

HTTP 生命周期为运行、关闭中、已关闭。关闭时停止新任务准入，拒绝尚未开始的排队写入并取消远端读取；已开始的本地事务完成提交或保留待确认记录。同一管理目录的新实例等待旧实例的本地写入结束，不能各自持有互不相干的写队列。卸载不删除用户数据。

入口位置统一由 `getEntryLocation`、`setEntryLocation` 读写；旧布尔值 `sidebarEntry` 和 HTTP `enabled` 字段只在存储及路由兼容边界解释。删除技能直接返回现有操作结果，不另设无消费者的进程内失败标记。HTTP 请求类型仅描述已挂载操作，旧安装记录的格式校验和恢复逻辑独立保留。

全局技能、项目技能、其他 Agent 来源、分类、自建/导入、回收站保留。发现只使用 Nacos；不迁入 Git 拉取、公共目录浏览、批量更新及回退业务。安装与回收事务所需的本地恢复能力保留；旧安装记录只作兼容数据读取，不恢复公网功能。界面词条及元数据只保留中文、英文。

`forge-enterprise` 随包交付技能管理器，独立研发套件 `forge-engineering` 拥有正式企业流程技能。管理器在自己的创建、导入及 Host provider 路径拒绝 `enterprise-*` 个人候选，不修改正式技能的调用策略，既有用户文件保留。正式流程沿用宿主随包技能的 `rank: 600`；原生个人及项目 provider 的同名候选选择遵循宿主规则，管理器不提供宿主全入口的同名覆盖防护或同权插件隔离。

## 3. 配置与数据

Nacos 配置仅 Host 可读：服务 URL、命名空间、账号密码的环境变量名、超时及显式本机 HTTP 开关。预览版由部署方在启动 Host 时注入环境变量，Nacos 模块直接读取当前进程环境；不要求录入宿主凭据库，不实现 IAM 换票。凭据缺失、为空或全空白时拒绝企业库访问并清除缓存令牌，本地管理仍可用。每次远端操作核对凭据指纹，变化后重新登录；令牌仅缓存于内存。外部环境变更须重启 Host 才能继承，插件不自行加载 `.env`；打包不注入秘密。字段及错误语义见[Nacos 契约](../../contracts/nacos-skills.md)。

环境变量凭据是仅限预览版、由项目负责人确认的 P8 受信存储临时例外，不宣称正式版完全符合该项规范；全局高阶规范保持原要求。正式接入仍须核验凭据来源及生命周期。页面仅展示技能所属命名空间 ID，不开放配置或切换，不展示账号、密码或令牌；不接入个人 ACL，不把 IAM 令牌发送给 Nacos。

沿用 `$DSH_HOME/skills-manager` 的状态、来源配置、安装记录与回收站格式，以及宿主全局/项目技能位置。首次安装不自动清理旧数据。旧插件与新插件不得同时挂载；安装替换前备份 profile 配置，卸载不删除用户技能与状态。

ZIP 使用固定版本 fflate 在构建期内联，运行时不解析外部依赖。单锁文件管理开发工具；安装制品无需现场编译、下载工具或连接公网。生成物检查先通过包内 `scripts/check-sdk.mjs` 校验本包开发 SDK 与根 `.dsh-version` 一致，再执行临时重建比对；公共版本检查入口不承担本包专属 SDK 扫描。

## 4. 接口与准入

HTTP 使用同源已认证的 `connection.fetch`，不注册裸 HTTP 回落。写请求先验证同源、自定义标记、JSON、已登记工作区及可写根；并发变更串行化。页面本地管理是用户操作，不等同于 Agent 工具授权。首版不注册 `create_skill` 自动工具，不放宽 `forge-policy` 的宿主目录保护。

Nacos 只允许登录、列出技能、下载版本三个固定服务端路径。仅展示已启用并带已发布 latest 标签的技能，详情和安装重新核对版本。完整资源下载后默认禁用，由用户显式启用；服务不可达只影响发现，本地管理仍可使用。详细字段与错误边界见[Nacos 契约](../../contracts/nacos-skills.md)。

本地管理状态机：准备 → 验证 → 写安装意图 → 暂存资源与禁用策略 → 提交文件 → 确认记录。失败在提交前不写最终目录，提交结果不确定时保留恢复记录、不报告成功；恢复只核对本地内容，不重新下载。回收与恢复继续校验来源和工作区，不能误删不匹配副本。

浏览器本地写入使用准备、提交中、待确认、已确认、已拒绝状态。每次提交携带操作标识；传输失败、无效响应或未知服务端异常保持待确认，后续只查询回执，不重发写入。待确认状态在同一客户端运行时跨组件重挂载保留。确认成功后重新读取宿主快照；刷新失败提示结果已确认但视图未更新，不把旧快照当作新状态。HTTP 适配器统一规范化错误体和回执，视图不解包原始错误字段。

同权 Host JS 及同账户进程可绕开插件内检查、访问同账户凭据，插件不是进程隔离安全边界。只读权限最终由 Nacos 服务端落实；客户端不调用上传接口不能替代服务端拒写验证。

## 5. 企业技能库界面

发现页采用轻量卡片市场，与企业账号设置共用宿主颜色、细边框、圆角和按钮原语。页头保持紧凑，四个管理页签保留；企业库不嵌套额外外围卡片。卡片展示真实名称、版本、最多三行用途及详情入口，不生成分类、中文别名、评分或热度。内容容器小于 640px 为单列，达到 640px 为双列。

卡片底部左侧以 12px 次要文字和线性图标展示命名空间 ID、下载次数，右侧保留详情按钮。命名空间过长省略，悬停及辅助技术可读取完整含义；下载次数为零正常显示，缺失不展示。空间不足时底部自动换行，详情按钮保持右对齐。下载次数采用 Nacos 真实统计，不标作安装量或使用人数。列表标注按下载次数排序，由服务端降序后分页，每页请求 20 条，不执行当前页局部排序。

搜索按技能名称提交，清空恢复第一页，刷新沿用已提交条件。仅标注本页条目数：上游 total 包含被过滤项，不代表可下载总数。当前页为空且上游仍有记录时允许翻页；单页隐藏分页。首次读取显示骨架，刷新保留旧列表并显式显示刷新状态；列表、详情、下载各有独立状态，迟到响应不得覆盖新选择。旧列表继续显示时，条目数和页码仍归属于其已完成的响应。

市场下载状态由安装记录轴统一投影，HTTP 轴通过注入端口组合 Nacos 列表/详情与本地状态；不新增持久文件、浏览器下载历史或横向轴依赖。来源身份包含服务根、命名空间、名称和版本，按全局及各已登记项目分别核验资源。已确认且摘要一致显示已下载，本地内容变化显示已下载且本地已修改，未确认及不可核验分别提示待确认和暂不可核验。回收或移除后不保留已下载提示，恢复后重新核验。重入市场、刷新、详情重开及下载确认均读取 Host；目标已有副本时禁用重复下载并可前往本地管理，其他目标保持独立。字段及错误语义见 [Nacos 契约](../../contracts/nacos-skills.md#3-本地边界与错误)。

详情使用宿主弹窗，目标宽度 640px，窄屏保留两侧安全间距；标题和操作固定，正文独立滚动。Markdown 预览支持标题、列表、代码与表格，禁用原始 HTML、图片及非 HTTP(S) 链接，不执行技能内容。资源清单折叠展示。下载位置使用全局技能、项目技能两个业务名称，项目只选已登记且可用的工作区；路径置于折叠的次级说明。

下载保持单飞，只有服务端确认后才显示成功；取消或结果不确定不自动重试写入。成功消息提供前往对应全局或项目技能的入口，下载仍默认禁用；列表刷新失败明确提示勿重复下载。浏览器组件通过回调请求现有管理页定位，不另建持久化状态；结果核对复用同一已认证 HTTP 边界和安装回执契约。

安装结果分为确认成功、确认拒绝、待确认。已派发安装请求的传输失败、取消及安装记录未确认均进入待确认；关闭和重开详情不得清除此状态。待确认目标由 Host 只读状态查询与现有安装记录核对，未获确认时禁止再次安装，不通过重新下载探测结果。查询不触发新的写入；同一 Host 运行时的请求状态在安装结束前保留，已提交但未确认的结果由持久安装意图继续约束。本地恢复完成后，查询仅在安装记录已确认、来源和目标仍有效且完整文件摘要一致时确认成功；记录自报完成不能代替内容核验。Host 重启后未见回执仍保持待确认，不承诺跨进程幂等。

Markdown 及其依赖在构建期内联进唯一客户端 bundle，React 复用宿主。构建仅生成运行代码，生成物检查在临时目录重建代码并只读核对文件清单及内容一致性。离线交互测试覆盖搜索、翻页、迟到响应、详情失败、重复下载、取消、成功定位及本地刷新失败；实际宿主布局与企业 Nacos 联调分别取证。

结构守卫遍历完整客户端源码集合和入口函数内部，按符号所有权检查网络、错误读取、持久化及状态位置；状态文件写入只允许存储所有者。每项约束以实际违规位置的变异证明会失败。构建使用稳定的依赖模块标识，生成物不得包含构建机器的绝对路径，依赖位于另一 checkout 时仍应生成相同代码。

## 6. 实施与验收

`scripts/verify-host.mjs` 接受实际 DSH CLI 入口和已校验的独立或企业组合 tarball，在全新临时 HOME、DSH_HOME 和 profile 内离线安装，并通过真实 CLI 启动仅绑定环回地址的 web 宿主。Nacos 使用独立合成 HTTP 服务，身份、技能及二进制资源均为合成数据；脚本不读取用户默认 profile、凭据或企业服务。验收覆盖已认证路由、并发管理、下载回执及响应丢失、重启恢复、插件禁用和再次装载、卸载后用户数据保留。原始启动令牌和浏览器 Cookie 仅在内存使用，不写入证据。证据记录实际 Node/DSH 版本、制品摘要和每项结果；真实 CLI 的 HTTP 验收、SDK 生命周期用例及浏览器组件用例分别记账，不相互替代。

1. 登记设计和范围，建立实际接口、生成物与离线正反向用例。
2. 迁入独立包，删除非 Nacos 发现实现、多余语言和发布脚本；适配包名、Loader、配置及来源记录。
3. 接入企业依赖与补丁，验证单包/组合制品闭包与数据兼容。
4. 隔离 profile 验证真实宿主装载、技能重名保护、下载禁用、启停、回收、卸载；企业 Nacos、国产平台及生产身份联调独立记账。

离线用例覆盖恶意 ZIP、未配置、认证失败、取消、超时、版本变更、并发写、损坏状态、项目越界、回收恢复、正式技能重名、路由销毁及缺依赖。包内 `test/provider-policy.test.mjs` 以实际 SkillRegistry 和合成 provider 验证管理器拒绝保留名称、保留既有文件及宿主候选选择规则，不直接导入研发插件源码，不代表真实研发插件联合验收。结构判据须以故意破坏单 bundle、入口职责或远程来源的变异证明会失败。实现状态唯一入口为[设计索引 §2.2](../README.md#22-实现与验证入口)。
