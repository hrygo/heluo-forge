## 1. 定位与准入

`@heluo/forge-skills-manager` 是 DSH Host + Client 插件，界面名称为「技能管理」，提供本地技能管理与 Nacos 公共库发现、下载。范围以[需求基线 §2](../../requirements/requirements-baseline.md#2-范围边界唯一真源)为准。源码与构建产物在本工作区维护。

装载使用宿主的 `connection.fetch`、`skills.registerProvider`、会话及浏览器 slots/locale/primitives 接口；目标版本从根 `.dsh-version` 读取。插件用自己的包和 `cordis.patch.yml` 装配。需要身份能力时，可通过 Cordis 动态服务注入使用同一 Host 已安装的 `iam` 服务；当前没有具体 IAM 消费功能，IAM 不属于必需注入或 npm 运行时依赖。准入按[插件高阶规范](../../engineering/dsh-plugin-conventions.md)建立可失败的判据，验证结果见[模块记录](../verification/forge-skills-manager.md)。

插件制品当前为 `0.1.0`，阶段为预览；`engines.dsh` 声明安装下限，精确 SDK 与兼容验收基线由 `.dsh-version` 管理，不推定范围内全部版本可用。文档版本独立于插件与宿主版本。同版本制品用 SHA-256、包体 manifest、源提交及工作区是否含未提交修改追溯，不仅以文件名或版本号判断。源码构建、制品构建、严格兼容和实际宿主试用的结果分别记账。

## 2. 结构与所有权

入口只装配。Host 分为本地技能及状态、安装记录与恢复、Nacos 会话、provider、HTTP 路由；每份可写状态只由对应模块持有。跨轴通过参数端口协作，纯类型、路径与摘要函数可共享。浏览器交付一个 ModuleLoader bundle，保留原有构建技术；生成物提交入库并校验与源码一致。源文件按常量、IO、状态、视图分段，结构守卫按符号归属判断。

管理策略由独立存储所有者持有，提供快照读取和事务更新；事务在同一状态文件的进程内队列中完成读取、迁移、校验、修改及原子提交。启停、分类、备注、来源清理和安装恢复均使用该入口，业务模块不得自行读取旧快照后整份写回。目录相关的 schema 判定经显式端口注入存储；`core` 保留本地业务兼容出口。安装记录事务可以等待策略事务，策略事务不得反向等待安装队列；远端下载不持有策略写入队列。同账户其他进程的写入不在进程内串行保证范围内。

写请求仅接受 `x-dsh-skills-manager: 1` 客户端标记，不接受其他标记头作为兼容入口；该标记不替代宿主认证。HTTP 只负责准入、协议适配和调用，查询快照在本地恢复后生成；安装管理器和 HTTP 仅依赖各自使用的窄端口。路由注册逐项取得清理责任，中途失败按逆序释放已注册项并保留原异常。业务及可识别的文件系统失败在对应适配器转换，未知程序异常保留为服务端异常，不进入普通导入失败明细。

HTTP 生命周期为运行、关闭中、已关闭。关闭时停止新任务准入，拒绝尚未开始的排队写入并取消远端读取；已开始的本地事务完成提交或保留待确认记录。同一管理目录的新实例等待旧实例的本地写入结束，不能各自持有互不相干的写队列。卸载不删除用户数据。

入口位置统一由 `getEntryLocation`、`setEntryLocation` 读写，默认「两边显示」：主页左侧栏「插件」下方与设置菜单各保留一个入口，宿主声明侧栏槽位前仅设置入口可见；旧布尔值 `sidebarEntry` 和 HTTP `enabled` 字段只在存储及路由兼容边界解释，已显式保存的位置不被默认值改写。删除技能直接返回现有操作结果，不另设无消费者的进程内失败标记。HTTP 请求类型仅描述已挂载操作，旧安装记录的格式校验和恢复逻辑独立保留。

全局技能、项目技能、其他 Agent 来源、分类、自建/导入、回收站保留。发现只使用 Nacos；不提供 Git 拉取、公共目录浏览、批量更新及回退业务。安装与回收事务所需的本地恢复能力保留；旧安装记录只作兼容数据读取，不恢复公网功能。界面词条及元数据只保留中文、英文。

全局 DSH、全局公共 Agent 和有效已登记项目的 DSH 来源支持受校验的写操作；Codex、Claude Code 等其他 Agent 源文件只读，本插件策略启停不修改对方文件或对方 Agent 的调用规则。自定义来源只有在配置与安全判定均允许时才可写。Nacos 下载仅写全局 DSH 或已登记项目，不写其他 Agent 目录。默认来源发现使用 Host 用户主目录和相应 `DSH_*_HOME` 配置，单独修改 `DSH_HOME` 不隔离其他来源。

`forge-engineering` 拥有正式企业流程技能。管理器在自己的创建、导入及 Host provider 路径拒绝 `enterprise-*` 个人候选；不修改正式技能的调用策略，既有用户文件保留。正式流程沿用宿主随包技能的 `rank: 600`；原生个人及项目 provider 的同名候选选择遵循宿主规则，管理器不提供宿主全入口的同名覆盖防护或同权插件隔离。

## 3. 配置与数据

正式交付由本包的 `scripts/package.mjs` 在制包时预置 Nacos 连接：地址、命名空间和固定 `credentialsRef: bundled` 写入独立 TGZ 的 `cordis.patch.yml`，专用只读账号密码写入包内 `private/nacos-credentials.json`，归档模式为 0600。Host 的 Nacos 模块从自身包位置读取固定文件，不接受任意路径，不将凭据回填宿主配置；无需员工填写 profile。源码构建的中性 TGZ 不含部署值，仅用于开发与构建核验。开发联调可通过 profile 的 `heluo-skills-manager.config.nacos` 覆盖；未配置时本地管理仍可使用。字段及错误语义见[Nacos 契约](../../contracts/nacos-skills.md)。

制包入口只接受 Nacos 专用配置，不要求 enterprise、IAM 配置或企业交付器。复用现有 Nacos 字段校验、补丁注入、归档与独立校验器；配置按数据解析，四项缺失、未知键或配置权限过宽时在写入产物前拒绝。POSIX 要求配置权限 0600，Windows 要求禁用继承且 ACL 仅授权当前用户、SYSTEM 和 Administrators。输出必须为仓库外的新目录，先在临时目录构建与校验，全部通过后发布。交付版本须区别于中性包；回执只列字段名、摘要与 `nacos.password` 已内嵌声明，不含原配置文件、密码或令牌。企业安装器与交付器不负责本包。

DSH「打开配置文件」显示 profile 补丁；插件不提供 Nacos 配置表单，也不向浏览器返回地址、账号、密码或凭据变量名，技能命名空间仍可展示。本机配置可由同账户用户读取，不提供配置加密。

Nacos 使用专用只读账号。`credentialsRef` 仅接受 `bundled`，不能与直配账号密码或环境变量名混用；文件缺失、损坏、链接、超限或凭据无效时返回固定 `error.nacos.config`，清除缓存令牌且不回落环境变量，本地管理仍可使用。无引用的旧开发配置保持兼容，显式任一凭据字段要求两项完整。每次远端操作重新读取并核对凭据指纹，变化后重新登录，令牌仅缓存于内存。插件不自行加载 `.env`，不接入个人 ACL 或 IAM 换票，不把 IAM 令牌发送给 Nacos。该机制隔离配置诊断，不能阻止持包人或同账户进程读文件；安装后的权限依赖包管理器及目标文件系统，不将归档模式当作 Windows ACL 保证。企业项目级安装器与交付器保持不变。包内专用凭据的授权及可读取边界见契约 §1.3。

管理状态、来源配置、安装记录与回收站存储于 `$DSH_HOME/skills-manager`，技能文件使用宿主全局/项目技能位置。插件以 `heluo-skills-manager` 行单次挂载；安装不自动清理已有数据，卸载不删除用户技能与状态。

ZIP 使用固定版本 yauzl 在构建期内联，以 Node 流式解压及 CRC32 校验实际内容；本地上传与企业下载共用读取器。每项实际长度须与目录声明一致，条目数、单项及累计输出同时受预算约束；整个包通过校验后才返回文件或进入写入流程。文件名按 UTF-8 解码后执行既有路径规则，避免旧编码将控制字节转成可打印字符。读取器及其传递依赖的许可证保留在生成模块中，运行时不解析外部 npm 依赖。单锁文件管理开发工具；安装制品无需现场编译、下载工具或连接公网。生成物检查先通过包内 `scripts/check-sdk.mjs` 校验本包开发 SDK 与根 `.dsh-version` 一致，再执行临时重建比对；公共版本检查入口不承担本包专属 SDK 扫描。

上传和企业库资源路径采用 Windows、macOS 与 Linux 可共同使用的文件名规则：拒绝控制字符、Windows 保留字符及设备名、末尾点或空格；重复路径按 Unicode NFC 规范化并忽略大小写判定，同一父目录的不同大小写或规范化拼写也拒绝，写入保留原始名称。上传目录、上传 ZIP 与企业库下载均执行该规则。可写根与安装记录读取继续拒绝普通祖先链接及技能内部链接；macOS 仅允许 `/tmp`、`/var`、`/etc` 分别直接链接至 `/private/tmp`、`/private/var`、`/private/etc` 且目标为目录，不将任意用户链接视作系统别名。路径检查不提供对同账户并发置换目录的进程隔离。

浏览器上传与企业 ZIP 下载按普通文件保存内容，不还原 POSIX 执行位、所有者或链接元数据；脚本通过已安装的解释器调用，例如 `bash scripts/run.sh` 或 `python3 scripts/run.py`，不保证 `./scripts/run.sh` 可直接执行。源码级跨平台校验与目标系统实机运行分别取证。

## 4. 接口与准入

下载响应体中的连接中断在有界读取入口转换为 `error.nacos.unavailable`，发生在本地安装前时明确拒绝；取消、超时和未知程序异常分别保留原语义。目标已有待确认操作或回执容量不足时，新请求以 `error.proto.busy` 明确拒绝，原操作的回执不变。策略存储区分暂存写入和最终替换：暂存失败确认未提交并返回 `error.state.write`；替换结果不确定时由存储所有者提供只读核验，当前状态与提交前后均不匹配则继续待确认。

回收事务在移动前保存事务 ID、允许的条目形态和完整资源摘要，包含目录及同名 `.md` 和本地修改；暂存路径使用同一 ID。恢复仅在原位置和暂存资源的完整并集与摘要一致且不存在重复条目时回滚暂存，不覆盖已有文件。已发布回收项保持回收状态。恢复的成功判据同时检查来源、完整资源和隐藏回执；永久删除在资源与来源记录都已结清后才确认。操作回执查询只读，恢复写入由正常管理视图执行。

浏览器对首次 POST 与后续查询共用安装回执判据，要求 `name`、`root` 为字符串且名称与原请求相同；校验前保留原 UUID，无效响应不显示成功或重发安装。第三方依赖按 esbuild 实际输出贡献生成 `lib/THIRD-PARTY-NOTICES.txt`，列出固定版本和原始版权许可，随源码生成物及 TGZ 交付；外部宿主依赖及未进入运行时的测试库不列入。

HTTP 使用同源已认证的 `connection.fetch`，不注册裸 HTTP 回落。写请求先验证同源、自定义标记、JSON、已登记工作区及可写根；并发变更串行化。页面本地管理是用户操作，不等同于 Agent 工具授权。首版不注册 `create_skill` 自动工具，不放宽 `forge-policy` 的宿主目录保护。

Nacos 只允许登录、技能列表、技能元数据和 Client 资源读取四个固定服务端路径。仅展示已启用、带有效 latest 标签且该精确版本为 online 的技能；列表缺少版本状态时仅补查本页候选元数据。详情和安装重新核对名称、命名空间、启用状态、latest 与该版本在线状态，并显式指定版本调用 Client API，使下载时下线仍受服务端拒绝。完整资源下载后默认禁用，由用户显式启用；服务不可达只影响发现，本地管理仍可使用。详细字段与错误边界见[Nacos 契约](../../contracts/nacos-skills.md)。

本地管理状态机：准备 → 验证 → 写安装意图 → 暂存资源与禁用策略 → 提交文件 → 确认记录。失败在提交前不写最终目录；首次意图写入失败后，若只读持久状态可确认该来源和目标的意图未落盘、资源尚未复制，则明确拒绝并释放请求，磁盘恢复后允许新请求重试。持久状态无法读取或已有相关意图时保持待确认，不据异常类型猜测未提交。提交结果不确定时保留恢复记录、不报告成功；恢复只核对本地内容，不重新下载。回收与恢复继续校验来源和工作区，不能误删不匹配副本。

浏览器本地写入使用准备、提交中、待确认、已确认、已拒绝状态。每次提交携带操作标识；传输失败、无效响应或未知服务端异常保持待确认，后续只查询回执，不重发写入。带来源的回收恢复在移动前保存原来源、位置及完整资源摘要，包含用户的本地修改；正常管理视图读取完成本地恢复后，回执查询只核对来源已确认、回收目录已移除及资源与原摘要一致，满足时转为成功并解除提交锁。查询不执行恢复或写盘，来源缺失、资源变化或核验失败仍保持待确认。待确认状态在同一客户端运行时跨组件重挂载保留。确认成功后重新读取宿主快照；刷新失败提示结果已确认但视图未更新，不把旧快照当作新状态。HTTP 适配器统一规范化错误体和回执，视图不解包原始错误字段。

同权 Host JS 及同账户进程可绕开插件内检查、访问同账户凭据，插件不是进程隔离安全边界。只读权限最终由 Nacos 服务端落实；客户端不调用上传接口不能替代服务端拒写验证。

## 5. 企业技能库界面

发现页采用轻量卡片市场，与企业账号设置共用宿主颜色、细边框、圆角和按钮原语。页头保持紧凑，四个管理页签保留；企业库不嵌套额外外围卡片。卡片展示真实名称、版本、最多三行用途及详情入口，不生成分类、中文别名、评分或热度。内容容器小于 640px 为单列，达到 640px 为双列。

卡片底部左侧以 12px 次要文字和线性图标展示命名空间 ID、下载次数，右侧保留详情按钮。命名空间过长省略，悬停及辅助技术可读取完整含义；下载次数为零正常显示，缺失不展示。空间不足时底部自动换行，详情按钮保持右对齐。下载次数采用 Nacos 真实统计，不标作安装量或使用人数。列表标注按下载次数排序，由服务端降序后分页，每页请求 20 条，不执行当前页局部排序。

搜索按技能名称提交，清空恢复第一页，刷新沿用已提交条件。仅标注本页条目数：上游 total 包含被过滤项，不代表可下载总数。当前页为空且上游仍有记录时允许翻页；单页隐藏分页。首次读取显示骨架，刷新保留旧列表并显式显示刷新状态；列表、详情、下载各有独立状态，迟到响应不得覆盖新选择。旧列表继续显示时，条目数和页码仍归属于其已完成的响应。

市场下载状态由安装记录轴统一投影，HTTP 轴通过注入端口组合 Nacos 列表/详情与本地状态；不新增持久文件、浏览器下载历史或横向轴依赖。来源身份包含服务根、命名空间、名称和版本，按全局及各已登记项目分别核验资源。已确认且摘要一致显示已下载，本地内容变化显示已下载且本地已修改，未确认及不可核验分别提示待确认和暂不可核验。回收或移除后不保留已下载提示，恢复后重新核验。重入市场、刷新、详情重开及下载确认均读取 Host；目标已有副本时禁用重复下载并可前往本地管理，其他目标保持独立。字段及错误语义见 [Nacos 契约](../../contracts/nacos-skills.md#3-本地边界与错误)。

详情使用宿主弹窗，目标宽度 640px，窄屏保留两侧安全间距；标题和操作固定，正文独立滚动。Markdown 预览支持标题、列表、代码与表格，禁用原始 HTML、图片及非 HTTP(S) 链接，不执行技能内容。资源清单折叠展示。下载位置使用全局技能、项目技能两个业务名称，项目只选已登记且可用的工作区；路径置于折叠的次级说明。

下载保持单飞，只有服务端确认后才显示成功；取消或结果不确定不自动重试写入。成功消息提供前往对应全局或项目技能的入口，下载仍默认禁用；列表刷新失败明确提示勿重复下载。浏览器组件通过回调请求现有管理页定位，不另建持久化状态；结果核对复用同一已认证 HTTP 边界和安装回执契约。

安装结果分为确认成功、确认拒绝、待确认。已派发安装请求的传输失败、取消及安装记录未确认均进入待确认；关闭和重开详情不得清除此状态。待确认目标由 Host 只读状态查询与现有安装记录核对，未获确认时禁止再次安装，不通过重新下载探测结果。查询不触发新的写入；同一 Host 运行时的请求状态在安装结束前保留，已提交但未确认的结果由持久安装意图继续约束。本地恢复完成后，查询仅在安装记录已确认、来源和目标仍有效且完整文件摘要一致时确认成功；记录自报完成不能代替内容核验。Host 重启后未见回执仍保持待确认，不承诺跨进程幂等。

Markdown 及其依赖在构建期内联进唯一客户端 bundle，React 复用宿主。构建仅生成运行代码，生成物检查在临时目录重建代码并只读核对文件清单及内容一致性。离线交互测试覆盖搜索、翻页、迟到响应、详情失败、重复下载、取消、成功定位及本地刷新失败；实际宿主布局与企业 Nacos 联调分别取证。

结构守卫遍历完整客户端源码集合和入口函数内部，按符号所有权检查网络、错误读取、持久化及状态位置；状态文件写入只允许存储所有者。每项约束以实际违规位置的变异证明会失败。构建使用稳定的依赖模块标识，生成物不得包含构建机器的绝对路径，依赖位于另一 checkout 时仍应生成相同代码。

## 6. 实施与验收

### 6.1 验证分层

验证分为默认离线回归与显式宿主兼容验证。默认 `test`、`verify` 及根 `check` 覆盖本地管理、Nacos、UI、结构变异、实际 Cordis 生命周期与 SkillRegistry 候选选择；仅为这些用例安装 Cordis 和技能注册 SDK，不引入完整原生调用链。原生 filesystem provider、scope 合并和 `skill.execute` 回归置于 `compat/`，由 `test:compat <installed-dsh-dir>` 单独执行，使用指定已安装 DSH 的 SDK。入口核对宿主及所需 DSH SDK 与根 `.dsh-version` 完全一致，缺少路径、SDK 或版本不符均失败，不从本包开发依赖回落，不以跳过表示兼容通过。发布、升级宿主基线及修改技能发现、优先级或启停逻辑时必须执行该项；其结果与默认回归、真实 CLI 验收分别记录。

`scripts/verify-host.mjs` 接受实际 DSH CLI 入口和已校验的 Skill Manager 独立 tarball，在全新临时 HOME、DSH_HOME 和 profile 内离线安装，并通过真实 CLI 启动仅绑定环回地址的 web 宿主。Nacos 使用独立合成 HTTP 服务，身份、技能及二进制资源均为合成数据；脚本不读取用户默认 profile、凭据或企业服务。验收覆盖已认证路由、并发管理、下载回执及响应丢失、重启恢复、插件禁用和再次装载、卸载后用户数据保留。原始启动令牌和浏览器 Cookie 仅在内存使用，不写入证据。证据记录实际 Node/DSH 版本、制品摘要和每项结果；真实 CLI 的 HTTP 验收、SDK 生命周期用例及浏览器组件用例分别记账，不相互替代。

离线用例覆盖恶意 ZIP、未配置、认证失败、取消、超时、版本变更、并发写、损坏状态、项目越界、回收恢复、正式技能重名、路由销毁及缺依赖。包内 `test/provider-policy.test.mjs` 以实际 SkillRegistry 和合成 provider 验证管理器拒绝保留名称、保留既有文件及宿主候选选择规则，不直接导入研发插件源码，不代表真实研发插件联合验收。结构判据须以故意破坏单 bundle、入口职责或远程来源的变异证明会失败。实现状态唯一入口为[设计索引 §2.2](../README.md#22-实现与验证入口)。
