## 1. 结论

DSH 将取代 Comet 与 oh-my-sdd，作为企业新一代智能研发工具；参考旧项目**使用企业工具的方式**，不要求复用其代码、Runtime、安装器或阶段体系。优先让模型与 Harness 承担通用分析、规划、实现、验证和修复；本项目补充企业事实、规范、工具入口、授权约束和工程追溯。

六阶段地图表示各阶段可提供的帮助，不表示 DSH 接管六阶段，更不以用户故事上线结束作为一次 DSH 任务必须负责到底的目标。业务验收、生产发布与最终结项继续由已有平台和人员负责。工程交付可以处于待评审、待合入、待 UAT 等状态，不能被统一包装成完成。

本稿同时描述只读基线与明确的受控写目标；后者不是远期口号，但在范围调整、服务端权限及运行时控制核验完成前保持禁用。具体边界只在需求基线 §2.3 维护；本稿不发布接口已可用或一期已扩围的结论。

## 2. 目标、边界与证据

### 2.1 企业任务模型

| 对象 | 含义和真源 | DSH 责任 |
|---|---|---|
| 用户故事 | DevOps；业务价值、故事级范围与验收；可由多个系统承建 | 读取背景；改变故事级要求必须有相应人的决策，不能只改子变更 |
| 系统变更 | DevOps；独立描述与验收；绑定一个明确系统及明确仓库 | 一次承接一个明确变更；获取正式要求，在该仓库交付 |
| Issue | Gitee；按真实工程交付边界建立工作项 | 简单变更可一项，复杂变更可多项；不按分析/计划/编码阶段机械建单 |
| PR 与提交 | Git/Gitee；实际代码、评审和合入事实 | 维护 Issue 关联；相关 commit message 均以 `[变更号]` 开头；最终合入记录也不丢失该标识 |
| 构建、制品、UAT 部署 | 需求方确认 DevOps 已关联展示；实际记录仍由原 CI/CD 负责 | 优先读 DevOps；不另建追溯系统、不接管部署；部署成功不等于验收通过 |
| 业务验收、上线与结束 | 业务人员验收，既有流程上线；故事结束时系统变更随之结束 | 不代理业务判断；不在 PR 创建、合入或 UAT 部署后调用最终结项 |

故事与系统变更的最终结束时间不可由工程交付时间代填。开始时间及研发进展仅在平台字段语义、可写权限明确后记录；不假定两个对象的开始时间也自动联动。Issue 在相应验收通过且关联交付 PR 已合入后才可关闭；Issue 已关而系统变更未结束是正常的生命周期差异。

### 2.2 入口与交付约定

用户明确执行 command/Skill 并提供系统变更号才构成承接；命令名待 DSH 接口核验后确定。编号无效、信息读取失败、系统/仓库不匹配时停止该企业任务，不用自然语言相似度猜测变更。用户输入只确定意图，不证明服务端权限。

目标清楚后允许模型自主组织方法；模糊且需人取舍时给出 2–3 个有区别的方案、影响和建议。确认后的业务澄清回写相应 DevOps 对象；普通技术方案不全部回灌为业务规范。回写冲突不覆盖他人修改。

更强模型先交叉审查，技术问题可自动修复与复审，人确认最终审查结果；结果正式留在 Gitee PR。AI 意见不冒充人工批准，人工确认不等于合并授权，DSH 不自动合并。使用现有模型选择、独立审查 execution 与交互能力；若宿主不能证明隔离或模型可用，标待补能力，不自建调度引擎或伪称已完成交叉审查。

### 2.3 非目标

不实现源码、包清单、生产工具、通用 Agent 流程引擎、跨系统 Agent 调度、知识平台、部署引擎、审批系统、指标后台或新看板；不 fork DSH，不搬运五环、Hook Router、状态快照/receipt 链；不自动安装旧项目或执行其命令。只有本次范围内的必要缺口才提出最小补充。

### 3.2 企业规范消费

以条款而非整 Skill 为筛选单位：区分通用知识、企业差异、强制要求，并标适用系统/版本、维护责任与依据。模型可建议精简，规范维护者确认有效性；DSH 按任务选择，不自行豁免。即使模型知道某安全知识，企业仍需声明适用约束。过粗的条款补清判据，过细的方法偏好降为建议；规则冲突提交维护者，不让每个会话自创优先级。既有检查器能验证的要求优先复用，未实测的宿主拦截不宣称硬保证。

## 4. 六阶段能力地图

状态：**B** 为现有只读/本地产物基线（不代表实现或获批）；**W** 为需求方确认的受控写目标，跨团队范围与接口待批待验；**C** 为可设计的条件查询，必要性与接口待确认；**X** 为不建设。所有接口目前均未在企业内网核验。

| 阶段/能力 | 依赖及待核验项 | Agent 面 | 人类面 | 读写 | 形态 | 状态 |
|---|---|---|---|---|---|---|
| 需求：取系统变更、独立验收、所属故事、系统/仓库 | DevOps：对象、关联、权限、稳定输出 | 显式入口后查真实上下文 | 同一 CLI/DSH 会话摘要 | 读 | CLI + 薄 Skill | B |
| 需求：经确认的澄清、开始/进展记录 | DevOps：对象版本、字段语义、冲突与写权限 | 在已确认对象内回写 | 人确认业务决策，不搬运内容 | 研发写 | CLI；必要时薄工具 | W |
| 设计：企业规范、规格与冻结检查 | 企业规范维护者、目标仓库、既有校验器 | 按需上下文；方法由模型决定 | 仓库产物、现有 CLI 检查 | 读 + 本地写 | Skill + 确定性 CLI/CI | B |
| 开发：仓库、Issue、PR、合入事实 | Gitee：目标仓库、用户鉴权、结构化输出 | 精确资源查询 | 同一 CLI、原生仓库页面 | 读 | CLI | B |
| 开发：Issue/分支/提交/PR 关联维护 | Gitee：创建/编辑/关闭权限、去重与结果回查 | 真实边界拆单；相关提交带变更号 | 同一操作语义，不要求每步确认 | 本地 + 远端写 | Git/CLI + 既有策略 | W |
| 开发：交叉审查意见、人工确认留痕 | DSH：可用模型与独立 execution；Gitee：正式 review 及版本绑定 | AI 意见与人工确认分开 | DSH 确认；Gitee 正式记录 | 读 + 评审写 | 原生审查/交互 + CLI | W |
| 测试：实际检查与工程验收依据 | 仓库已有测试；执行环境、可用命令 | 原生执行并报告未验边界 | 可核对的结果与 PR 摘要 | 本地执行/证据写 | 原生工具 + 项目测试 | B；远端证据写属 W |
| 测试：缺陷/用例查询 | DevOps：必要场景、对象与访问权限 | 有需要才查询 | 同一 CLI或原平台 | 读 | CLI | C |
| CI：构建状态、失败摘要、制品关联 | DevOps 已展示（用户确认）；工具读取映射未验 | 优先 DevOps 查询，不重复接所有 CI | 同一事实来源 | 读 | CLI；原生页面作补充 | C |
| CI：主动触发/重跑流水线 | CI 提供方、安全：权限、消耗、幂等 | 当前不开放 | 继续原平台操作 | 远端写 | 不新增能力 | X；未来单独范围变更 |
| CD：本变更制品的 UAT 就绪信息 | DevOps：版本/变更关联、部署终态 | 查询，不代替功能验收 | 原平台交付记录 | 读 | CLI | C |
| CD：生产发布状态/发布单信息 | 既有变更平台；DevOps 是否已提供必要信息待验 | 仅在确认必要且获批后只读 | 原平台 | 读 | 优先已有查询 | C；不是一期必做 |
| CD：业务验收、生产部署/回滚/审批、故事/变更最终结束 | 业务与既有平台 | 不承担、不自动调用结束命令 | 既有业务流程 | 生产/业务写 | 不接入 | X / N9 |

所有 W 都是正常研发协作目标，不因“写”字等同生产变更；但命令级开关、任务范围、服务端权限、必要确认与审计必须分别成立。

## 5. 形态判定与人机双面

### 5.1 判定顺序

形态是职责组合，不是“命中一个就排除其他”。先定义必要业务能力和权限，再依次判断：

1. 已有企业 CLI 能满足双端运行、用户鉴权和稳定可判定输出时，**CLI 为默认执行面**；不要因模型会反复调用就先写插件工具。
2. 仅涉及企业业务语义、适用规则、产物与调用指引时用 **Skill**；不把授权、权威状态或真实副作用交给提示词保证。
3. CLI 存在必要的结果/交互适配缺口时，才评估 **薄插件工具**；其底层仍调用同一 CLI，不能形成另一套鉴权与数据账。策略/凭据接线优先使用既有宿主插件，不臆造 SDK 挂点。
4. 只有 CLI 三项前提失败或已确认的必要远程共享能力无法满足，才评审 **MCP**；失败先关闭动作，不自动部署服务。
5. 必须在仓库流水线验证的不变量交 **既有 CI job**，不让客户端复制流水线引擎。
6. 人需要可见信息时先用 **DSH 原生会话/确认、CLI 或原平台页面**；只有明确不可替代的需求才另评 Client 面板，不默认新增。

### 5.2 套用与反例

| 新能力 | 判定结果 | 反例及原因 |
|---|---|---|
| 查询变更及验收条件 | CLI 读取 + Skill 解释业务关系 | 常驻 MCP 包装同一个查询，只增加维护面 |
| 回写确认后的澄清 | 同一用户 CLI 受控写 + 原生确认 | Skill 写“已确认”不能替代真实人的决定与服务端权限 |
| PR 人工评审记录 | 原生确认 + 同一 CLI 写正式 review；绑定当前 PR 版本 | 另建面板/审批库会形成两套批准记录 |
| 查询 UAT 部署 | 优先读 DevOps 已有关联 | 为查询而新建部署引擎或直接连全部 CI/CD |
| 冻结/提交标识验证 | CLI 与已有 CI | 用工具描述解释规则，却没有可验证结果 |

### 5.3 同一能力的两张使用面

人和 Agent 使用同一业务动作、目标资源、结果语义和审计；可读展示不同，不能把原始 CLI 全部暴露给模型，也不能以“人能运行任意命令”绕过企业服务端权限。人类原平台操作仍按原平台审计，本项目不声称控制 DSH 外的所有行为。

固定的本次变更入口只表达有限委托：系统变更、仓库和已启用动作。普通 Issue/PR 维护不逐步询问；业务歧义、澄清采纳和人工 review 必须真实确认。委托不能覆盖 N9、自动合并、越权或数据外发 C3。宿主/策略必须能绑定并校验确认事实，不能只凭模型生成的参数；不能证明时关闭相关写动作，不新增一套二次授权后台。

## 6. 追溯与最小工具契约

```text
DevOps 用户故事 → 一个或多个系统变更
单个系统变更 → 明确系统与仓库 → 一个或多个 Issue
Issue ↔ PR → Git 提交/合入版本 → 构建/制品/UAT 事实
业务验收与生产上线 → DevOps 既有最终状态（只观察，不由 DSH 驱动）
```

| 追溯段 | 真源与读写责任 | 缺失处置 |
|---|---|---|
| 故事 → 系统变更 → 系统/仓库 | DevOps 读；需求决策后的澄清为受控写 | 边界不明确不承接，不新造业务主数据 |
| 系统变更 → spec/指纹 | DevOps 要求版本读；仓库规格及既有校验器生成冻结依据 | 无版本/指纹不能声称冻结覆盖，记录缺口 |
| spec/变更 → Issue/分支/提交/PR | Git/Gitee；仓库产物本地写，正式关联远端受控写 | 不凭相似标题认领；最终提交不能丢变更号 |
| PR/合入版本 → 测试/构建/制品 | Git/Gitee 与既有 CI；客户端读事实、受控写证据引用 | 测试必须匹配版本，缺证据不算通过 |
| 制品 → UAT 部署 | DevOps 展示的 CI/CD 关联读 | 无版本/变更对应关系为 unknown |
| 工程交付 → 发布单/上线事实 | 原平台为真源；有明确必要且获准时只读现有引用 | 无关联不声称上线；不新接生产写或代最终结项 |

标识、动作、结果未知、部分成功、确认与审计的字段唯一真源为[工程工具契约](../../contracts/engineering-tools.md)。指纹只证明冻结规格是否变化，不证明业务正确、PR 已合入或 UAT 已就绪。PR 描述关联本次采用的 DevOps 要求版本及规格指纹；平台不能提供版本标识时记缺口并使用明确人工确认，不伪造版本。

不重复建立全生命周期数据库。关联优先写回现有 DevOps/Gitee 支持的关联字段；若只有受控描述区/链接，需提供方确认维护规则；两者都不支持时将自动闭环标为阻塞，不宣称双向强一致。目标变更并发修改或未知写入结果只允许查询核对，禁止无脑重放。

## 7. 权限、数据与失败行为

| 场景 | 处置 | 用户可见结果 |
|---|---|---|
| 变更号无效、要求不可读、仓库不符 | 不承接；不靠旧上下文猜测 | 具体缺口及责任方 |
| 写开关关闭、权限不足、必要审计不可用 | 拒绝该动作；不借服务账号或换通道 | 没有发生写入或结果待核对 |
| 401/403、非结构化输出、超时/取消 | 区分未执行、失败、部分、未知 | 未知不当成功，也不自动重试写 |
| 创建 Issue 成功而建 PR 失败 | 保留已创建关联，查询后继续剩余动作 | 部分成功；不自动删对象“回滚” |
| 人确认后目标要求/PR 版本改变 | 原确认不再覆盖新版本 | 重取差异，按影响重新确认 |
| PR 未合入或检查未执行 | 不关 Issue；不写“已交付” | 待合入/未验证，不等于失败 |
| UAT 是别的版本、状态缺失 | 不宣布本变更 UAT 就绪 | 缺少交付关联，unknown |
| 指标上报失败 | 指标独立降级，不放宽必要审计 | 丢弃/缺失计数，不阻塞研发 |

凭据与工具正文按既有 C1–C4 和策略设计处理。操作审计记录主体、动作、目标引用、决定、结果及时间，不记录 token、提示词、代码、diff 或需求正文；业务所需内容在获准的业务写通道传递，不复制进指标事件。采集实现归属见 §9。

## 9. 研发效能与过程指标

### 9.1 目录与边界

以下为待 DevOps/PMO 冻结的观察口径，不作为绩效或准入评分。分母缺失即不可计算，不补 0；各来源均带覆盖范围与口径版本。DORA 的五项定义以[官方指南](https://dora.dev/guides/dora-metrics/)为参考（2026-10-22 文档核对，不代表企业已具备数据），本项目不扩大生产访问以采数。

| 指标 | 候选口径与分母 | 权威采集点 | 状态/误用风险 |
|---|---|---|---|
| 部署频率 | 指定系统/环境窗口内成功生产部署数 ÷ 窗口时长 | DevOps 已有发布记录 | 平台计算待确认；不按个人排名，不把 UAT 当生产 |
| 变更前置时间 | 各已进入生产的提交从提交到首次成功生产交付的时长分布；分母为关联完整的提交集 | Git + 发布记录，DevOps 关联 | 待确认；缺关联样本单列，不混入故事业务等待 |
| 变更失败率 | 需要立即干预的失败生产部署数 ÷ 同窗口生产部署总数 | 变更/故障记录 | 分类待确认；不以流水线单测失败代替 |
| 失败部署恢复时间 | 失败部署至服务恢复的时长分布；分母为有完整起止记录的失败部署 | 变更/故障平台 | 待确认；不是全部故障的通用 MTTR |
| 部署返工率 | 为处理生产问题而进行的非计划部署数 ÷ 生产部署总数 | DevOps 已有分类 | 待确认；不把正常 PR 修订当部署返工 |
| 需求输入就绪时间 | 显式承接到有效要求取得/澄清回写确认的时长分布；分母为结束该环节且事件齐全的变更 | 客户端补起点 + DevOps 要求版本 | 候选；缺输入就绪事件时不可计算，需先冻结事件/版本关联；反映沟通等待，非模型能力评分 |
| PR 等待合入时间 | PR 正式可评审至合入的时长分布；分母为有起止记录的合入 PR | Gitee / DevOps | 平台计算；不归因为 DSH 编码耗时 |
| UAT 交付就绪时间 | 约定合入版本至对应制品 UAT 成功的时长分布；分母为关联完整的交付单元 | DevOps | 待确认；不表示业务验收或故事完成 |
| 工程修订率 | 交叉/人工审查后需工程修订的 PR 数 ÷ 有结构化审查分类的 PR 数 | Gitee，客户端仅补缺少的分类事件 | 候选；正常迭代不直接算质量失败 |
| 工具动作成功率 | 已确认成功动作数 ÷ 全部终结逻辑动作数；同时列 failed/partial/unknown 比例 | 策略审计投影 | 候选最小集；重试不当新动作，未获准动作单列 |
| 人工决策请求率 | 发生明确业务决策请求的已承接变更数 ÷ 可观察的已承接变更数 | 仅结构化确认事件 | 候选 AI 子集；不从聊天轮数推导，不把必需评审/合并当低效 |
| AI 辅助变更占比 | 明确由 DSH 入口承接且关联有效的变更数 ÷ 同期同系统全部变更数 | DevOps 全量分母 + 客户端承接关联 | 分母/跨会话去重待确认；只看到 DSH 样本时不得计算 |
| 关联完整率 | 所需关联齐全的交付单元数 ÷ 同期应有关联的交付单元数 | DevOps / Gitee | 最小数据质量项；丢失/不适用分开 |

“最小集”先利用已有平台数据，并补动作结果和关联质量；人工决策请求、AI 辅助占比在定义与分母落实前不采。主体维度默认系统/项目/团队；个人如需本人可见须另经安全和 PMO 确认，不生成个人排名。指标不能替换登录、安装、活跃、故障、继续使用意愿等试点指标；M4 的撤销状态不恢复。

### 9.2 采集器归属

选择**并入 `forge-policy` 既有 OTel 操作审计设计的独立观察投影**，不新增采集包/服务。“既有”指既有方案职责，不表示该插件或摄取通路已经实现和可用。理由：同一工具结果和关联事实已有来源，再建独立 SDK/队列会重复计数并增加维护面。平台能算的指标不由客户端重算，不能从 Agent 自述补全平台事实。

必要审计与可选指标导出严格分离：前者按安全规则关闭动作，后者可有界缓冲/丢弃且不阻塞研发。若既有 OTel 路径不能独立降级或缺少摄取协议，关闭观察导出并列缺口，不默默新建独立采集器。事件、上报、保留及拒绝内容字段的契约唯一真源见[metrics-events](../../contracts/metrics-events.md)。

### 9.3 最小配置职责（不是已存在的配置键）

| 配置概念 | 默认与约束 | 维护者 |
|---|---|---|
| 观察导出开关 | 未审批前关闭；与必要安全审计分开，停用不删除正式业务记录 | 安全、平台 |
| 事件允许集 | 仅冻结的事件/schema；AI 子集未批准不采；不接受自由扩展字段 | DevOps、PMO、安全 |
| 出口及身份引用 | 复用现有获准 OTel 路由与机器出口身份；不把业务访问令牌借给摄取端 | IT、IAM、DevOps |
| 容量/保留/退避 | 使用事件契约候选上限并由责任方冻结，不在多文档复制数值 | 平台、安全、DevOps |
| 生效/降级 | 随现有配置生命周期生效；版本不兼容则关闭投影，必要审计仍独立执行 | 平台 |

具体配置键、SDK 挂点和热更新能力均待目标宿主核验，不因这张职责表新增配置管理系统。

## 11. 打包、兼容与退出

本稿是跨模块能力设计，不创建 `forge-devops-lifecycle` 包；配置与 Skill 仍按现有分发机制。DSH 目标版本和 SDK 挂点以对应模块实测为准，不从旧项目推导。停用某企业动作不删除 DevOps/Gitee 正式对象；停用观察指标不影响权威业务记录。契约草案需经提供方映射并冻结版本后才能实现；升级不得把未知旧字段默认解释成已批准。
