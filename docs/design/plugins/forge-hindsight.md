## 1. 结论

`@heluo/forge-hindsight` 是员工个人长期记忆的 Host 插件：员工按三档模式控制采集，查看与删除自己的记忆，Agent 在员工允许时检索并引用。一期 800 名员工共用一个 Hindsight 实例、一个数据库 schema，员工之间以 bank 隔离；bank 由接入边界按已验证身份单向决定，客户端不参与。

访问路径只有一条：插件 → 接入边界（BFF）→ Hindsight。原生 HTTP、`/mcp/{bank_id}/` 与管理控制面均不对员工网络开放。采集为三档模式（自动记录 / 关闭 / 未配置），默认「未配置」：未配置状态下首次触发记忆调用时，提示员工在「自动记录 / 关闭」中二选一，此后的行为按该选择执行，不再重复询问。

隔离依赖两个服务端组件：自写的 `TenantExtension`（只做身份，固定 schema）与 `OperationValidatorExtension`（bank 归属、列表收敛）。二者均属独立仓库的服务端扩展，不在本包内。

设计准入五项尚未全部满足（宿主事件未核验、范围基线未同步），因此本文不建立 `package.json` 与 `src/`。

## 2. 目标与非目标

**目标**：同一员工跨会话、目录、设备进入同一 bank；不同员工互不可见；采集受员工模式控制；删除覆盖原始内容与派生记忆；处理中、失败与未知状态可辨认。

**非目标**：跨助手通用记忆平台；业务管理员查看员工记忆；端到端加密；Git 历史与既有会话导入；云端记忆服务；本地缓存记忆与离线召回；自动更新；共享单实例多租户（N1）。

## 6. 权限、凭据与数据

| 项 | 处理方式 | 生命周期 | 失败时 |
|---|---|---|---|
| IAM 令牌 | 每请求经 `ctx.iam` 只读取用；不落盘、不进环境变量、不进日志 | 随 IAM grant；过期即失效 | 拒绝访问，不回退长效 Key |
| 记忆正文 | 仅经 BFF 流转；不写本地文件、不进指标与审计 | 由员工删除或企业规则决定 | 静默跳过，不缓存正文 |
| 采集设置 | 存 profile 设置（非凭据），按 IAM `sub` 分区存放 | 随该身份失效；换号视为未配置 | 未配置状态下不采集、不召回；读不出同样按未配置处理 |
| 审计字段 | 动作、结果、耗时、请求 id；不含正文 | 按审计策略 | 无法审计则拒绝写操作 |

**设置绑定身份**：采集模式是员工对“是否记录我自己的对话”的授权，按 IAM `sub` 分区存放。同一实例换人登录时，新身份一律视为未配置，不得继承前一位员工已选的 `auto`。身份代际变化时，在途请求与进行中的提示一并作废。

**身份缓存与有效性判定**：缓存只回答“这个 AT 属于谁”——`hash(AT) → sub / 授权范围`，保留 2 小时，到期重新解析，同时限制条目总量避免无界增长；AT 被替换后 `hash(AT)` 变化，自然重新解析，不复用上一条目的身份。令牌是否仍可用不进入缓存：每个请求都由 BFF 判定一次，`exp` / `nbf` 本地校验，不从缓存继承结论。接入边界一旦具备撤销信号（校验接口或事件推送），信号缺失或判定失败即拒绝新操作；当前不具备该信号时，按下一段的口径如实执行，不声称具备。

**撤权窗口的当前边界**：现有 IAM 回函记录访问令牌为不透明令牌且无标准内省端点，因此 BFF 目前只能做到“令牌寿命级”判定——AT 失效或被替换后，新请求因 `hash(AT)` 变化重新解析，最迟随 AT 到期失效。员工被停用或异地登出后，若本地仍持有未过期 AT，最长可持续到该 AT 到期（默认 7200 秒，公开客户端是否同值待 IAM 确认）。IAM 提供校验或撤销事件后，把判定间隔收敛到 5 分钟，属 §11 未决项，不以配置项代替。

## 7. 事件与工具

| 宿主事件 | 用途 | 约束 |
|---|---|---|
| `agent/session-start` | 读模式设置、确认身份可用 | 失败只降级记忆能力，不阻断会话 |
| `agent/pre-step` | 按模式召回，注入为带来源的普通消息 | 记忆内容为可能过时的资料，不改变系统指令与工具权限 |
| `agent/turn-stopping` | 按模式写入；未配置状态不写入 | 超时或未知不重发；提交成功不等于派生完成 |

模式同时决定召回：`off` 停采集也停召回；`auto` 允许召回，条数受 `recall.maxItems` 约束；`unset` 不放行任何调用，先请员工选择。

**未配置状态的行为**：`unset` 不是“默认开启”，也不是“关闭”，而是尚未取得授权。在将要发生一次 Hindsight 调用（召回或写入）之前，插件提示员工二选一：自动记录或关闭。约束如下：

- **选择前零动作**：不召回、不采集、不持久化任何正文，本次调用直接跳过；提示本身不含记忆内容。
- **提示只给一次选择**：员工选定即写入该身份的设置，此后长期沿用，不再重复询问；选择结果在设置页可见并可随时更改。
- **提示未完成**：员工关闭提示而未选择，则本次会话内不再打扰，状态保持 `unset`；下一个会话的首个触发点再次提示。
- **不做第三个选项**：本档不提供“逐条确认”或“手动指定”，避免把授权问题变成每轮打断。

**与 REQ-005 的两处差异**：

- **模式集合**：REQ-005 §2 的“自动记录 / 确认后记录 / 手动记录”中，本设计去掉“确认后记录”与“手动记录”，改为“自动记录 / 关闭 / 未配置”。授权在首次触发时一次性取得；未取得授权即不采集、不召回。
- **控制粒度**：REQ-005 把“暂停采集”与“停止 Agent 召回”列为两个独立控制，本设计收敛为一次模式选择，员工无法“继续记录但不让 Agent 召回”。

两处差异均不属设计层可自行决断的范围，已列入 §11，由项目负责人在 REQ-005 升版时裁决；裁决前按单一模式实现，不额外引入独立召回开关与逐条确认。

| 工具 | 类型 | 说明 |
|---|---|---|
| `memory_search` / `memory_list` / `memory_read` | 读 | 按当前身份检索本人记忆；空、处理中、失败三态可区分 |
| `memory_delete` | 写（确认） | 返回 operation 状态；未确认不报“已删除” |
| `memory_status` | 读 | 查询异步操作状态 |
| `memory_mind_create` | 写 | 按员工给定的名称与问题创建心智模型；返回异步 `operation_id`，不等待完成 |
| `memory_mind_update` | 写 | 修改名称、问题或触发方式；不改已生成内容 |
| `memory_mind_delete` | 写（确认） | 删除心智模型及其内容；未确认不报“已删除” |

不复用上游 `hindsight_*` 前缀：那套是“项目知识页”语义，与本产品的“员工个人记忆”不同，混用会让模型误判作用域。

**心智模型不在记忆链路上**：它是已存记忆的后台加工产物，采集上报与召回都不读取它，也不因其存在改变时序或判定。三个 `memory_mind_*` 工具只在员工显式要求时调用，执行由 Hindsight 后端异步完成，插件不注入、不轮询、不把结果拼进上下文。授权沿用采集模式，不新增开关：`unset` 与 `off` 下调用返回未授权；`auto` 下可用。

**刷新默认关闭**：创建时不启用自动刷新——`trigger.refresh_after_consolidation` 置 `false`，不设 cron。刷新由运维侧在固定时间窗口调用后端刷新接口完成，插件不参与、不提供刷新或清空工具。这样加工只发生在人为选定的时段，不会在会话进行中触发模型调用。刷新失败的记录保留在后端，由运维按窗口重试；插件不因刷新状态改变召回或采集行为。

## 8. 上游复用与差异

静态核对基准：`coding-agents@0.8.7`（标签 `v1.2.1`）。决定“基于官方插件”之后的具体处置：

| # | 上游事实（位置） | 本模块处置 | 理由 |
|---|---|---|---|
| 1 | 按仓库解析 bank（`src/dsh.ts`、README#bank-resolution） | 推翻：bank 由 BFF 按已验证 `sub` 绑定 | MEM-AC-01 |
| 2 | 配置在 `~/.hindsight/coding-agent.json`，含服务地址与令牌 | 不读取：配置走 settings，令牌走 keychain + IAM | 令牌不落明文 |
| 3 | 默认云端、`npx` 安装、每日 `autoUpdate` | 禁用：企业 npm 精确版本，插件不联网自更新 | 供应链与数据边界 |
| 4 | 自动采集会话与 Git 历史（`src/core/config.ts`） | 收紧：仅对话文本，不导入 Git 与历史会话 | MEM-AC-02/08 |
| 5 | 注册 `hindsight_*` 页面套件（`src/core/page-tools`） | 改造：保留检索与注入思路，改为个人记忆语义并前置鉴权 | 产品语义不同 |
| 6 | 结构性类型、`inject = ["agents"]`、不依赖 dsh 包 | 直接采用 | 不锁宿主版本 |
| 7 | 事件名 `agent/session-start` / `pre-step` / `turn-stopping` | 待实测：目标 rc.3 是否同名同序、能否 await、卸载是否解绑 | 上游注释提及 `alpha.4+` 的 `snapshotEvents` 差异 |
| 8 | `RuntimeCore` 按 workspace root 缓存 | 改为按进程单例 + 身份代际失效 | MEM-AC-06 |

复用方式：精确依赖 `0.8.7`，只导入事件桥与工具核心（`RuntimeCore`、page tools），入口自写。理由：`resolveHostMemory()` 把 bank 与 client 绑定到工作区路径与本地配置文件，正是必须替换的部分；而 `RuntimeCore(client, bankId, cfg, harness, root)` 的签名允许传入自有 client 与服务端下发的 bankId。

## 9. 状态机与失败

| 组 | 状态 | 要求 |
|---|---|---|
| 采集 | `unset` / `auto` / `off` | 切换立即生效；`off` 不清除已有记忆；关→开不补发；`unset` 不产生任何读写 |
| 操作 | `accepted` → `processing` → `searchable` / `failed` / `unknown` | `unknown` 不重发、不显示成功 |
| 身份 | `ready` / `expired` / `switched` / `unavailable` | 任一变故立即停止记忆调用；旧结果按代际丢弃 |

失败一律 fail closed：BFF 不可达、令牌缺失、审计不可写、设置读不出，均拒绝相应操作。对用户静默：不弹窗、不横幅、不返回缓存；诊断只落非内容字段。

## 10. 测试矩阵

| 类别 | 用例 |
|---|---|
| 正向 | 同员工跨会话命中同一 bank；三档模式行为；`unset` 首次触发时提示二选一并按选择长期执行；召回注入带来源；删除后浏览与召回均不可见；心智模型创建返回异步状态且不改变召回结果 |
| 反向 | 伪造 `bank_id` 被拒；他人记忆不可读；无令牌/过期令牌拒绝，且身份缓存命中不放行过期 AT；`unset` 下零写入、零召回；同一实例换号不继承前一人的采集模式 |
| 并发 | 同一记忆并发删除；换号与在途请求交错；`turn-stopping` 与卸载交错 |
| 退出 | 卸载后事件解绑、工具不可见、无残留注册；profile 切换后旧实例作废 |
| 契约 | 错误码与四态映射；审计字段不含正文；`unset` 提示每个会话最多一次，选择后不再重复询问 |
