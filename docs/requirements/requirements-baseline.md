## 摘要（一页纸）

**做什么**：让 3 个部门的 800 名研发同事在自己电脑上用上企业版 DSH——模型走企业网关，代码能读能写，研发平台以只读查询为现有能力基线，全程可追溯；变更／Issue 驱动的受控研发需求已确认，见 §2.3，实际开放仍以权限、安全控制和技术验证为准。

**为什么做**：企业已有 IAM、AI 网关与自研 DevOps，但各自独立使用、没有统一入口；本方案把这些能力接进一个客户端，模型与代码都不出机构边界。

**不做什么**：多人共享实例、白标发行、自建模型、公网访问、执行生产变更、macOS 系统钥匙串与代码签名。

**给谁用**：开发、评审、发布、测试、运维、PMO、外包共 7 类角色；Windows 与银河麒麟各占一半。

**要多久**：前置验证 1 周（过 G0）、概念验证 4 周（过 G1）、试点工程准备 4 周（过 G2）+ 试点运行评估 6 周（过 G3）。总周期取决于企业 IAM、网关、DevOps 三个团队的配合时间，这三段等待不在平台组控制内。

**要什么投入**：平台组 2–3 名工程师为工程粗估，各团队投入和试点支持待认领；模型与网关沿用现有，但不能据此宣称零成本。ARM构建、内部源、签名/分发、监控与支持资源是否可复用，须在G0确认。

**怎么算成功**（试点运行 6 周后判定）：

| 看什么 | 目标 |
|---|---|
| 五项试点指标（首次登录、麒麟安装、周活跃、严重故障、使用意愿） | 目标值与口径的唯一真源见 §6.1；本摘要不复制 |

**最大的两个风险**：约 400 台银河麒麟的沙箱与安装；800 人对应 2–3 名工程师的支持比（约 1:300）。

**G0 尚需落实的外部事实与资源**：

1. 按实际支持人力确定 800 人的进场安排；两批各 400 人仍为建议。
2. 核验 §4.4 四条已确认数据约束的真实服务端落实情况。
3. 取得麒麟验证与企业依赖的实际资源及到位时间，不承诺未经证实的周期。
4. 白标不在一期范围；若用户改变范围，另评签名、发行和维护成本。
5. 本项目需求及范围变更由当前用户最终决定；企业资源与强制控制按真实规则落实，不另建项目需求审批链。

## 1. 结论

DSH 的产品目标是替代 Comet 与 oh-my-sdd 成为企业新一代智能研发工具，不替代 DevOps/Gitee。企业业务模型及受控写增量依据 2026-10-22 需求方澄清整理；当前无企业内网访问，既有工具使用文档不等于接口实测或跨团队批准。

本文把一期范围、使用人群、必须跑通的场景、22 条有效需求（REQ-11 已取消）与 5 项试点指标收敛成一份可判定基线，作为项目范围的唯一真源。它影响四类人：领导据此决定投入与去留，开发据此排期与验收，用户据此知道能做什么，安全据此评审数据边界。

相对初版主文档的四项裁定（试点扩至 3 部门 800 人、银河麒麟占 50% 并前置为准入项、用户自助安装为主、角色细分为 7 类）已在 V0.4 中完成回写。本版另按 §5.5 / ADR-11/13 同步插件来源、AIHUB 原生索引、自包含三目标首版与轻量边界，并联动[总体架构设计](<../architecture/platform-architecture.md>)及[推广实施方案](<../plans/rollout-plan.md>)；上述人群、终端与角色输入不变。企业接口与终端能力仍待团队确认及实测，文档口径一致不等于技术验证完成。

仍缺三个部门的实际名单与联络口径、五项硬依赖的到位时间及真实试点证据。本项目需求及交付由当前用户确认；企业试点若另有强制签署规则，由 Agent 核验，不据此替本项目新增审批人。

## 2. 范围边界（唯一真源）

一句话：一期做 Windows、银河麒麟与 macOS 三端、每人一套；模型与工具都走企业现有系统；共享实例、白标、自建模型、macOS 代码签名一律不做。

本节为项目范围的唯一真源；其他文档直接引用本节，不另写独立清单。

### 2.1 一期范围

| # | 范围 | 边界说明 |
|---|---|---|
| S1 | Windows 桌面 App | 官方 DSH 宿主与企业插件轻量集成；自助或受管理安装，每人一套；具体方式待核验 |
| S2 | 银河麒麟本机 Web | `dsh --profile web`（仅绑定 `127.0.0.1`）+ `dsh-web-open` + 浏览器，仅本机自用，不对他人开放 |
| S3 | 统一身份 | IAM 统一登录；个人模型访问对应当前真实用户并限 DSH；应用 Agent 受控开通，边界见 §2.4 / §4.6；DevOps/Gitee CLI 按其服务端支持的用户凭据与权限鉴权 |
| S4 | 模型与额度 | 企业 AI 网关执行模型授权与团队/成员预算；个人访问采用路线 B 双因子凭据协同，个人长效凭据与 IAM 身份令牌须同时满足；客户端不持上游模型密钥 |
| S5 | 工程系统工具 | 复用 DevOps 与 Gitee 现有 CLI；支持变更／Issue 双入口，核实本 Issue 的唯一变更、唯一仓库和验收，以故事作背景。研发受控写需求已确认，实际开放仍须开关、权限、安全策略及接口证据，默认关闭；结构化输出、凭据和双端可用性由 Agent 核验。只有 CLI 无法满足已确认的必要能力时，才评估最小适配 |
| S6 | 分发与治理 | AI 开发者平台（AIHUB）维护并托管 format-1 索引，提供只读 URL；用户通过 DSH 原生「插件市场 → 索引源」添加后浏览，官方 manager 按精确版本从企业 npm 安装。企业私有 npm 为唯一 npm 制品源；企业私版另可通过内部文件交付，终端不连接公网；索引首版只放自包含、三目标通用稳定版。本项目只做索引契约、只读校验与验收，不建设生成器、当前授权、租约或 CI 发布链路 |
| S7 | 策略与审计 | 工具调用前的门禁（放行 / 询问 / 拒绝）、`$DSH_HOME` 硬拒绝保护与决策审计 |
| S8 | Issue 研发交付 | Skill 提供企业语义，Teamflow 唯一执行；充分 Issue 不另写规格，设计按需；以实际版本的本地验证、独立 AI 审查与用户验收形成可核对交付，SDD 退出默认并按盘点退役，边界见 §2.3 |
| S9 | macOS 桌面 App | 官方 App + 自助安装；凭据使用 SQLite 值级 AES-256-GCM 加密，密钥文件为 0600，不使用系统钥匙串、不要求代码签名与图形会话；安全边界为用户级隔离，同账户进程可读取密钥 |

### 2.3 Issue 交付模型与受控研发目标（需求已确认）

**对象与信息边界**：系统变更组织业务目标、总体范围和约束，不再强绑唯一代码仓库；Issue 承载具体工作范围、非目标、约束、依赖和可执行验收。一个 Issue 可有续跑、返工等多次 run，run 不成为业务真源。澄清按信息归属写回变更或 Issue，仍需真实授权和版本检查；不在聊天或内部 PRD 中另立业务真源。需求、代码或验收版本改变后，重新判断旧方案、验证和人工确认的覆盖。

**交付与业务结束**：各 Issue 独立交付并不代表没有依赖；未满足的依赖列为未验或阻塞，不用模拟结果代替联调。只有本地证据时可交付待验收候选，不冒充 CI 通过、已合入或业务完成。用户验收不自动授权合并、发布或关闭；平台规定额外条件时按真实规则执行。单个 Issue 或全部 run 完成不导致系统变更最终结束，Agent 不调用旧 `dop change done` 代替业务判断。

**SDD 处置方向**：`forge-sdd` 退出默认交付要求，以退役独立组件为目标；Agent 先盘点 CLI、组合包、测试和其他调用，再处理未使用部分。只保留有明确用途的最小能力，不为已有代码创造冻结需求；不把 spec／freeze／archive 齐套作为开工或验收前提。2026-11-03 后续授权已按方案 A 执行全量退役：`packages/forge-sdd` 删除，企业组合依赖与 bin 移除；已安装 profile／已发布制品不动，外部 caller 未取证。

**保持不做**：自动合并、代替业务验收、生产部署／回滚／审批、最终结项管理、跨系统 Agent 调度、通用修复循环引擎。CI 触发及生产状态读取若另有必要，由用户决定是否扩展范围，并先核验权限及运行条件；六阶段地图不自动增加一期能力。

### 2.4 模型访问与应用 Agent 边界

个人研发统一通过 DSH。DSH 内由人操作的交互式 Agent 属个人访问；无人值守应用 Agent 属网关受控例外，按应用和环境开通并保留责任归属。应用凭证不能变成个人绕过 DSH 的通用入口。

本项目只对接网关现有或获准补齐的授权及管理能力，不建设应用 Agent 执行框架、机器身份平台、凭证管理后台或自动轮换服务。关键能力不足时不开放对应路径；不因此自动批准 N7 的核心改动。个人访问采用路线 B（长效个人凭据 + 实时 IAM 身份令牌双因子协同），能力未齐阶段按[网关契约 §4.1.2](../contracts/gateway-contract.md#412-阶段能力矩阵)的判据执行，不退回只验静态 Key。

## 4. 核心场景

### 4.1 场景总览

| S1 | 首次登录与激活 | 第一次打开 | 完成登录与网关授权准备后 30 秒内完成一次对话；未登录或必要授权未就绪时企业模型不可用 | 浏览器未拉起、回调端口不通、用户取消授权、网关未开通；需 Key 路线另含录入错误 | A1、A2、A3 |

### 4.2 用户会经历什么

**第一天。** 自己装好（或由 IT 推送），打开后使用公司账号登录；网关完成必要开通后才能提问。按提示到控制台创建并录入个人 Key，完成双因子授权准备。登录与授权准备完成后，目标是 30 秒内完成第一次对话；首次开通总时长另测。没有有效授权时不提供替代模型。

**平时。** 像现在一样打开项目目录，让它读代码、改代码、跑测试；问它“上次构建为什么失败”；让它查研发平台里的用户故事与工程信息。它的能力清单在会话里可见，不用记命令。

**出问题时。** 额度用完展示恢复信息；不能区分具体额度时引导到网关控制台，不换模型。按错误类别区分登录失效、凭证无效、未授权、用途或网络限制；不把所有 401 都当成需要重建 Key，也不盲目刷新或重放。

### 4.3 两条不能失败的路径

**S1 首次登录**：未登录时企业模型不可用 → 企业 IAM 登录 → 完成身份校验 → 网关检查人员开通与模型授权 → 按选定路线准备必要凭证 → 首次对话。登录失败与模型未授权分开提示；个人 Key 如保留，必须归属当前人。任一步失败不得回落到公网或只验 Key。

**S7 异常自助**：预算耗尽不自动重试；限流按已确认退避规则处理。身份失效、凭证错误、未授权及依赖故障分别提示。令牌续期遵循已核验契约；只有能确认请求未执行时才评估安全重试，已输出或结果未知不自动重放。

### 4.4 数据与合规约束

试点允许客户与生产数据进入 DSH 上下文，以下四条作为硬约束：

| # | 约束 | 通俗说 | 落点 |
|---|---|---|---|
| C1 | 客户数据只经企业 AI 网关与机构自部署模型，不出机构边界 | 数据不出公司 | 架构 §7.2 / §10、[AI 网关契约](../contracts/gateway-contract.md) §4.5 |
| C2 | 会话正文默认不进安全事件平台，保留期单独评审 | 聊天内容不留档，要留先评审 | 架构 §7.6 |
| C3 | 客户数据的导出、外发、批量复制需本机人工确认（`ask`） | 往外搬数据要问你 | 架构 §7.6 / §9（`@heluo/forge-policy`） |
| C4 | 河洛两类模型访问均须关闭正文日志，并抽验网关与模型日志不含请求/响应正文；网关生产环境默认关闭业务正文日志、业务正文零留存；排障采样另评 | 服务端要关闭正文日志；产品默认不是关闭，开通/更换时必须核对 | [AI 网关契约](../contracts/gateway-contract.md) §4.5 |

### 4.5 未纳入的场景

- 多人协作同一会话（依赖多租户，见 N1）。
- 跨终端迁移会话与工作区（一期不做）。
- macOS 的系统钥匙串与代码签名路径（见 N2；macOS 本机使用本身在一期范围内，见 S9）。
- 执行生产环境变更（部署、回滚与变更审批，见 N9）。

### 5.3 追踪约定

- `REQ-*` 是唯一需求编号；验收项与工作分解项只在这里引用，不在其他文档另起编号。
- 需求删除不删编号，标“已取消”并写明替代项；REQ-11 按此处理。
- 一条需求对应多条验收时，全部通过才算达标。
- §2.3 的需求、四项取舍与有限任务委托目标已由当前用户确认；Agent 核验 C3 动作分类、真实服务端权限、可信确认与审计映射，未验不开放相应写，目标确认不是 C3 豁免，也不另设平台／安全／PMO 需求批准链。
- 本机确认是 C3 风险动作的必要条件；approval policy为`never`、无确认UI、超时/异常均拒绝，不能把“不询问”解释为自动允许。
- 工具描述/preset不是服务端授权依据，本机管理员可修改客户端；企业服务端独立鉴权与撤权必须成立。对文件及命令子进程的秘密隔离，两端都要实测，未通过不开放相应工具。
- 可选插件可隔离不等于强制安全依赖可绕过；IAM/policy/必要审计缺失时拒绝相应操作。

### 5.4 核心补丁为条件项

REQ-12 保留编号以追踪原方案，但当前属于条件需求，不是 DevOps/Gitee CLI 接入的核心补丁授权。只有其他集成经批准采用 MCP，且其身份或凭据生命周期无法通过现有能力满足时，才核定 `dsh-mcp-client` 改动、工作量、独立验收与上游提案；在此之前不发布带补丁的客户端，也不把历史 50–80 行估算计入当前基线。DevOps/Gitee CLI 形态及其待核验前提见 DESIGN-009、DESIGN-010。

### 5.5 插件制品来源决策

2026-10-21 用户已确认[ADR-11](<../architecture/plugin-registry-source-decision.md>)：企业私有 npm 统一承载公网同步包和内部定制包；固定 Gitee group 只约束内部定制源码，不要求公网包先迁入 Gitee。终端不直连公网，企业仓库缺包或上游不可达不能自动转向公网或 Gitee 归档；企业私版可通过经授权的内部文件路径交付；内部 scope 不得代理到公网同名包。

用户另确认首版只收自包含、Windows 10 amd64／统信 UOS 20 amd64／银河麒麟 aarch64 三目标通用的稳定版；普通带依赖或单平台包不是 DSH 非法，只是不进首版索引。2026-10-21 进一步决定采用原生索引轻量模式（ADR-13）：AIHUB 维护并托管 format-1 索引，用户通过原生「索引源」添加只读 URL，官方 manager 安装精确版本；不再建设生成器、`current/policy/evidence`、CI 单写发布、15 分钟租约或写前授权。正式技术方案仍保留审核/批准待定；企业接入与三目标安装必须通过 G1/G2，其他一期范围、人群、指标及 A/REQ 编号不变。

2026-10-21 用户进一步裁决平台边界：企业可用插件由外部“AI 开发者平台”（AIHUB）完成预创建、Gitee 指定 group 建仓、审查、发布 npm，并维护/托管 format-1 索引 JSON；本项目不承建其后台、生成器或审批系统，只定义索引契约、提供只读校验器并做三目标验收。客户端直接用原生「插件市场 → 索引源」添加 AIHUB 的只读 URL，不要求内置自定义市场插件。自研/内部插件的中英文名称、描述、图标及真实 tarball 由平台负责人验收。终端目标为 Win10 amd64、统信 UOS 20 amd64 与银河麒麟 aarch64 三目标并存，UOS 与麒麟不互相替代，试点人群与终端比例口径不变；企业私服入口仅存本地配置并在打包时内置，允许内网 HTTP（已批准例外）。

## 6. 成功指标

一句话：6 周试点运行后看 5 个数。登录成功率不过关就没得谈，其余可以修补。

### 6.1 指标定义

| # | 指标 | 怎么算 | 目标 | 数据来源 |
|---|---|---|---|---|
| M1 | 首次登录与激活成功率 | 触发登录的人里，24 小时内完成网关授权准备并完成一次成功对话的比例 | ≥ 95% | IAM 登录日志 + 网关授权/首调用记录 |
| M2 | 麒麟安装成功率 | 执行安装的麒麟设备里，24 小时内完成一次成功对话的比例 | ≥ 90% | 安装脚本回执 + 首调用；失败样本注明原因 |
| M3 | 周活（第 4 周 / 第 6 周） | 单周内至少 1 次成功对话的人数 ÷ 已进场试点人数 | ≥ 60%（全量时 480 人） | 网关按人去重 |
| M5 | 严重故障次数 | 单次导致 ≥30% 试点用户连续 >2 小时不可用 | ≤ 2 起/月 | 工单系统 + 值班记录 |
| M6 | 愿意继续用 | 试点末问卷中“收回 DSH 会主动申请继续用”的同意比例 | ≥ 70% | 匿名问卷，有效回收率 ≥50% |

> M4（写操作审计覆盖率）随生产变更场景撤销；M5 / M6 编号保留，不重排。

M1 包含网关必要授权准备：登录成功但未完成路线 B 的双因子授权开通的不计激活。按稳定人员映射去重（AS-3 待确认），M2 使用同一成功对话定义。

M3 是试点中期的检查点：第 4 周不达标即启动干预（增补指引、缩小部门、延长时间），最终判定沿用第 6 周最后一周的周活，目标同为 ≥60%。两个时点用同一口径，不重复计数。

分两批各400人仍为待用户决定的组织建议，不改变总规模与上述目标值；Agent 先核实人员、资源和实际进场条件，不把目标企业 PMO 当成本项目批准人。G0须明确运行起点、各批进场时点、已进场分母和第4/6周观察的可比性；按批记录起点、分别展示批次结果是[实施方案](../plans/rollout-plan.md)提出的待确认方法，不是已新增指标规则。若末批观察不足，不能以先行批次结果代替全体证据，也不能宣称第15周必然通过G3；须由用户确认补足观察窗口并回写排期。

### 6.2 判定规则

| 结果 | 条件 | 处置 |
|---|---|---|
| 通过（过 G3） | 观察窗口与证据完整，5 项全达标 | 由当前用户依据实际证据决定进入 P3；真实企业准入强制条件另行核验，不虚构代签 |
| 有条件通过（尚未过 G3） | M1 有完整证据且达标，其余 1–2 项未达标 | 停止扩量，制定责任明确的整改计划；由当前用户决定延长 2 周或缩至单部门复测，复测达标后再确认 G3；Agent 不代写验收结论 |
| 不通过 | M1 未达标，或 M1 达标但其余 3–4 项未达标 | 停止扩量，回到对应验证阶段修复；不得把未覆盖组合默认为通过 |
| 不予判定 | 观察窗口不足、任一指标数据缺失/口径未冻结，无法证明达标 | 暂停 G3，先补证据和窗口；缺数不记为达标，重排需留痕，不以问卷/口头反馈替代调用与审计证据 |

### 6.3 采集与隐私

最小必要审计与 C1–C4 的控制须在 G2 前验证；REQ-16/A13 的 P1 优先级表示 G3 完成全量完整性评估，**不是允许试点期无审计或保留正文**。普通模型问答按稳定主体与调用关联，有研发变更时才关联 change-id，不为普通问答伪造变更编号。

- 客户端只上报事件（登录成功 / 失败、安装成功 / 失败、调用成功 / 失败），**不上报内容**，与 §4.4 C2 一致。
- M1 的“成功对话”以网关侧收到并返回成功为准，不用客户端自报，避免两套账。
- M3 的“独立用户”按人去重；一人多设备只计一次。
- 故障次数以工单为唯一口径，口头反馈不计入。

### 6.4 不作为成功判据的观察项

调用总量、令牌总量、装机数、人均日用量只进周报观察，不参与试点成败判定。这些数只能证明“装了、跑了”，不能证明“有人用、值得用”。不另设项目成功指标中的成本阈值，**不等于取消网关团队/成员预算或业务预算**；异常消耗由网关控制与周报共同暴露，再按已确认预算责任人工处置。

### 6.5 企业研发过程观察指标

[全流程能力设计](../design/plugins/forge-devops-lifecycle.md) §9 定义观察目录，[事件契约](../contracts/metrics-events.md)定义客户端补充事件。DevOps 汇聚已有仓库、CI/CD 和客户端缺口数据，不另建指标平台；平台已有事实不由客户端重复采集。仅作改进观察，不用于个人排名、绩效评估或 G3 去留，不改变 M1–M6（M4 已取消）的口径、目标与责任。

字段采用允许清单，禁止需求正文、提示词、代码、diff、工具输出及其内容哈希。必要安全审计与可降级指标投影分别处理。缺失、重复、迟到、失败和离线均显式计量，未知不补零；Agent 核验保留期、采集主体、出口、权限及企业强制规则，证据不足不启用。改作判定用途需当前用户另行确认并冻结口径，不引入 PMO 替本项目审批的链。

## 附录 C 试点用户须知

**你会得到什么**：一个能读你项目、改代码、查研发平台信息的助手；模型走公司网关，不需要你申请任何外部账号。

**怎么装**：Windows 按安装包指引完成；银河麒麟从内部软件源安装并打开。用公司账号登录，按路线 B 完成网关授权准备，到控制台创建自己的 Key 并录入。正式操作指引待联调后冻结，开通总时长另测。

**能做什么**：读代码与文档、改代码并跑测试、查询研发平台的只读信息（用户故事、流水线与构建信息以接入工具为准）、按规范做评审、调用公司内部技能。

**不能做什么**：不能多人共用一个实例；不能从公网直接安装插件；经企业私有 npm 同步且获批的公网插件可按角色使用；不能把客户数据贴到公司以外的工具里；不能执行生产环境变更；不能替代人工代码评审的最终判断。

**出问题时找谁**：试点支持渠道在试点开始前公布。额度问题会显示恢复时间；凭据问题按提示到 UAG 控制台核查或重建；只有登录过期才点“重新登录”。

**关于数据**：审计记录的是“谁在什么时候调用了什么工具、做了什么决定”，不记录对话正文；对话内容默认不进安全事件平台；河洛两类模型访问均需关闭正文日志；生产默认关闭业务正文日志、业务正文零留存，开通/更换时抽验。
