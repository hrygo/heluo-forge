## 1. 目标与依据

用户已选择严格保护：没有核验过覆盖 Key 与元数据的原子能力时，保存和清除均拒绝；旧格式保持只读，不自动迁移。默认组合的网关录入也可因此不可用。用户的工程策略选择不等于企业团队批准生产后端或数据迁移。

实施依据是 [IAM 模块设计](<../design/plugins/forge-iam.md>)与[验收清单](<../design/README.md#221-iam-离线验收清单>)。当前 `credentials` SDK 只声明单引用操作和单记录 `modifyRecord`，不声明跨两类键的联合事务。现有分步保存失败补偿、迟到清理和空状态 ABA 不能据此得到安全保证。

## 2. 技术边界

- 使用既有 Node ESM、Node 24.21.0 和 `node:test`；不新增依赖、不改 credentials 包或 DSH 核心。
- 联合能力是 IAM 工厂的私有依赖注入，不是已有 Host Service 方法，不是配置字段，也不注册成 Agent 工具。
- 默认不注入能力。getter 与独立 verifier 必须同步，verifier 仅字面 `true` 放行；grant 的单记录 verifier 不可复用。
- 能力提供联合存储快照与完整快照条件提交。禁止用带环境回落的解析结果构造存储快照，禁止嵌套 `modifyRecord` 与引用操作冒充事务。
- guard 在比较成功之后、联合提交之前同步执行。失败、异常、Promise 不得写入；每次提交前重查具体 provider、adapter、专用证明及本地生命周期。
- 新格式使用独立写入代际；清除产生独立代际墓碑，而非物理删记录。旧格式、orphan、未知格式和不一致 pair 不自动修复。
- CAS 预期快照不更新、不自动重试。提交异常或无法核对的回执报告未知，不补偿、不回滚、不通过读取后续状态猜测此前提交。
- 仅模拟 one-turn 联合提交；不据此宣称生产耐久事务、跨进程即时 IAM 授权、OS 物理擦除或旧客户端混用安全。

## 3. 可独立核验的步骤

### 任务 A：默认拒绝与旧记录保护

- [x] 检查实际 SDK 与后端，确认无可直接采用的联合事务。
- [x] 新增默认、描述符、单记录证明、异步或异常证明的零变更负测。
- [x] 执行负测，确认旧实现缺少门禁，而非测试夹具报错。
- [x] 实现独立联合能力准入与旧格式只读；旧读取不写代际。

### 任务 B：受控联合路径

- [x] 为明确注入的精确 fixture 实现联合快照、全量 CAS、同步 guard 和回执语义。
- [x] 通过独立写入代际及清除墓碑防止旧快照覆盖新保存或新空状态。
- [x] 验证 guard 拒绝、身份失效、旧格式、不一致 pair、提交前失败与提交后未知均不触发分步补偿。
- [x] 保留按 provider、缓存、退出和 issuer 的既有测试，不把只读 seed 全局升级为可信能力。
- [x] 隔离 CAS 参数与私有原始意图；guard 阻止可见参数改写，回执不能通过别名重定义成功，返回元数据与 adapter 参数分离。

### 任务 C：集成、文档与独立审查

- [x] 向管理 API 和账户页提供固定错误语义，不能把未知当成功。
- [x] 同步用户与开发指南、模块设计和验收清单中的默认不可写、旧记录只读及未验边界。
- [x] 独立审查最终差异；必要问题已复测关闭，定向测试通过。
- [x] 完整仓库检查覆盖当前参数意图与模型未知结果回归并通过；真实 macOS keychain spike 显式关闭。

## 4. 文件职责与交付判断

[存储适配](<../../packages/forge-iam/src/store.mjs>)负责联合能力准入与数据代际；[IAM 服务](<../../packages/forge-iam/src/service.mjs>)负责本地生命周期与 provider 绑定；管理路由和 Client 只转换错误与展示。测试夹具只模拟明确注入的能力，不参与产品配置。

交付要求是实际业务路径及正负用例通过、旧数据不被迁移、指南描述当前行为。全仓检查显式关闭真实 macOS keychain spike；未安装到当前 profile、未提交、未发布，不以模拟结果代替企业或双端验证。
