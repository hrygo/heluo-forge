## 1　终版结论

2027 终版是 2027-12-31 可复现的运行状态，不是“所有能力都开”。它由五个“已开放”和五个“未开放”共同定义：已开放人的登录、模型调用、只读工具、受控写、智能体单场景；未开放无数据支撑的三重交权、未许可的 AIGS 生产、未证实的五分钟、未支持的 PKCE、未通过的写操作。

终版与 2026Q4 的 V1 共用同一组接口：身份、凭据、模型、策略、工具、审计。2027 年替换的是每层的实现，不是插件契约；V1 的插件、工具元数据和审计字段保留。

> **一句话**　终版不是“安全能力全部达标”，而是“每项开放能力都有证据，每项未达标能力都有边界和替代”。

### 1.1　终版必须成立的三件事

- **人的身份**：IAM 6.3 完成升级；登录、刷新、退出在 Windows 与银河麒麟上可复现；PKCE 只有厂商书面确认后才打开。
- **模型访问**：一人一凭据；网关若支持令牌+Key 则切换，否则保持 Key-only 并保留 UA/IP/privacy_mode/90 天轮换。
- **工具治理**：只读与受控写分级；审批、回查、审计可查；AIGS 只覆盖工具调用，不进入人的登录链路。

### 1.2　终版不承诺

终版不承诺“三重交权全量落地”。三重交权需要业务系统实时权限数据；取不到时，最终权限退化为“智能体能力上限 ∩ 策略范围”，审计标注 `degraded=true`。终版不承诺“五分钟停用”在所有网关节点成立；实测超过五分钟，就把该能力标为未达标，限制高风险用途，而不是改口径。终版不承诺“AIGS 生产全覆盖”；AIGS 只覆盖工具调用，人的登录、模型 Key、DevOps/Gitee 仍由各自服务端负责。终版不承诺“PKCE 已支持”；只有 IAM 书面确认并通过回归，才把 `authMode=pkce` 打开。

## 2　终版能力矩阵

下表是终版的“能力—条件—不成立时”的对应关系。条件不成立时，不是降级为无控制，而是保留 V1 的替代路径，并在审计中标注能力状态。

**表 1　终版能力与条件**

| 能力 | 2027 终版目标 | 成立条件 | 不成立时 |
| --- | --- | --- | --- |
| 人的登录 | IAM 6.3；机密客户端为主；PKCE 若可用则灰度 | 6.3 升级完成；回调/claims 回归通过 | 保持机密客户端；不写 PKCE |
| 会话退出 | RP 登出可用则调用；否则本地清空 + 浏览器 SSO 登出 | 6.3 的 14 项实测 | 保留兜底；不宣称全局登出 |
| 模型访问 | 网关 Key+Token 或 Key-only；一人一凭据 | 网关生产版本确认 | Key-only + UA/IP + 90 天轮换 |
| 工具 | 只读 + L1/L2 受控写；审批台账与回查 | 策略/审批/审计通过 | 仅只读；写操作关闭 |
| 智能体 | AIGS 单场景扩到 2—3 个工具；双标识/委派/CIBA | AIGS 许可/部署；SCIM 或目录桥接 | 停在 POC；V1 不受影响 |
| 审计 | jti 全链；本地 + SIEM | 字段对齐；保留期批准 | 本地审计 + 导出 |

## 3　终版架构

**表 3　终版分层**

| 层 | 2027 终版实现 | 与 V1 的关系 |
| --- | --- | --- |
| 身份 | IAM 6.3（人）+ AIGS（智能体）；同一实名口径 | V1 的 IAM 插件保留；新增 AIGS 适配，不换登录入口 |
| 凭据 | 钥匙串（人/客户端）+ AIGS 凭证保险箱（智能体） | 同一 CredentialProvider 接口，新增后端 |
| 模型 | AI 网关模型路由；MCP 走 AIGS 网关 | V1 的 provider 配置保留；新增 MCP 路由 |
| 策略 | 本地 policy + AIGS PDP；PEP 在网关/SDK | V1 规则保留为第二道闸 |
| 工具 | DevOps/Gitee/SDD + MCP 工具；风险分级 | V1 工具描述字段只增不减 |
| 审计 | 本地事件 + SIEM + AIGS 决策日志 | V1 的 actor/jti/decision_id 继续使用 |

### 3.1　三条主链

**人的登录**：系统浏览器 → IAM 6.3 授权端点 → 回环回调 → 换 token → 校验 claims → 钥匙串。AIGS 不改变员工登录路径。

**模型调用**：DSH 从钥匙串取本人凭据 → 网关校验 Key/令牌、模型、预算、IP → 私有模型。若网关支持令牌+Key，则同时校验当前人；否则以一人一 Key、UA、IP、审计兜底。

**工具调用**：模型发起工具调用 → 本地策略或 AIGS PDP 判定 → 只读放行或转人工确认 → DevOps/Gitee/MCP 执行 → 审计事件。策略拒绝时适配器零调用；子 Agent 继承同一策略。

### 3.2　演进缝

**表 4　演进缝**

| 演进缝 | V1 实现 | 2027 实现 | 兼容规则 |
| --- | --- | --- | --- |
| 认证模式 | confidential | confidential / pkce / aigs | 配置项 authMode；同一回调路径 |
| 令牌来源 | staticKey | key+token / delegated | TokenSource 接口；不改变调用方 |
| 策略 | 本地 policy | 本地 + AIGS PDP | decision 结构 allow/deny/approval + obligations |
| 工具描述 | risk/resource/action | 同左 + agentScope | 字段只增不减；旧字段保留 |
| 审计 | actor/jti/decision_id | 同左 + agent_id/on_behalf_of | V1 写空值，2027 填值；查询兼容 |
| 分发 | enterprise bundle | bundle + 原生市场 | 包名与配置 schema 不变；只升版本 |

## 4　终版验收与运营

终版必须能运营：版本可锁、配置可回滚、密钥可轮换、审计可查询、故障可降级、容量有基线。运营指标至少包括：登录成功率、刷新失败率、模型 401/429/5xx、工具拒绝率、审批时长、Key 轮换到期数、AIGS 决策拒绝率、jti 缺失率。

**表 5　终版验收指标**

| 阶段 | 指标 | 目标 | 数据来源 | 停止规则 |
| --- | --- | --- | --- | --- |
| P1 | 登录成功率 | ≥99% | 客户端 + IAM 日志 | <98% 不回 800 |
| P1 | 刷新成功率 | ≥99.5% | 客户端 + IAM | <99% 排查 |
| P1 | 撤权实测 | 记录最坏值 | 管理台 + 网关 | >5 分钟限高风险 |
| P1 | 银河麒麟通过率 | 100% 试点机 | 实机清单 | 不过不扩量 |
| P2 | MCP 工具回放 | 100% 带 jti | AIGS/网关审计 | 缺失即停 |
| P2 | 匿名智能体 | 0 | 注册审计 | 发现即停 |
| P3 | 开放能力证据 | 100% | 证据矩阵 | 无证据不开放 |

## 5　2027 行动节奏

### 5.1　2027Q1：IAM 6.3 与 800 人

- 升级 IAM 6.3；先做五项回归，不直接扩量。
- 08 仍不支持则继续机密客户端；14/19 只部分支持则保留兜底，不设 800 人前置。
- 网关若提供令牌+Key，做 A/B 对比；否则保持 Key-only 并记录未达标。
- 扩到 800 人；Windows 与银河麒麟各半；完成回滚与撤权演练。

### 5.2　2027Q2：AIGS 单场景

- 选一个低风险、只读、单工具场景；验证注册、双标识、audience、PDP 求交、CIBA、审计回放六项。
- 六项全过才扩第二个工具；不过，AIGS 停在 POC，不影响 V1。
- SCIM 不成立时只做工具治理，不做人员/组织联动。

### 5.3　2027H2：终版收敛

- 工具从只读扩到 L1/L2 受控写；高风险写操作另立范围变更。
- AIGS 扩到 2—3 个工具；三重交权只在有业务权限数据时启用。
- SIEM、容量基线、演练、运营指标齐备；开放能力逐项有证据。
