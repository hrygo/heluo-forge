## 1. 目标与"完成"的口径

目标：给 IAM 相关的六个开放 issue 排出可执行顺序，并把**仓库内能做完的部分做完**；依赖真实硬件或企业接口的部分，写清依赖方、所需证据与当前阻碍。

三类结论，每项只取其一：

| 标记 | 含义 |
|---|---|
| PASS | 有本仓库可复现的证据（用例、配置检查、源码路径） |
| BLOCKED | 依赖企业接口、实机或授权，当前无法取得证据 |
| NOT RUN | 排期未开始 |

mock、纯判定函数、文档描述都不算 PASS；这类结果只能写成 NOT RUN 或“隔离模拟”。

## 3. 依赖与顺序

```
#125 凭据唯一且失败可见
  └─→ #121 真实后端与 secret 生命周期
        └─→ #122 宿主接线与执行入口拦截
              └─→ #120 跨进程失效与服务端撤销验证
                    └─→ #123 双端验收（发布门禁）
#124 汇总以上，最后收口
```

顺序理由：凭据是其余验证的地基，明文兜底仍在时，#121 以后的“实测”都没有意义；#122 接线之后 #120 才有宿主侧的失效通道；#123 必须等前四项都有证据，否则重复取证。

## 4. 工作分解

### M1：#125 单 provider 与失败可见

1. 组合级测试：用真实 Cordis 组合（不是 mock ctx）断言只有 keychain 提供 `credentials`，且 keychain 不可用时组合里没有第二个凭据来源；覆盖 keychain 先挂载与被 local 抢先两种顺序。
2. 开发覆盖层：文档化“禁用 local + `filePath` + `allowInsecureFile`”，标注非生产，并在 README 与包说明里同源。
3. 错误可见性：keychain 不可用时启动日志能读到原因与下一步动作，而不是只有 `did not activate` 计数。
4. 反向验证：测试在修复前失败、修复后通过，至少对第 1 项留一次反证记录。

### M2：#122 宿主能力核验与执行入口

1. 用 Inspect 核验目标 DSH 的 Remote/watch、连接鉴权、请求取消与卸载能力，逐项记 PASS/BLOCKED。
2. Host 侧注册只读状态订阅，Client 只收非敏感投影；令牌不进 RPC（#132 的 `getSession()` 已保证无令牌，作为既有证据引用）。
3. 模型与工具的真实执行入口接入门禁：未登录、缺凭据、IAM 被禁用、未授权四种情况都被拒；纯判定函数不算完成。
4. 官方四行禁用与独占断言在真实入口复验。

### M3：#120 跨进程失效

1. 双进程用例：共享文件后端，A 进程退出后 B 进程的新调用必须被拒（`resolveToken` 与模型调用入口两处）。
2. 本地清理、远端撤销、未验证三态在视图与文档里分开表述。
3. 服务端撤销与五分钟窗口记 BLOCKED，附 IAM 答复依据。

### M4：#121 生命周期与配置

1. 决策记录：首次受控下发、分发、轮换、吊销、异常更新的责任人与周期；人工轮换、两分钟生效、旧访问令牌不随轮换作废。
2. 配置校验：未获准使用 0600 明文时拒绝启动该 provider；获准时只显式开启。
3. 两平台后端与实机取证记 BLOCKED。

### M5：#123 双端验收

1. 环境登记表与用例矩阵骨架（PASS/FAIL/BLOCKED/NOT RUN 四列）。
2. 实机执行记 BLOCKED，写明所需机器与账号权限。

### M6：#124 收口

按 M1—M5 的证据汇总 AC1—AC9，逐项给结论；未通过的写责任方与替代处理。

## 5. 阻塞与风险

| 风险 | 影响 | 处理 |
|---|---|---|
| 无 Windows / 麒麟实机 | #121、#123 无法 PASS | 记 BLOCKED，保留可执行脚本与矩阵，机器到位即可跑 |
| IAM 无单令牌撤销接口 | #120 的“只断当前授权”不可实现 | 记 BLOCKED，不默认调用全局登出 |
| 网关侧证据缺失 | 五分钟窗口与计费语义无结论 | 引用 #120 的联合记录要求，不自行推断 |
| 宿主能力未核验 | #122 的入口拦截可能无法接线 | 先核验再实施，缺什么记 BLOCKED，不改内核 |

## 6. 完成判定

- 每个 issue 的仓库内工作项有对应用例或配置检查，且在本机 `pnpm check` 中通过。
- BLOCKED 项写明依赖方、所需证据与当前阻碍；不以 mock 或文档替代。
- 设计、契约、登记与 issue 状态一致；issue 关闭前把结论回写正文。
