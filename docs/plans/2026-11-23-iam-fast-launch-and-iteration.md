## 1. 结论

- 能力基线固定为 IAM 6.0.3 反馈后，登录路径没有悬而未决的设计选择：**机密客户端 + PKCE S256 + 不透明令牌 + 按访问令牌撤销**，四项都有书面依据。
- 真正阻塞登录的只剩部署侧的登记与预置（客户端、密钥、端点、回调）。**S256 是否被接受已由 IAM 于 2026-11-23 答复为可用**（省略 `code_challenge_method` 才退化为 `plain`），只剩我方一次真实往返留证，不需要设计降级。
- 网关侧没有第二条在线判权手段：令牌不透明、无标准内省端点，因此判权只能依赖“有效性回查接口 + 短 TTL + 事件通道”。回查接口本身尚未确认，是 R1 的关键外部依赖。
- 代码改动共 5 项：3 项配置化或新增（网关身份头、UserInfo 字段映射、环境旁路检测）、1 项覆盖面补齐（独占断言）、1 项实测留证（PKCE S256）；另有 1 项私版模板收敛。除 PKCE 实测外都不改变协议语义。
- 迭代分四段：R0 让目标人能登录并调用模型；R1 把可容忍风险落成 SOP；R2 需 IAM 版本升级立项；R3 需 AIGS 上线。后两段不在本计划承诺范围，也不作为前两段的设计前提。

## 2. 能力基线（6.0.3 反馈）与对本计划的影响

完整能力表与依据见 [CONF-007 §2](../collaboration/iam-review-feedback.md#2-能力基线iam-603-反馈为准)。下表只列决定本计划形态的条目。

事实来源分四类，按域取用，不互相替代：

| 类别 | 载体 | 用途与边界 |
|---|---|---|
| 外部能力事实 | [问询函 §4.5](../collaboration/iam-confirmation-letter.md#45-回函提取与实测支撑材料内部团队验证) 及 §4.5.6—§4.5.8 的答复登记 | IAM 侧能力的唯一原文来源；答复不等于联调 |
| 本仓库行为事实 | [IAM 实现与验证记录](../design/verification/forge-iam.md) | 只证明本仓库可复跑的行为，不证明企业侧能力 |
| 决策与冲突规则 | [ADR-32](../architecture/platform-architecture.md#14-架构决策记录) | 定基线、定同版本冲突取哪一方 |
| 节选摘要 | 本表、[CONF-007 §2](../collaboration/iam-review-feedback.md#2-能力基线iam-603-反馈为准) | 不新增结论；与原始登记不一致时以原始登记为准 |

外部能力与本仓库行为属于不同域，不能互相顶替：不能因本地 mock 通过就写“IAM 已支持”，也不能因答复存在就写“本仓库已实现”。

| 能力 | 6.0.3 反馈结论 | 对本计划的影响 |
|---|---|---|
| 客户端认证 | 刷新必带 `client_secret`；每应用一个 `client_id`；无重叠轮换、两分钟生效 | 机密客户端为唯一路径；轮换按运维窗口执行 |
| PKCE | S256 可正常发码；`plain`/`S256` 均可用、不强制；省略参数按 `plain`；未登记参数静默忽略（2026-11-23） | 固定 S256 且显式携带参数；只需一次真实往返留证（MC-01） |
| 回调 | 前缀登记（`http://127.0.0.1:`、`http://127.0.0.1/`，`https` 可用），端口可随机；固定端口精确匹配可选 | 回环回调；默认系统分配端口配合前缀登记，固定端口为可选，二者不交替（MC-09） |
| 访问令牌 | 不透明、`7200` 秒、无 `aud`/`scope`、无标准内省；有未确认的有效性回查接口 | 网关判权依赖回查接口；不假设 JWT 验签（MC-12、A-11） |
| 刷新令牌 | 滑动 `7300` 秒、轮换、重用仅拒当次、并发首个成功、刷新后旧 AT 实时作废 | 锁内 pending + 锁外单飞；缺新 RT 即要求重登 |
| 撤销 | 只有 `GET revokeToken?access_token=`，仅 AT，RT 不可撤销 | `revocationMode` 固定 `access_token_query`，不启用 `rfc7009`（MC-10） |
| 分资源授权 | 不支持 `resource` | `gatewayResource` 留空；不外发未知参数（MC-06） |
| 授权范围 | 换票响应直接返回 `refresh_token`，未把 `offline_access` 列为必要条件 | 模板显式设置 scopes；插件默认值含该项，必须以显式值覆盖（MC-06） |
| UserInfo | `work_no`/`pinyin` 与 `employeeNumber`/`name` 两组口径并存 | 字段映射配置化，默认不投影（MC-05） |
| 目录同步 | 内部实测最坏 90 分钟 | 撤权窗口按 90 分钟计，不以“实时”为依据 |
| 签名与密钥 | 仅 `RS256`、单 `kid`、不支持 JWKS 轮换 | 公钥静态缓存，不实现轮换适配 |

## 3. 必须改动清单

级别：P0 = 不改则无法登录或无法调用模型；P1 = 不阻塞登录，影响退出、合规或后续切换成本。

### 3.1 代码改动与实测

| 编号 | 级别 | 组件与落点 | 改动内容 | 验收判据 | 责任 |
|---|---|---|---|---|---|
| MC-01 | P0 | 实测项，落点 `packages/forge-iam/src/oidc.mjs` 的当前行为；预期不改码 | 用一次真实授权请求验证目标部署接受 `code_challenge_method=S256`，结论写入验证记录。不新增 `plain` 路径；仅当 S256 被拒时才另立议题，按安全取舍交用户裁决 | 有“S256 被接受”的实测记录（授权请求 + 授权码发放）；代码中不存在 `plain` 分支 | 平台组 + IAM 团队 |
| MC-02 | P1 | `packages/forge-iam/src/model-transport.mjs`、`src/service-gateway.mjs` | 把身份头名与 consumer 类型提取为配置（默认保持现值），所有请求经单一出口组装 | 头名与类型可配置且默认值不变；现有头断言用例保持通过；新增加载自定义头名的正向用例 | 平台组 |
| MC-03 | P1 | `packages/forge-iam/src/exclusive.mjs` | 独占断言从单一 `deepseekAccount` 服务扩展为覆盖装配可见的官方行结论（或直接采用 reflow 的 `absent` 判定） | 官方行全部缺席时通过；注入任一行残留时拒绝且原因码可区分 | 平台组 |
| MC-04 | P1 | `packages/forge-iam/src/exclusive.mjs` 或独立启动检查 | 启动检测 `DEEPSEEK_API_KEY` 等官方旁路环境变量，默认告警；是否阻断由用户裁决 | 存在变量时产生固定诊断与审计字段（不含变量值）；无变量时不产生噪声 | 平台组；阻断需裁决 |
| MC-05 | P1 | `packages/forge-iam/src/service.mjs`、`scripts/lib/private-bundle.mjs` | 把 `profileFields` 映射开放为私版配置键，默认不投影；默认候选取较新答复的 `work_no`/`pinyin`，待 FB-IAM-06 二选一确认后固化 | 未配置时不请求 UserInfo；配置后可显示工号姓名；映射非法时拒绝启动而非静默不显示 | 平台组 |
| MC-06 | P1 | `scripts/lib/private-bundle.mjs`、私版模板 | 私版模板**显式给出** `HELUO_IAM_SCOPES=openid profile`：未设置时私版不写 scopes，插件默认值含 `offline_access`，因此不能靠“删除”解决，只能显式覆盖。`gatewayResource` 保持留空（6.0.3 反馈：RT 非要件、`resource` 不支持）。插件兼容默认值不变 | 生成的补丁显式含 `openid profile`；不含 `offline_access` 与 `gatewayResource`；含 `gatewayResource` 时仍通过校验 | 平台组 |

### 3.2 部署与登记改动（不涉及代码）

| 编号 | 级别 | 对象 | 改动内容 | 验收判据 | 责任 |
|---|---|---|---|---|---|
| MC-07 | P0 | IAM 管理台 + 目标终端 | 登记机密客户端（`client_id`、认证方法），在终端预置 `client_secret` 记录 | 抓包可见 Basic 或 post 凭证；无 `invalid_client`；换票后首次计划续期记录 `refresh-committed` 且会话保持 `ready` | 平台组 + IAM 团队 |
| MC-08 | P0 | 私版 `.env` | 显式配置 issuer 与 authorization/token/jwks（及 revocation、endSession、userinfo）端点，不依赖 discovery | 启动 `isConfigured` 通过；授权与刷新均走显式端点；不产生 `.well-known` 探测 | 平台组 |
| MC-09 | P0 | 私版 `.env` + IAM 管理台 | 回环回调：默认系统分配端口（`callbackPort: 0`）配合前缀登记；仅在需要精确校验或固定端口审计时改登记固定端口，并保持单一形态 | 每次登录回调成功；IAM 侧无地址不匹配；同一部署不出现两种形态交替；端口冲突时不改写回调地址 | 平台组 + IAM 团队 |
| MC-10 | P1 | 私版 `.env` | `revocationMode` 固定 `access_token_query`；退出文案区分“AT 已撤销 / RT 自然过期” | 退出后旧 AT 在 IAM 端失效；失败时面板显示“重新登录”而非成功 | 平台组 + IAM 团队 |
| MC-11 | P0 | 设置页 + 网关控制台 | 录入网关地址与个人 Key，校验凭据属主与当前 `sub` 一致，完成目录同步与一次真实模型调用 | 换人登录后旧 Key 显示属主不匹配；目录同步成功且模型可调用；缺失或非法 Key 被拒绝 | 平台组 + 网关团队 |
| MC-12 | P1 | 网关侧判权链路 | 确认网关以“有效性回查 + 短 TTL + 事件通道”判定身份令牌，且回查失败时拒绝而非放行；不依赖 JWT 验签 | 回查可用时按结果放行或拒绝；回查不可用时请求被拒并有可区分错误；无 JWT 验签依赖 | 平台组 + 网关团队 |

### 3.3 依赖与不可并行项

| 依赖/约束 | 说明 |
|---|---|
| MC-01 ← MC-07、MC-08、MC-09 | 没有登记的客户端、显式端点与可用回调，S256 实测没有可观察对象。IAM 侧已答复可用（E1），此处只差我方环境 |
| MC-07 ← IAM 管理台权限 + 终端预置 | 登记与预置必须同批具备，只有其一不能发起登录 |
| MC-09 ← MC-07 的 `client_id` 与登记规则 | 回调地址必须与已登记客户端一致，不能先于登记固化 |
| MC-11 ← MC-08、网关可达 | 目录同步与模型调用依赖端点与网关地址 |
| MC-12 ← FB-IAM-07 答复 | 回查接口未确认前只能记未联调，不得写成已具备 |
| MC-05 ← FB-IAM-06 答复 | 字段名二选一未定前只实现映射能力，不写死字段名 |
| 不可并行 | MC-09 的两种端口形态不得同时启用；MC-01 执行期间不并行改 PKCE 代码，避免实测对象漂移 |

## 4. 迭代路线

四段与[推广实施方案 §4](rollout-plan.md#4-工作分解) 的 G0–G3 对应，不自建第二套门禁。R2/R3 需版本或平台立项，本计划只记录启动条件，不承诺日期与能力。

### 4.1 R0 快速上线（1–2 周，对应 G1）

| 项 | 内容 |
|---|---|
| 目标 | 目标企业员工能用企业 IAM 登录，刷新不断线，并能调用企业模型 |
| 交付 | MC-01、MC-06、MC-07、MC-08、MC-09、MC-11（MC-06 即私版模板定稿） |
| 退出判据 | 端到端一次真实往返：授权 → 回调 → 换票 → 计划刷新 → 模型调用成功；断网与 RT 失效各有一条失败路径表现正确。判权链路（MC-12）不在 R0 判据内 |
| 不做 | 不引入 AIGS、不改撤销语义、不动宿主内核、不启用 public 或 `plain` 路径 |

### 4.2 R1 生产加固（2–4 周，对应 G2 前置）

| 项 | 内容 |
|---|---|
| 目标 | 把可容忍风险变成可运营的 SOP 与可观测字段 |
| 交付 | MC-02、MC-03、MC-04、MC-05、MC-10、MC-12；会话吊销 SOP（人事变动“下线所有会话” + 网关 Key 吊销）；审计字段固定；FB-IAM-04~08 答复落地 |
| 退出判据 | 可容忍风险各有补偿措施与验证记录；网关判权依赖（有效性回查）可用或明确关闭相应路径；升级 DSH 后官方行断言仍通过 |
| 不做 | 不在本地实现 PDP/PEP，不把本地门禁当最终授权，不假设 JWT 生效 |

### 4.3 R2 版本升级（需立项，不在本计划承诺）

| 项 | 内容 |
|---|---|
| 启动条件 | IAM 升级到 6.3.0 并完成商务与部署立项 |
| 届时评估 | public client 是否可用、Discovery 是否规范、SCIM 出站是否可用、`resource`/受众能力是否有变化、性能是否改善 |
| 判据 | 每项需书面结论 + 实测样例；口径变化以新增 ADR 记录，不改写 ADR-31/32；同步更新 DESIGN-016 与 IAM-002，不同时保留两套默认 |
| 现状 | 6.0.3 反馈未覆盖上述能力，本计划不以此作为 R0/R1 前提 |

### 4.4 R3 AIGS 目标态（需平台立项，不在本计划承诺）

| 项 | 内容 |
|---|---|
| 启动条件 | AIGS 完成部署、许可与联调准备，且 SCIM 出站与 Kill Switch 可用 |
| 交付方向 | 认证迁至 AIGS AIM、令牌切 STS ExToken、`X-IAM-Token` 退役、判权接入 `permission-check`、审计上送 |
| 判据 | 离职与紧急停用的令牌失效窗口可测；Exchange Token 的 `sub`/`act` 可验证；静态 Key 路径全部关闭 |
| 与 6.0.3 基线的关系 | ADR-32 的能力前提只覆盖 V1；AIGS 的能力主张沿用[从 IAM 到 AIGS](dsh-plugin-tools/iam-to-aigs-evolution.md)，届时另立基线与 ADR |

## 6. 风险与回退

| 风险 | 处置 | 回退 |
|---|---|---|
| IAM 不为 OIDC 补 `redirect_uri` 校验 | 以 S256 兜底并保持本地严格校验；缺口作为 IAM 侧风险登记，转 FB-IAM-09 | 不做基于回调地址的安全假设，登记值只作留痕 |
| `client_secret` 轮换或回滚的 2 分钟传播窗 | 只在无在线刷新的窗口轮换，窗口内暂停自动续期，不反复试探新值 | 回滚重填旧值并等传播，失败即停用该客户端并重登 |
| 固定端口在目标终端被占用 | 绑定失败即拒绝发起登录并给固定错误码，不改写回调地址 | 改回系统分配端口形态（前缀登记支持） |
| 机密 secret 轮换窗口内旧会话失效 | 轮换后重新登录，不沿用旧授权 | 保留旧记录直到新登录成功 |
| 有效性回查接口不可用（R1 项） | 拒绝而非放行；缩短 AT TTL 不能替代判权 | 关闭依赖该接口的路径，保留模型访问受限 |
| 环境旁路检测误报 | 默认只告警，不阻断 | 关闭检测开关，保留审计 |

## 8. 执行顺序

1. **Wave 1（阻塞解除）**：MC-08 → MC-07 → MC-09 → MC-01 → MC-11。MC-01 必须在 MC-07/08/09 完成后执行，否则拿不到可用的授权请求。
2. **Wave 2（加固）**：MC-02 → MC-03 → MC-04 → MC-05 → MC-10 → MC-12；每项含正向与负向用例，逐条可单独回退。
3. **Wave 3（外部依赖）**：R2/R3 按版本升级与 AIGS 立项启动，届时重写能力基线。

Wave 2 的每一项都是独立提交、独立开关、独立回退；不允许把多项加固合并为一次不可分割的改动。
