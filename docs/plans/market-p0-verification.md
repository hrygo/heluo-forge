## 3. 本仓库已能自证的部分

- **接口基线**：DSH `0.2.1-rc.2` 的 `pluginMarket`、`pluginManager` 已只读核验（2026-10-21）；它是接口基线，不是企业发行批准。
- **自身显示资源不足**：`packages/forge-market/package.json` 现无 `meta.title/description`、无 `./locale/*.json` 与 `./icon` 导出，`files` 也未包含 locale/icon。按 [DESIGN-007 §6.1](<../design/plugins/forge-market.md#61-目标最小交互>) 自身也不满足发布门禁，补资源列入 P1 前置。
- **仓库无发布流水线**：仅 `.github/workflows/check.yml`，没有发布、定时续期或原子切换任务，M0-7/M0-8 无法在仓库内证明。
- **无企业源与凭据**：仓库不含 registry 地址、CA、token 或 profile 配置，M0-1～M0-6 只能由企业侧提供。
- **无双端实机**：Windows 与麒麟均未跑过安装，M0-9 未取。

## 4. 可直接发给企业的提问

正式问询与逐题回函模板见 [插件市场企业接入问询函](<../collaboration/market-access-clarification.md>)（代拟，未发送）。

1. 企业 registry 用哪个产品？规范聚合入口 URL 是什么？scope 是否权威解析、缺包会不会代理公网？
2. 内网 HTTPS 用哪套 CA/代理？是否禁止 redirect？静态托管能否原子替换单个 `current` 文件？
3. 下载与发布分别用什么认证？能否给 CI 只读、给发布端最小写权限？凭据如何注入和轮换？
4. ACL 能否按包、版本、角色阻断？对 pnpm 缓存、本地 tarball、Git/path spec 是否也生效？
5. 同名同版本是否不可变？保留多久？删除或隔离后能否恢复？
6. 现有 CI 支持任务互斥、取消、5 分钟定时和失败告警吗？单个 job 最长能跑多久？
7. 目标 Windows 版本与 CPU 架构、麒麟 aarch64 基线分别是什么？DSH/Node/pnpm/SDK/Client 精确版本是多少？
8. 企业 DSH 发行版如何预置市场插件与 profile 基线？谁负责升级与回收？
9. 内部包的显示资源（en/zh 标题描述、icon、locale）由谁提供？真实 tarball 验收由谁签字？

## 5. 关闭条件

- 每行填入证据链接或命令输出、核验日期、执行人；M0-1～M0-11 全部为“通过”才可关闭 P0。
- 关键项不成立时，在本表记录“只读决议”，并同步 DESIGN-007／012 的未验标注；**不得**通过放宽安全行为“让它通过”。
- P0 不关闭不影响离线 P1：清单校验、自包含检查、索引/证据生成可用夹具先行，但不得连接企业源或宣称可安装。
