## 1. 评审结论与证据边界

个人研发统一通过 DSH，以当前真实用户身份访问模型；无人值守应用 Agent 使用受控开通、按应用及环境区分的凭证。身份认证、凭证归属、用途限制、模型授权、预算与网络规则分别判断，全部满足才放行。

个人访问优先评估**纯令牌**；若 **Key＋令牌**显著降低现有网关改造与运维成本，且能满足同样的身份、用途及撤权要求，可采用后者。尚未选定路线。仅有静态 Key 的 2026-10-22 基线不足以满足本轮要求；不以“Key 分组＋IP 白名单”代替当前用户身份验证。

安全目标是阻止普通转借和把凭证直接放到其他研发工具中使用。需求方接受有权限者刻意复制全部凭据并仿冒 DSH 协议的残余风险。工具标识不能被描述为不可伪造的身份证明。

| 事项 | 已知证据 | 本轮判断 |
|---|---|---|
| 业务要求 | Q1—Q17 由需求方确认 | 已确定要求；提供方能力待核验 |

## 2. 已确定要求的评审解释

下表解释需求基线 §4.6，范围仍以需求基线 §2 为准。

| 方面 | 已确定行为 | 不能据此推定的能力 |
|---|---|---|
| 个人归属 | 当前调用者必须是合法用户；保留个人 Key 时只能使用自己的 Key | 创建时记录 owner 不能证明运行时持有者就是 owner；本地 `ownerSubject` 不能替代网关校验 |
| 统一工具 | 个人研发只通过 DSH；DSH 内交互式 Agent 仍属个人场景 | 不能用应用 Agent 凭证作为其他 coding 工具的通行证 |
| 授权分工 | IAM 负责人员身份；网关负责模型、团队、额度及用途授权 | IAM 登录成功不等于模型开通；可批量开通，不要求逐人审批 |
| 轻量识别 | 使用 DSH 默认 UA，要求网关按关键字匹配以降低普通误用；诊断头为可选提案，不作为放行前提，详见[标识设计](../design/client-identification.md) | 网关能力及匹配规则待确认；UA 可仿冒，不能区分河洛定制或代替人员归属；不采集硬件序列号/MAC，不引入设备证书等硬件证明 |
| Agent 主体 | 按应用、环境开通；留存创建人、责任团队、当前责任人；支持责任转移 | 运行时不要求创建人在线，也不把创建人当作每次调用者；不新建机器身份平台 |
| 开通治理 | 网关控制台由管理员或获授权角色受控开通 Agent 凭证，变更及例外留痕 | 普通个人不能自行把个人凭证改成无约束应用凭证 |
| 网络限制 | 个人可在企业最低要求上加严 IP 限制；Agent 默认限定出口 IP/CIDR，例外需审批 | IP 不是人的身份，也不能证明使用了 DSH；不可低于企业最低限制 |
| 生命周期 | Agent 默认 90 天，更长需审批；人工更换、撤销、转移，接受必要的短维护窗口 | 不承诺双 Key 并存或零中断，不自建自动轮换平台；有原生提醒则复用 |
| 管理入口 | 凭证、审批、IP 与责任归属在网关控制台管理；DSH 展示状态、错误与链接 | 不要求 DSH 实现管理后台或网关签发 API；混合路线可人工创建并一次性录入 |
| 不满足时 | 关键身份、用途、撤权或退出要求缺失，相应路径不开放 | 不自动降级到裸 Key，不自动批准核心补丁或自建身份代理 |

## 3. 放行逻辑与信任边界

个人路线 A：有效且面向网关的用户授权 **且** 人员及会话有效 **且** DSH 用途符合 **且** 模型/预算/网络规则符合。

个人路线 B：路线 A 的全部条件 **且** Key 有效 **且** Key 为个人 DSH 用途 **且** 已认证人员与服务端 Key 归属一致。Key 与令牌是同时满足的条件，不能任选其一；这也不是多因素认证。

应用 Agent：受控开通的应用/环境凭证有效 **且** 对应应用用途、模型、预算和网络规则符合。创建人用于治理与审计，运行时授权归属应用。责任人离职时按应用责任交接或停用决定处理，不因不在线而失效，也不能失去责任主体。

所有可达入口均执行对应策略，包括兼容端点、备用认证头、旧路由和获准的其他调用入口。网关原生“团队”是成本/组织维度，不能未经核验等同于用途分组。服务端从可信映射取得主体及团队，不信任客户端任意填写的 owner、team 或应用身份头。

## 4. 撤权、退出与故障的时间语义

| 事件与计时起点 | 已确定上限或行为 | 核验重点 |
|---|---|---|
| IAM 中账号实际停用，或网关管理员实际封禁，记为 t0 | 最迟 t0＋5 分钟拒绝新的模型请求；刷新不得延长窗口 | 状态同步、节点缓存、验签/内省缓存、时钟容差均计入总窗口；HR→IAM 上游同步另测 |
| 服务端接受当前授权的撤销请求，记为 t0；含接受异步队列 | 最迟 t0＋5 分钟，该授权已发及窗口内新发的 Access Token 均不能用于新请求；所有刷新后代不能继续产生可用授权 | 只清客户端令牌或只撤一个 Access Token 不足；不能影响其他设备授权及应用 Agent |
| 用户点击退出 | 本地立即停止企业调用、清会话与运行时副本、取消本地在途请求；尝试服务端撤销 | 默认只退出当前设备授权，不自动登出浏览器全局 SSO，不默认撤销长期个人 Key |
| 离线退出 | 本地立即退出，显示“服务端撤销未确认” | 服务端五分钟从接受撤销时开始，不能从离线点击开始承诺；补偿/重试能力待 IAM 确认，不假装已完成 |
| 服务端已经接收的流式请求 | 可按已有请求截止时间结束；后续模型调用重新鉴权 | 不建设跨节点强制断流；本地取消不保证上游已停止生成或不计费 |
| IAM、密钥信息或状态服务故障 | 有效且可验证的授权，仅在仍能满足五分钟撤权约束时可继续；否则停止 | 令牌过期、签名未知、状态过旧均不能凭旧缓存无限放行，不能回落到只验 Key |

五分钟是端到端安全要求，不指定一定采用五分钟 JWT、每请求访问 IAM 或新增撤销服务。由提供方说明可兑现机制与最坏上界。若仅靠 JWT 有效期，必须同时约束停用后刷新、撤销后的刷新后代及容差，否则仍不达标。

## 5. 纯令牌与 Key＋令牌比较

| 维度 | A：纯令牌 | B：Key＋令牌 |
|---|---|---|
| 用户操作 | IAM 登录并完成网关授权，无个人静态 Key 录入 | IAM 登录，另到控制台创建个人 Key 并录入 |
| 当前用户校验 | 校验网关目标 Access Token 及人员/授权状态 | 同左，另校验 Key 和两者主体一致 |
| 网关改造 | 需将可信用户映射到模型授权、成员/团队预算、审计、网络及正文日志关闭策略 | 可复用 Key 的既有策略；新增令牌校验、归属一致校验与用途约束 |
| 客户端改造 | 网关目标令牌获取、刷新、请求取用、退出；具体 DSH seam 待核验 | 同左，加 Key 存取；双凭据承载是否需适配待核验 |
| 生命周期负担 | 无个人 Key 的创建、到期、更换支持成本 | 多一份长期秘密及更换、撤销、用户支持成本 |
| 撤权与退出 | 必须满足 §4，不能只说 JWT 可验签 | 同左；只撤 Key 不等于当前会话退出，不能影响其他设备 |
| 额度与审计 | 稳定人员/团队及必要的授权维度；不能拿短期 token 值作预算桶 | 复用 Key 计量时仍按稳定人员预算聚合，多设备或换 Key 不重置 |
| 日志与 IP | 需要不依赖静态 Key 的等效策略挂载点 | 可复用现有 Key 策略，但实际能力仍待核验 |
| 成本判据 | 成本接近时优先，减少长期凭据及人工流程 | 仅在显著降低总成本并达到同一标准时采用 |

网关可本地验证适用的签名 Access Token，身份一致比较可在网关内完成，**不必为比较 owner 每次访问 IAM**。但必须事先核实签名、issuer、audience、时效、身份映射，并解决五分钟撤权；若 IAM 只发不透明令牌，则需其支持的内省或其他可信验证机制。创建 Key 时保存身份仅解决归属记录，不能免去运行时调用者认证。

尚不固定新请求头、scope、audience 字面值、会话字段名或 Kong 插件。ID Token 用于客户端登录，不能直接当作模型 API 的 Access Token。RFC 8707 不是唯一可接受登记方式；经核验的 audience/client 配置亦可，但不能取消目标资源隔离。

请提供方分别评估现成配置、二次开发、许可、联调、上线等待和持续维护成本，并说明版本、依赖、负责人及时间。旧 Key-only 方案的“无需网关改造”或历史“两周”估算不适用于本轮，不凭空给出人日。

## 7. 验收细化

以下为既有 A 项的场景细化，不是新增全局 A 编号。均需实际 IAM/网关和 Windows、麒麟双端证据；离线测试不能代替企业联调。

| 场景 | 通过标准 | 归属 |
|---|---|---|
| 正常开通与计量 | 已授权用户成功调用；未开通人员及未授权模型拒绝；多设备、换 Key 不重置成员预算 | A1/A3 |
| A：无 Key | 无个人静态 Key 仍满足模型、成员/团队预算、可选 IP、审计及正文日志关闭要求 | A3/A13 |
| B：人员与 Key | A 的身份＋B 的 Key 拒绝；仅 Key、仅 token 均拒绝；A 的身份＋A 的 Key 成功 | A3/A14 |
| 令牌有效性 | 过期、错误签名/issuer/audience、ID Token 冒用拒绝；不能只检查主体文本 | A2/A14 |
| DSH 用途 | 默认 UA 缺失或不匹配经网关确认的关键字时拒绝；直接把 Key 配到普通 coding 工具且未携带匹配 UA 时不可调用；刻意仿冒不作强对抗验收；其他协议权限仍按独立契约检查 | A3/A14 |
| 入口一致 | 个人/应用凭证不能走其他认证头、兼容或旧路由绕过各自策略 | A3/A14 |
| Agent 开通治理 | 未授权者不能创建/改为通用应用凭证或批准 IP 例外；审批及责任转移可追溯 | A3/A13 |
| 网络规则 | 白名单内外结果正确；伪造转发头不能绕过；个人可选加严不降低企业基线 | A3/A14 |
| 停用与封禁 | 多节点、复制的 AT/RT、并发刷新下，按 §4 起点五分钟内拒绝新请求；HR→IAM 时延另记 | A2/A3/A14 |
| 当前授权退出 | 撤销前后及轮换竞争产生的刷新后代、已发 AT 均不能延长五分钟窗口；其他设备及应用 Agent 继续正常 | A2/A14 |
| 离线退出 | 本地立即清理并停止调用；明确显示服务端未确认；只从服务端接受时计时 | A2 |
| 依赖故障 | IAM、JWKS/内省或状态同步故障下，无法证明有效授权及五分钟边界时拒绝，无裸 Key 回落 | A2/A3/A14 |
| 流式与循环调用 | 已接收流按截止时间结束；窗口后循环中每次新模型调用拒绝；本地退出取消连接，不宣称服务端零计费 | A2/A3 |
| Agent 生命周期 | 默认 90 天、更长审批，到期/撤销生效；人工换新与停旧在约定维护窗口内完成 | A3/A13 |
| 日志安全 | 不记录 Key/token/正文；可追溯稳定主体、应用、原因、trace；A 路线无 Key 也满足 C4 | A13 |
| 失败与重放 | 区分未认证、未授权、用途、网络、预算和服务故障；未确认未执行或已输出的请求不自动重放 | A2/A3 |

每项记录版本、配置、动作起止时间、节点与最坏时延、脱敏结果和责任人。只拿一次成功调用、单节点 401、200 撤销响应或代码检索不能判定通过。

## 8. 标准依据与取舍

2026-10-23 核对以下官方规范；规范说明协议要求，不证明企业产品具备对应能力。

- [RFC 8252](https://www.rfc-editor.org/rfc/rfc8252.html)：原生应用采用系统浏览器与公共客户端安全接入，不能把共享 Client Secret 当桌面应用身份保证。本项目因 IAM 明确不支持公共客户端，V1 暂以机密客户端 + 系统钥匙串过渡；这是有已知残余风险的偏离，不是安全等价。钥匙串只保护静态存储，不能阻止正在使用该客户端的本人或同用户进程提取；短 AT 也不能阻止持有 secret 的攻击者换新令牌。secret 托管、轮换、吊销与防提取须单独验收。
- [RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)：OAuth 安全最佳实践；公共客户端刷新令牌须有适用的重放防护。优先核验 IAM 既有轮换/重用检测，不默认新增设备密码学体系。
- [RFC 7009](https://www.rfc-editor.org/rfc/rfc7009.html)：令牌撤销及相关授权处理；标准端点存在不等于本项目要求的跨节点五分钟、当前授权隔离和全部后代已经成立。
- [RFC 9068](https://www.rfc-editor.org/rfc/rfc9068.html)：适用的 JWT Access Token 验证与目标 audience；采用 JWT 时参考，未预设 IAM 的 Access Token 必为 JWT。
