## 1. 结论

2026-10-22 用户裁决：**V1 采用 UAG 标准产品的个人凭证作为正式模型网关凭据，不再把 IAM 令牌直通作为一期目标，也不要求网关为一期新增 JWT 验签。**

链路固定为：企业账号（SSO 或目录登录）进入 UAG 控制台 → 每台设备创建一把 `uag-` 个人凭证 → 一次性展示后粘贴进 DSH → DSH 存入系统凭据库 → 以 `Authorization: Bearer` 或 `apikey` 调用 `/v1/chat/completions`。企业 IAM 仍负责 DSH 登录与身份；模型网关不再消费 IAM access token。

这不是“临时兜底”，而是 V1 接入基线。代价是客户端重新持有长期静态凭据，且签发、轮换、账号停用联动部分依赖人工与 UAG 控制台；相应控制写入 §5，不接受“先跑起来再说”。

## 2. 与原令牌直通方案的差异

| 维度 | 原 ADR-2：令牌直通（已被 ADR-14 取代） | 本方案：UAG 个人凭证 |
|---|---|---|
| 客户端凭据 | IAM access token（短期）+ refresh token | `uag-` 静态 Key（长期，可设有效期） |
| 网关认证 | JWKS 或 introspection 验签 | Kong key-auth 查表 |
| 身份来源 | token 的 `sub` | 凭证绑定的 `owner_user_id` + `team_id` |
| 客户端是否经手凭据 | 否，登录后自动使用 | 是，用户从控制台复制并粘贴一次 |
| 账号停用联动 | 受 token TTL 与撤销约束 | UAG 内停用即时；IAM 停用需 SCIM 或人工工单 |
| 撤销窗口 | 受验签/内省缓存约束 | 约 5 秒，漏通知最长 300 秒；到期扫描 ≤60 秒 |
| 客户端复杂度 | 刷新管线、按资源缓存、401 刷新 | 录入、探测、401 引导、到期/轮换提示；无刷新 |
| 网关改造 | 需数据面 JWT 验签 | 使用标准产品现有能力，不新增 |

## 3. 接入要点（按 UAG `dev/2.2.1` 已知行为）

### 3.1 凭据与存储

- 格式：`uag-` + 32 位十六进制（128 位），无环境标识、无 `kid`；控制台显示 `uag-****ab12` 提示。
- 明文只在创建时展示一次，关闭后不可再看；DSH 不缓存明文到配置、日志或模型上下文。
- 控制面只存不加盐 SHA-256（不参与认证）；Kong `keyauth_credentials.key` 存明文。**这是已知残余风险，不因客户端加密而消失。**
- DSH 存储：系统凭据库中的 `CredentialRef: ENTERPRISE_STATIC_KEY`；生产使用 keychain provider，keychain 不可用时 fail closed；仅 dev/pilot 可显式接受 0600 fallback。
- 客户端记录 `ownerSubject`（录入时的 IAM `sub`）与设备标签，仅用于账号切换时阻止沿用上一账号的 Key，不作为服务端授权依据。

### 3.2 签发与开通

```text
管理员建团队、配模型白名单/路由、设团队与成员预算
  → 用户用企业账号（SSO 或目录登录）进入 UAG 控制台
  → /personal-credentials 新建：选团队、名称写设备、有效期建议 90 天、允许的模型
  → 一次性展示 uag-… 明文
  → DSH 粘贴、写入系统凭据库
  → 一次最小探测请求
```

- UAG 不提供客户端签发接口；DSH 不模拟控制台、不抓取会话、不调用未获支持的内部接口。
- 首次开通由 DSH 给出控制台入口（可配置深链）、设备命名建议与粘贴框；不要求网关新增自动签发。
- 服务型 Agent（CI、机器人）走 UAG Agent 凭证，不使用个人凭证；V1 不涉及。

### 3.3 调用与归属

```http
POST /v1/chat/completions
Authorization: Bearer uag-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
Content-Type: application/json

{ "model": "corp-chat", "stream": true, "messages": [ … ] }
```

Kong key-auth 识别凭证 → 归属到 `owner_user_id`、`team_id` → 模型白名单 → 团队/成员预算与 RPM/TPM → 上游路由（上游密钥只在网关内）→ 流结束计量并写审计。客户端自带的 `x-agent-id` / `x-team-id` 会被清除；`X-Device-Id` 不采集，设备维度以凭证名称进入计量。

### 3.4 生命周期与撤销

| 事件 | 操作 | 网关效果 | 生效窗口 |
|---|---|---|---|
| 挂起 / 恢复 | 本人、团队管理员、超级管理员 | 挂起返回 403，Key 保留；恢复后原 Key 可用 | 约 5 秒，最长 300 秒 |
| 撤销 / 退役 | 同上 | 删除 Key，之后 401 | 同上 |
| 到期 | 系统扫描 | 60 秒一次吊销，之后 401 | ≤60 秒 + 缓存 |
| 轮换 | 本人 | 新建 → 更新客户端 → 撤销旧 Key；系统“轮换”按钮立即撤旧，个人凭证返回 409 | 人工 |
| 移出团队 | 团队管理员 | 该团队下个人凭证退役、成员密钥吊销、成员预算清除 | 即时 |
| UAG 内停用 / 删除 | 管理员 | 先切断名下全部凭证，失败不写库 | 即时 |
| IAM 侧停用 | IAM 经 SCIM 推送 | 走同一条停用流程 | 配置后生效（时延待确认，要求 IAM 接 SCIM） |
| LDAP / AD 禁用 | — | 不自动作废已有 Key，只在下次登录控制台时被拒 | 无联动，靠 TTL 或改接 SCIM |

### 3.5 错误语义

| 返回 | 含义 | 客户端动作 | 重试 |
|---|---|---|---|
| `401 Unauthorized` / `No API key found` | Key 缺失、错误、到期、撤销或账号停用（不可区分） | 检查是否完整；到控制台核查状态或重建；不重试 | 否 |
| `403 You cannot consume this service` | 凭证被挂起 | 联系团队管理员；恢复后原 Key 可用 | 否 |
| `403 POLICY_DENIED` / `PENDING_APPROVAL` | 策略拒绝 / 待审批 | 展示原因；待审批去控制台跟进 | 否 |
| `400 MODEL_NOT_ALLOWED` / `MODEL_NOT_ROUTABLE` / `MODEL_REQUIRED` | 模型未授权/不可路由/未填 | 申请权限或检查模型名；不静默换模型 | 否 |
| `422 NO_ROUTE_STRATEGY` | 无路由策略 | 联系管理员 | 否 |
| `429 budget_exhausted` + `reset_at` | 团队/成员/凭证预算耗尽 | 展示恢复时间；不重试 | 否 |
| `429 RPM_LIMIT_EXCEEDED` / `TPM_LIMIT_EXCEEDED` + `Retry-After` | 限流 | 按 `Retry-After` 退避 | 按头 |
| `5xx` / 超时 | 网关内部已重试，结果未知 | 不盲目重放；已输出内容不重放 | 否 |

### 3.6 客户端流程与界面

- 首启 4 屏调整为：欢迎 → 登录 → 网关凭据（控制台入口、设备命名建议、粘贴、探测）→ 完成。登录成功但未配置凭据时，企业模型不可用，显示“模型未就绪”而不是“登录失败”。
- 可跳过 onboarding；跳过后保留横幅与账户页“网关凭据”入口，随时配置。
- 账户页展示：凭据状态（未配置/可用/挂起/无效/不可达）、设备标签、录入时间、建议到期日、控制台入口、清除凭据；不显示 Key 明文。
- 探测：一次最小 `/v1/chat/completions`（`max_tokens` 极小）或经确认的更轻接口；区分“凭据有效但模型未授权”与“凭据无效/挂起/不可达”。
- 退出：清运行时副本与内存副本；默认保留已保存 Key，但仅对录入时同一 IAM 主体可用；换账号需重新粘贴或显式清除。**退出不宣称已吊销 UAG Key。**
- 不允许自动刷新或自动重建 Key；401 只引导用户到控制台核查/重建，不重放原请求。

### 3.7 审计与可见性

- 分析稿称 UAG 记录每次请求的 `owner_user_id`、`team_id`、agent/凭证、provider、model、token、成本、状态、耗时、trace；审计保留 ≥365 天、WORM + HMAC 链，待联调与书面确认。
- 凭证名称进入计量，作为设备维度的替代；控制台展示状态、最近使用与撤销入口。
- DSH 只记录配置/探测/清除等本地事件，不记录 Key 明文或请求正文。

## 4. 与原提议的差异（未采纳项）

| 项 | 2026-10-20 原提议 | UAG 标准产品 | 裁决 |
|---|---|---|---|
| 签发方式 | `POST /v1/keys` 自助签发、列表、撤销 | 仅控制台手工创建，无客户端签发 API | 接受控制台；不要求 API |
| 格式 | `csk_<env>_<kid>_<secret>`，256 位 | `uag-` + 32 位十六进制，128 位 | 接受 `uag-`；不要求 kid/环境前缀 |
| 服务端存储 | HMAC-SHA256(secret, pepper) | 控制面 SHA-256（不参与认证）；Kong 明文 | 安全书面接受 + 补偿控制，不要求重写 Kong |
| 有效期 | 默认 90、上限 180、禁 never、到期前 7 天提示 | 永不/30/90/自定义，无默认/上限/提醒 | 以管理员策略与运行规范补足；不接受产品层“永远有效” |
| 401 细分 | invalid_key / expired / revoked / disabled | 只有 Kong 原文，不可区分 | 客户端引导查控制台；不要求网关细分 |
| 设备维度 | `X-Device-Id` + 每设备一把 | 凭证名称进入计量，无设备头 | 用凭证名；DSH 不再上报设备头 |
| 组织维度 | 部门/成本中心 | 只有团队；SCIM 不同步 group | 团队按部门建；REQ-23 后补 |
| 轮换 | 新旧并存 ≤24h、自动 | 人工新建→更新→撤旧；按钮 409 | 人工 runbook；需确认多活跃 Key 上限 |
| 按模型预算 | 契约含模型维度 | 记录模型，不设模型预算 | 降级为统计维度；REQ-04 只保留个人/团队 |

## 5. 采用条件与残余风险

**已裁决采用；以下条件不闭合则不扩大试点：**

1. **C4**：河洛使用的每个凭证在创建、更换、轮换时开启 `privacy_mode`；平台核对、安全抽验网关与模型日志不含正文。产品默认记录正文，不能把“有开关”当成“默认关闭”。
2. **账号停用**：优先 IAM → UAG SCIM；未接通前把 UAG 停用/批量撤销纳入离职工单，明确责任人、时限与核对证据；TTL 只作兜底。
3. **TTL**：管理员策略禁止“永不”，默认 90 天、上限 180 天或安全批准值；到期提醒与轮换 runbook 落到支持流程。
4. **Kong 明文**：安全书面接受，并确认 DB/备份访问控制、静态加密评估、审计与泄露批量撤销；否则本方案不成立。
5. **容量与统计**：800 人前取得并发、吞吐、P95、超时与 SLA，以及按人去重的首调用/活跃数据；未取得不作容量承诺。

**残余风险**：手工签发/轮换的支持成本；长期 Key 被复制/共用的归因风险；401 不可细分导致的自助体验差；无设备头/部门模型；控制台故障时新用户与轮换受阻；Kong 明文库泄露的放大效应。以上不因客户端实现而消失，需在试点准入与运行手册中承接。
