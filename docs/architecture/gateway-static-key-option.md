## 1. 结论

**本文件是备选方案，不是现行设计。主方案仍为 ADR-2「客户端只持 IAM access token、网关验签、不换发 Key」。**

记录它的原因有两条：一是"静态 Key"在云模型生态里是事实标准，讨论时反复出现，需要一份完整的对照而不是口头结论；二是如果主方案在联调中卡在某个具体条件上（见 §5），要有可直接执行的替代路径，而不是临时拍板。

本文件不改变任何契约、验收、排期或文档清单中的现有条目。若将来采纳，本文件转为决策依据，另立 `CORP-DSH-GW-002` 作为字段级契约；方案与契约分开，避免把未冻结的接口写进受控契约。

## 2. 与主方案的差异

| 维度 | 主方案（现行） | 备选方案（本文） |
|---|---|---|
| DSH → 网关凭据 | IAM access token，短期 | 网关签发的静态 Key，长期或限期 |
| 凭据来源 | IAM 令牌端点 | 网关密钥服务 |
| 网关验签 | JWKS 或 introspection | 查 `kid` 与哈希比对 |
| 身份来源 | token 的 `sub` | Key 绑定的 `sub` |
| 与 `llm-pi-ai` 的关系 | 需把 token 镜像进 `CredentialRef` | 直接作为 provider `apiKey`，无需改造 |
| IAM token 的角色 | 资源通行证 | 仅用于换取 Key 与身份态校验 |

差异的本质：主方案让"身份"与"调用凭据"是同一件东西，备选方案把它们拆开，用一次签发换长期稳定。

## 3. 方案要点

### 3.1 密钥格式与存储

```text
csk_<env>_<kid>_<secret>
     └ 3~4   └ 10 位随机   └ 32 字节随机
```

- 前缀 `csk_` 供密钥扫描与误提交拦截；`kid` 可直接索引，无需全表比对。
- 服务端只存 `kid`、`HMAC-SHA256(secret, 部署级 pepper)`、绑定主体与状态，不存明文。secret 为 256 位随机值，用 HMAC 足够，不用慢哈希——鉴权在每请求路径上。
- 客户端存入凭据存储，引用名 `ENTERPRISE_API_KEY`；不写配置明文、不进日志、不进模型上下文。
- 明文仅在签发响应中出现一次，之后任何接口都取不回。

### 3.2 接口面（拟建，非既有）

| 方法 | 路径 | 鉴权 | 作用 | 约束 |
|---|---|---|---|---|
| `POST` | `/v1/keys` | IAM access token | 签发 | owner 恒为 token 的 `sub`，请求体不接受 owner 字段 |
| `GET` | `/v1/keys` | 同上 | 列出自己的 Key | 只返回元数据 |
| `DELETE` | `/v1/keys/{kid}` | 同上 | 撤销 | 只能撤自己的；幂等 |
| `POST` | `/v1/keys/{kid}/rotate` | 同上 | 轮换（可选） | 新旧重叠 ≤24 小时 |

推理面在 OpenAI 兼容路径上接受 `Authorization: Bearer csk_...`，同时兼容 `x-api-key`，以适配不同 SDK 的默认头。

签发侧三条硬要求：

1. 新近认证：token 的 `auth_time` ≤10 分钟才允许签发，不接受缓存中的旧 token。自助签发等于发放长期凭据。
2. 配额：每用户活跃 Key ≤5 把，签发 ≤10 次/天，限制被控会话囤积。
3. TTL 必填：默认 90 天、上限 180 天，不提供永不过期选项。

### 3.3 生命周期与撤销

| 触发 | 机制 | 生效窗口 |
|---|---|---|
| 用户主动撤销 | 置 `revoked`，鉴权缓存 ≤60 秒 | 分钟级 |
| 到期 | 校验 `expires_at` | 精确 |
| IAM 禁用或离职 | 事件或 SCIM 推送批量撤销 + 每请求校验 owner 状态（缓存 5 分钟） | ≤5 分钟 |

第三行是本方案能否成立的前提。没有 owner 状态校验，离职残留授权会从"不超过 60 分钟"恶化到"最长 180 天"，这个差距不是配置能弥补的。

### 3.4 错误语义

| 码 | 含义 | 客户端动作 |
|---|---|---|
| `401 invalid_key` | 不存在或格式错 | 提示重新签发 |
| `401 key_expired` | 已到期 | 自动重新签发一次 |
| `401 key_revoked` | 已被撤销 | 提示重新签发并告知可能异常 |
| `401 account_disabled` | 主体已禁用 | 不重试，提示联系管理员 |
| `403 model_not_allowed` | 模型不在白名单 | 不重试，展示可选模型 |
| `429 quota_exceeded` | 额度耗尽，带 `quota_scope` | 不自动重试 |

`expired` 与 `revoked` 必须可区分：前者是正常运维，后者可能是异常信号。统一成"认证失败"会丢失这个信息。

### 3.5 审计与可见性

- 事件：`key.created`、`key.revoked`、`key.expired`、`key.auth_failed`；字段含 `kid`、`sub`、来源 IP、UA、时间，不含 secret。
- `last_used_at` 异步更新，延迟 ≤5 分钟。
- 用户可见自己的 Key 列表：label、设备、创建、到期、最近使用。自助签发模式下，陌生条目可被发现是最重要的补偿控制。

### 3.6 客户端流程

```text
IAM 登录 → 本地无 Key 或收到 key_expired / key_revoked
        → POST /v1/keys（携带有效 token）
        → 写入凭据存储
        → 推理请求带 csk_...
```

401 只触发"重新签发"，不重放已执行的推理请求；该边界与主方案 §4.3 一致，不因为换成静态 Key 而放宽。

## 4. 对比

| 维度 | 主方案 | 备选方案 |
|---|---|---|
| 撤销窗口 | ≤60 分钟（受 IAM TTL 与验签缓存约束） | ≤5 分钟（有状态校验）或最长 TTL（无校验） |
| 落盘凭据价值 | 短期 token + refresh token | 长期 Key + refresh token，价值更高 |
| 客户端复杂度 | 刷新管线、引用镜像、401 分支 | 签发一次、401 重签 |
| 网关复杂度 | 验签或内省 | 密钥服务、哈希存储、状态缓存、IAM 集成 |
| 兼容性 | 需确认 `llm-pi-ai` 是否按请求重取引用 | 与云厂商 SDK 一致，无需改造 |
| 多资源隔离 | 一资源一 token，天然隔离 | Key 只对网关有效，隔离面相同 |
| 失败模式 | token 中途过期影响长任务/流式 | 过期时间显式，可提前轮换 |
| 运维成本 | 依赖 IAM 能力 | 新增一套密钥生命周期管理 |

结论：备选方案在**兼容性与长任务稳定性**上更好，在**凭据价值与运维面**上更差。主方案优先，是因为这两个代价在 800 人内部平台上比"少几次刷新"更重要。

## 5. 采用条件

出现以下任一情况时，应重新评估本方案：

1. 网关无法提供 JWKS 或 introspection，且短期内无法补齐，导致主方案无法验证 token。
2. `llm-pi-ai` 无法在流式期间按请求重取 `CredentialRef`，而 401 后又禁止重放，导致长任务频繁中断且无可接受的产品降级。
3. 范围扩展到需要直连云厂商 SDK 或第三方模型市场的场景，静态 Key 成为硬约束。
4. IAM 的 access token TTL 无法压到可接受范围（例如必须 ≥8 小时），主方案的撤销窗口优势消失。

前两条在 P0/P1 联调即可判定，不需要等到 G2。

## 6. 切换成本

| 项 | 内容 |
|---|---|
| 网关新建 | 签发/列表/撤销接口、哈希存储、状态缓存、IAM 状态集成、审计事件 |
| 文档改动 | ADR-2 换向、§7.1 重写、GW-001 §4.1/§4.3 与验收改写、A14 调整、风险表增补、新建 GW-002 |
| 客户端改动 | IAM 插件新增签发与重签流程、凭据引用改为 `ENTERPRISE_API_KEY`、401 分支按错误码分流 |
| 测试 | 签发—使用—撤销—401、到期、禁用、越权撤销、列表不泄露 secret、哈希命中 |
| 迁移 | 无存量 Key，但需定义首次签发失败时的降级与提示 |

## 7. 不采纳的理由与残余风险

不采纳的主要理由不是"技术不好"，而是**它把一次认证问题变成了一套凭据资产管理问题**：

- 长期凭据一旦随凭据文件外泄，攻击者可长期使用；短 token 把同一个事故限制在一小时内。
- 自助签发带来持久化风险：会话被控即可 mint 一把撑过会话撤销的 Key。
- 需要网关持续维护撤销、轮换、到期提醒、异常检测，这些能力的运营成本会沉淀在网关团队。

若将来启用，必须同时接受：TTL 上限、owner 状态校验、可枚举可撤销、审计留痕。四项缺一不可。

## 8. 待确认

| 问题 | 需要谁回答 | 影响 |
|---|---|---|
| 网关能否承载密钥服务与状态缓存 | 网关团队 | 是否具备实施条件 |
| IAM 是否提供禁用事件或 SCIM 推送 | IAM 团队 | 级联撤销的生效窗口 |
| 企业是否已有密钥管理规范（TTL、轮换、审计） | 安全 | 参数上限与合规口径 |
| 一人多设备时按人还是按设备签发 | 平台、IT | 撤销粒度与支持成本 |
