## 1. 结论

个人访问需可信的当前人员身份和 DSH 用途约束；A 纯令牌与 B Key＋令牌均为待核验候选。B 必须同时通过两种凭据验证及人员归属一致校验，不能任选。应用 Agent 使用按应用/环境受控开通的专用凭证，记录创建人与责任归属，运行时不要求创建人登录。

模型权限、团队/成员预算、网络规则、正文日志关闭及审计在选定路线下均须成立。五分钟撤权与当前授权退出是硬要求。关键条件缺失时，相应路径不开放，不能回落到只验 Key。仅 Key 归属记录不能证明当前调用者身份。

## 2. 适用边界

项目范围以[需求基线 §2](../requirements/requirements-baseline.md#2-范围边界唯一真源)为准。本契约负责调用者身份、用途、授权、预算、来源、错误、撤权及 C1/C4 的接口与运行约束；不授权新建身份平台或自动轮换服务。本轮不做实现，也不冻结未经提供方核实的新接口字段。

## 3. 已有分析稿记录的现状（非本轮能力承诺）

- UAG 标准产品基于 Kong；模型路由只认 API Key（`key-auth`），模型路由上没有 `jwt` / `oidc` 插件；只有可选的 AIGS 在 `/mcp` 上验 AAM 签发的 JWT。
- 个人凭证格式为 `uag-` + 32 位十六进制（128 位），无环境标识、无 `kid`；控制面只存不加盐 SHA-256（不参与认证），Kong `keyauth_credentials.key` 存明文。
- 控制台支持 OIDC、LDAP/AD 与本地账号，JIT 建号；分析稿所述停用路径为 SCIM `active=false` 推送，IAM 出站及实际接通状态未知，LDAP 只在下次登录控制台时发现，OIDC 无 back-channel。
- 同一凭证可能同时受团队预算、成员预算与可选的个人凭证预算约束；模型只记录、不单独设预算。
- 客户端持有的 Key 为长期凭据，撤销生效受 Kong 节点缓存影响（约 5 秒，漏通知时最长 300 秒）；到期由 60 秒扫描吊销。

## 4. 契约

本节定义需求方要求的目标行为，提供方能力全部按证据逐项确认。§3 的既有事实不因本节要求而变成已支持；G1 冻结协议/字段，G2 验证多节点及双端边界。新问询为 CONF-GW-09—20，原 CONF-GW-01—08 历史问答仍保留。

### 4.1 身份、用途与凭据

| 项 | 目标契约 | 能力状态 |
|---|---|---|
| A 纯令牌 | 校验面向网关的 Access Token，可信映射到人员及授权上下文；不要求个人静态 Key | 当前 UAG 分析稿未证明支持 |
| B Key＋令牌 | Key 有效 AND 目标 Access Token 有效 AND 已认证人员对应 Key owner；任一缺失/不匹配拒绝 | 不能只复用 key-auth；承载与比较能力待核验 |
| 身份验证 | JWT 路径校验签名、算法、issuer、audience、时效；不透明令牌使用提供方确认的可信验证；ID Token 不替代 Access Token | 格式、claims、资源登记、JWKS/内省均待 IAM/网关确认 |
| 人员映射 | 明确 IAM 主体与 `owner_user_id` 的可信映射、跨客户端 sub、账号重建规则；不信任自报 owner/team | 待 CONF-IAM-10 / CONF-GW-09；不预设字段相等 |
| 用途隔离 | 个人凭据只能用于 DSH 个人访问；应用凭据仅用于获批应用/环境；所有认证头、兼容与旧路由同样约束 | 原生 team 不等于用途组，需网关核实策略能力 |
| DSH 识别 | 应用标识、接入协议版本、随机安装实例标识；缺失/不支持的协议拒绝；标识只用于轻量防误用和关联 | 字段名及请求位置未冻结，不引入硬件指纹或通用内置秘密 |
| 实例边界 | 随机实例标识不是可信人员身份，不授权撤销，也不作为成本主体；单设备授权由服务端可信生命周期关联 | 会话关联机制待 IAM 核实，不能仅依赖客户端 UUID |
| 应用 Agent | 按应用/环境开通；创建人不可混淆为运行时调用者；责任团队与当前责任人可转移 | 优先复用现有服务 Agent 实体；完整能力待确认 |
| 控制面 | 管理员或授权角色审批应用资格、用途/IP 例外、责任交接；个人不能自助变成通用应用凭据 | 管理权限及审计待核验；DSH 不承建后台 |
| 网络 | 企业基线始终生效；个人可选加严；应用默认 IP/CIDR 白名单，放宽需审批；只信受控代理链的实际来源 | 白名单支持及转发头信任规则未有明确证据 |
| 签发及保存 | 如 B 保留 Key，控制台人工创建、一次性展示、录入系统凭据库；不要求额外签发 API；秘密不进上下文/日志 | 现有 `uag-`＋32 位十六进制、Bearer/apikey 是 Key-only 历史承载，不推定支持双凭据 |
| 应用有效期 | 默认 90 天，更长由管理员审批；人工换新/撤销，接受必要短维护窗口 | 默认强制、提醒及并存能力待确认；不承诺零中断 |

**身份一致比较无需每次查询 IAM**：若网关能独立验证适用 Access Token 并取得可信主体，可在本地与服务端 owner 映射比较；但撤权和会话状态的新鲜度仍必须满足下表，不能因此离线无限接受旧授权。

#### 4.1.1 生命周期与失败约束

| 事件 | 必须满足的运行行为 |
|---|---|
| IAM 实际停用 / 网关实际封禁 t0 | 最迟 t0＋5 分钟拒绝新模型请求，刷新不能延长；状态传播、缓存及容差均计入。HR→IAM 同步单独测量 |
| 当前设备退出 | 本地立即停企业调用、清会话/运行时副本并取消本地在途请求；默认不影响其他设备、全局浏览器 SSO 或应用 Agent，也不默认撤销长期个人 Key |
| 服务端接受撤销 t0（含接受入队） | 当前授权及所有刷新后代最迟 t0＋5 分钟不能继续产生可用访问；已发及窗口内新发 AT 均不得用于新的模型请求，不牵连其他授权 |
| 离线退出 | 本地立即生效，明确服务端未确认；服务端窗口从接受时起算。补偿/重试材料及清理方式待 IAM 核实 |
| IAM/验证或状态依赖故障 | 只有授权仍有效、可验证且仍保证五分钟撤权时才继续；状态过旧或无法证明则拒绝，不回落到裸 Key |
| 已接收流 | 按已有请求截止时间结束；后续模型请求（含工具循环后的模型调用）重新检查；不做跨节点强制断流；本地取消不保证上游停止或零计费 |

### 4.2 额度与计量

| 维度 | 键 | 说明 |
|---|---|---|
| 团队 | `team_id` | 团队日/月预算，成本归属 |
| 成员 | `owner_user_id` | 成员月预算，个人公平性；多设备 Key 共享同一预算 |
| 个人凭证 | credential id | 可选的设备级附加限制，不能替代成员预算 |
| Agent / Provider | agent / provider | 服务型 Agent 与供应商上限，非桌面个人场景 |
| 模型 | `model` | 记录到计量；**不设按模型预算** |
| 窗口 | 日 / 月 | 由网关配置，DSH 不假设 |

- 上表字段为现有 Key 路径；A 路线须将已验证人员/授权映射到等效预算与策略，B 路线核实人员与 Key 一致后才复用既有预算。应用按获批应用/环境归因，不把创建人误作当前操作者。
- 现有路径聚合键为 `(owner_user_id, team_id, credential, model, window)`；A 路线需等效稳定维度。禁止用 Key/token 原值或随刷新变化的 token ID 作为成员预算桶；不预设 A 的新字段名。
- 同一成员多设备、换 Key、轮换后预算桶不清零；按此验收，不以“每设备一把”替代个人总量。
- 计数单位支持 token、cost、request；RPM 按凭证所属 Agent 计，TPM 按 `agent_id` 计。
- 流式请求在流结束结算；中断或取消按已产生用量计（具体行为待联调）。
- 额度查询接口未确认；`GET /v1/quota` 不是既有接口，V1 不承诺。

### 4.3 超额与错误

下表记录既有 Key 路径行为；新增的身份不一致、用途拒绝、来源限制、会话撤销及依赖故障需在 G1 冻结错误映射。DSH 按可靠类别处置，不把所有 401 都引导为重建 Key；不能从旧表推定新路由仍返回同样字段。

预算耗尽示例（UAG 当前格式）：

```http
HTTP/1.1 429 Too Many Requests
Content-Type: application/json

{"error":"budget_exhausted","reset_at":"2026-10-23T00:00:00+08:00"}
```

RPM/TPM 超限返回 `429`，带 `Retry-After`。预算 429 不带 `Retry-After`，也不使用 `application/problem+json`、`quota_scope` 或 `quotas` 数组。

| 返回 | 含义 | 客户端行为 | 可自动重试 |
|---|---|---|---|
| `401 Unauthorized` / `No API key found in request` | Key 缺失、错误、到期、撤销或账号停用（当前无法区分） | 提示检查 Key 完整性，并到 UAG 控制台查看该凭证状态或重建；不重试 | 否 |
| `403 You cannot consume this service` | 凭证被挂起 | 提示联系团队管理员；恢复后原 Key 可用 | 否 |
| `403 POLICY_DENIED` / `PENDING_APPROVAL` | 策略拒绝 / 需要审批 | 展示原因；待审批的提示到控制台跟进 | 否 |
| `400 MODEL_NOT_ALLOWED` / `MODEL_NOT_ROUTABLE` / `MODEL_REQUIRED` | 模型未授权、不可路由或未填 | 提示申请模型权限或检查模型名；不静默换模型 | 否 |
| `422 NO_ROUTE_STRATEGY` | 该凭证没有配置路由策略 | 提示联系管理员 | 否 |
| `429 {"error":"budget_exhausted","reset_at":…}` | 团队 / 成员 / 凭证预算耗尽 | 展示 `reset_at`；无法区分层级时提示到控制台查看；不重试 | 否 |
| `429 RPM_LIMIT_EXCEEDED` / `TPM_LIMIT_EXCEEDED` | 每分钟请求数 / token 数超限 | 按 `Retry-After` 退避 | 按 `Retry-After` |
| `5xx` / 超时 | 网关已在内部重试和容灾，结果未知 | 不盲目重放；已经输出过内容的请求不重放 | 否 |

**重放边界**：401 本身不证明请求尚未执行；请求已接收、已开始生成、已输出或结果未知时，禁止自动重放；应报告状态并按已确认机制查询/人工核对。网络故障、取消或超时不等于未执行。UAG 内部对 429/5xx 的重试可能重复生成或计费，客户端不得再用自动重放放大。

### 4.4 模型目录

- 现有 Key 路径以 UAG 凭证级“允许的模型”为准；A 路线需等效服务端模型授权；DSH 的 `gateway.models` 是客户端白名单，必须是凭证允许集合的子集。
- 未授权模型返回 `400 MODEL_NOT_ALLOWED`，不返回可用模型列表；DSH 不静默降级到其他模型。
- UAG 是否提供模型目录接口未确认；V1 以配置白名单 + 控制台授权为准。

### 4.5 数据边界与日志保留（C1 / C4）

| 约束项 | 契约要求 |
|---|---|
| 路由边界（C1） | 所有模型路由仅指向机构内私有化推理服务，禁止配置任何公网或第三方商业模型上游 |
| 正文日志（C4） | UAG 产品默认记录请求/响应正文，`privacy_mode` 可按凭证关闭；河洛所有使用 Key 的个人及应用凭证必须在创建、更换、轮换时开启 `privacy_mode`；A 路线必须提供不依赖个人静态 Key 的等效关闭策略，并由平台组核对、安全抽验网关与模型日志不含 prompt/completion。逐凭证开关不是产品默认值，需以开通/运行控制补足；不能只在 B 中落实 C4 |
| 计量与审计日志 | 分析稿称 UAG 记录 `owner_user_id`、`team_id`、agent/凭证、provider、model、token、成本、状态、耗时、trace；审计保留 ≥365 天、WORM + HMAC 链，均待核验。DSH 只上报调用元数据，不报正文 |
| 排障采样 | 任何正文采样仍须安全审批、最小化脱敏并到期删除；“不超过 7 天”仅为平台方建议上限，未获批准不得开启 |

## 5. 失败模式

| 场景 | 行为 | 客户端应对 |
|---|---|---|
| Kong 缓存未失效 | 撤销/挂起后短时间内旧 Key 仍可能通过（约 5 秒，最长 300 秒） | 不把一次 401/403 当全网生效；按控制台状态与重试提示处置 |
| 预算存储不可用 | UAG 行为待确认；不得假定 fail open | 仅确认未执行时退避；结果未知不自动重放 |
| 计数延迟 | 超额可能延后一个请求生效 | 接受偶发超出，按窗口结算 |
| 停用联动不满足时限 | 现有静态 Key 可能继续可用，不能声称五分钟达标 | 核验等效可兑现机制；关键能力缺失不开放该路径，工单/TTL 不能代替上限 |
| Kong 库泄露 | 明文 Key 可被直接使用 | 依赖 DB/备份访问控制、静态加密评估、审计与批量撤销；安全书面接受 |
| Key 共用/转借 | 仅 Key 路径无法区分实际使用者；客户端 owner 绑定不能证明真实 owner | B 必须服务端验证当前身份及归属一致；不能只以追责规则代替拒绝 |
| 控制台不可用 | 新用户/更换受阻；已授权访问是否可继续须独立判断 | 仍须符合身份、用途及五分钟撤权，不能因持 Key 就默认放行 |

## 6. 验收

完整细化见[评审稿 §7](../architecture/gateway-identity-review.md#7-验收细化)，挂接[推广方案 A1/A2/A3/A13/A14](../plans/rollout-plan.md#7-验收标准)。两条候选路线只有全部满足本契约才可选用；本轮未实测。

- 个人身份、可选 Key owner、DSH 用途、应用用途、来源限制的正常及拒绝路径均验证，覆盖所有入口。
- 多节点、AT/RT 复制及刷新竞争下，分别按实际停用/封禁和服务端接受单授权撤销的起点测量五分钟；其他设备及应用隔离验证。
- 预算、模型、错误、429、流式取消/计费、未知结果不重放，按选定路线联调。纯令牌必须有等效预算/IP/C4，不以 Key-only 测试代替。
- 开通、默认 90 天、更长审批、人工更换与维护窗口、责任转移及审计提供证据。
- 生产/试点 UAG 版本、容量、吞吐、P95、最大请求截止时间及 SLA 取得书面基线；正文关闭在网关和模型两侧抽验。
