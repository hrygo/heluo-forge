## 1. 结论与范围

只采企业平台看不到、且已定义用途的结构化事实。DevOps 汇聚、计算和展示；客户端不重算部署频率、PR 等待或平台已有全量数据，不自建数据库/指标平台。指标只观察与改进，不替换 M1–M6、不恢复已撤销的 M4，也不作为 G3 判定或个人绩效依据。

采集选择并入 `forge-policy` 既有工具审计的**独立观察投影**，不新增包；必要安全审计与可选指标导出分别处置。指标失败不阻塞研发，必要审计失败仍按原安全规则关闭相关动作。

## 2. 数据最小化与归属

禁止字段：提示词、聊天正文、代码、diff、需求/验收正文、工具 stdout/stderr、文件内容、用户姓名/邮箱、token、任意扩展属性和业务 URL。不以哈希这些内容作为规避；业务引用需使用已获准的不透明标识。接受业务写入所需正文不代表可将正文复制进指标。

| 数据 | 权威产生方 | 客户端行为 |
|---|---|---|
| PR、合入、构建、部署、故障 | 原平台/DevOps 关联 | 不另发“权威部署完成”事件；仅消费必要关联 |
| 工具动作是否真实执行及其终结结果 | 宿主/策略层 | 投影结果，不采 Agent 自述成功 |
| 显式承接、正式业务决策请求 | 明确入口/可信交互 | 仅在事件用途获批后补充，不能从聊天推断 |
| AI 辅助全量分母、团队归属 | DevOps | 不从本机 DSH 样本推全量 |

## 3. 事件目录与候选信封

### 3.1 事件名

| 名称 | 何时产生 | 属性与状态 |
|---|---|---|
| `forge.change.accepted` | 显式入口且变更/仓库读取核对成功 | 不透明变更/仓库引用；可选观察启用后产生 |
| `forge.tool.completed` | 同一逻辑动作取得终结观察 | 动作名、读写类、结果、耗时和结构化错误码；unknown 也是结果，不伪造成功 |
| `forge.tool.reconciled` | 原 unknown/partial 经正式查询取得新证据 | 原 `operation_id`、更高结果版本；消费者更新该逻辑动作，不累加一次成功 |
| `forge.decision.requested` | 明确业务决策请求，不含内容 | 仅类别码与变更关联；用途/口径待批，默认不采 |
| `forge.observation.loss` | 缓冲超限、超期、拒绝或导出失败后可报告 | 分原因丢弃计数和窗口；不能递归生成自身失败事件 |

不发布“AI 已完成业务验收”“故事已结束”等客户端权威事件，也不从任意工具输出正则提取业务结果。

### 3.2 字段

以下是候选允许清单；未列字段一律拒绝，不采用任意 `attributes` map。

| 字段 | 类型/要求 | 用途 |
|---|---|---|
| `schema_version` | 固定 `forge.observation.v1` | 版本路由，不等于包版本 |
| `event_id` | 不透明唯一标识；同一事件重送保持不变 | 摄取去重 |
| `event_name` | §3.1 枚举 | 禁止自由文本 |
| `occurred_at`, `emitted_at` | UTC 时间；不可用明确缺失 | 业务观察时间与客户端导出时间分开 |
| `source_version` | 客户端/投影版本的受控标识 | 解释覆盖范围 |
| `project_ref`, `system_ref`, `change_ref`, `repository_ref` | 获准的不透明引用；缺失与不适用分开 | 由原平台映射，不采对象名称 |
| `operation_id`, `result_version` | 逻辑动作引用与单调结果版本 | 重试、回查、跨事件结果折叠 |
| `action`, `access_kind` | 受控动作枚举；`read` / `development_write` / `local` | 无原始 Shell 命令或参数 |
| `status` | 工具契约结果枚举 | 不把失败/缺失变成 0 |
| `duration_ms` | 单调计时所得非负数或缺失 | 不以跨机器墙钟差冒充耗时 |
| `error_code`, `decision_kind` | 已登记枚举；不含错误正文 | 原因分类 |
| `loss_reason`, `loss_count`, `window_start`, `window_end` | 仅 loss 事件使用 | 数据质量 |

引用只能来自已核验入口/原平台映射，按冻结的标识格式和长度验证；不得将自由文本或其哈希塞进合法引用字段。各事件必需/允许字段与时间缺失语义冻结前保持导出关闭。

`event_id` 用于重复传输，`operation_id` 用于一个逻辑动作的多次观察，不能混为一个键。没有明确信息就不生成主体标识；个人维度默认不进入本契约，不能借关联映射输出排名。

## 4. 幂等、缺失与版本演进

- 摄取按同一租户范围内的 `event_id` 去重。相同 ID、相同载荷重送不重复计数；相同 ID 不同载荷拒绝并记数据质量，不取最后一次覆盖。
- 按 `operation_id` 与 `result_version` 折叠工具结果；乱序/重送不增加逻辑动作分母。unknown 后查明成功是修订，不是第二次动作。
- 缺事件、缺关联、客户端未启用、端点故障和数据不适用分别统计；缺分母、起止或权威关联时指标是 unknown/不可计算，不插值或补 0。
- 不采自由文本；客户端与摄取端均按精确字段、类型、枚举及每事件适用性验证。仅定义允许清单不证明实现已经验证。
- 候选单事件上限 8 KiB，不截断后把内容当合法事件；超限整条拒绝并计数。实际阈值需安全/DevOps 冻结。
- v1 含义不回改；新增事件/枚举须先由消费方支持，未知字段/事件隔离拒绝，不静默降格为成功。破坏性语义使用 v2，在平台确认的过渡窗口双读但不双计；无版本映射时关闭对应导出。

## 5. 上报与离线降级

### 5.1 通道与认证

优先使用企业已有 OTel/OTLP 到 Collector 的审计基础设施做独立观察投影。**不在此发明 OTLP 端点、认证 header 或 DevOps 摄取 API。** 摄取方提供脱敏契约、认证资源、批量与响应格式后才冻结。

若现有 OTLP 通路不可用，可评审 DevOps 摄取 API，但它是替代候选而非已经存在的兜底。默认不同时双发；切换需保持事件标识和确认位置，无法证明去重时停止并核对，不新建路由服务。凭据通过已有身份机制取得，不进事件、模型或磁盘缓冲。

原生 CI/CD 语义可参考 [OTel CI/CD spans](https://opentelemetry.io/docs/specs/semconv/cicd/cicd-spans/)（2026-10-22 页面核对，该页 span 约定标为 Development）；这不表示全部相关属性都处于同一稳定级别。企业采纳的具体版本与字段须单独锁定；本契约的业务事件不直接依赖实验性字段，也不部署额外 trace 服务。

### 5.2 失败、重送与候选上限

| 场景 | 候选行为 |
|---|---|
| 摄取确认成功 | 仅移除被明确确认的事件 |
| 部分批量成功 | 只重送未确认项，保持 `event_id` |
| 响应未知/超时 | 若提供方保证按 ID 幂等，可有限重送；否则暂停导出，不影响研发 |
| 401/403 | 停止导出，通知配置责任方；不借业务令牌或换账户 |
| 429/临时故障 | 遵循有效服务端退避提示；候选指数退避加抖动，最大 5 分钟，连续 5 次后暂停至下一合法恢复机会 |
| 离线 | 默认有界内存缓冲，候选最多 1000 条且 4 MiB，二者先到即拒绝新增并计数；TTL 候选 24 小时 |
| 退出/重启 | 内存事件可能丢失，记录覆盖缺口；不承诺持久可靠投递，不恢复一个新采集服务 |
| 需要持久离线队列 | 只能使用企业已批准的现有机制；加密/ACL/容量/TTL 单独确认，未批准不落盘 |
| 未知 schema 或含禁止字段 | 不发送/摄取拒绝；不打印被拒载荷；仅增加拒绝原因计数 |

这些数值是限额草案，不是当前客户端实现或企业 SLA；提供方无法确认安全降级时关闭可选指标，而非阻塞研发或放宽必要审计。

## 6. 摄取、保留与用途边界

| 项 | 草案 | 冻结责任及未确认处置 |
|---|---|---|
| 摄取负责人/通道/认证 | DevOps 提供，IT 维护已有 Collector | DevOps、IT、安全；未确认不导出 |
| 原始观察事件 | 候选最多 30 天 | 安全、PMO；业务正文不在采集范围 |
| 团队/项目汇总 | 候选最多 90 天 | PMO、DevOps；保留口径与覆盖范围 |
| 去标识长期趋势 | 候选最多 180 天 | 安全、PMO 另批；不代表默认建设 |
| 迟到窗口 | 候选 7 天 | DevOps；窗口后不静默改已发布快照，另出修订并关联原口径 |
| 摄取去重记录 | 至少覆盖允许重送/迟到窗口并留安全余量 | DevOps；若 TTL/迟到变化需同步调整，不能先删去重记录再接收迟到重复 |
| 小样本展示 | 团队人数候选不少于 5 人 | 安全、PMO；不足不展示可识别分组 |
| 个人可见性 | 默认无个人维度；本人视图须另批 | 安全、PMO；禁止个人排名、绩效评估及对外披露 |
| 修订/删除 | 由既有平台的数据治理机制负责 | DevOps、安全；客户端不复制权威库 |

客户端时间可能偏移；单机耗时优先单调时钟，跨系统里程碑按权威平台时间/版本关联。偏移不可判定时不计算端到端时长，不自行校准企业记录。

## 7. 验收目标与负向用例

1. 重送同一事件只摄取一次；同 ID 异载荷拒绝。
2. unknown 后 reconciled 成功只修订一个逻辑动作；乱序不扩大分母。
3. 缺少开始或全平台分母时返回不可计算，不能输出 0 或 AI 覆盖率。
4. 分别构造含 `prompt`、`code`、`diff`、`description`、`stdout`、token 或未知扩展字段的事件，均整条拒绝且诊断不回显内容；即使值为其哈希也不能绕过允许清单。
5. 合法字段承载不合法类型/自由文本、超大载荷、未知版本或与事件不适用的字段，同样拒绝；不是仅做敏感关键词扫描。
6. 摄取超时、部分成功、限流、离线、缓冲溢出、TTL 到期与进程退出不会阻塞正常研发，缺失计数和覆盖边界可见。
7. 任何观察故障都不改变必要审计规则、M1–M6 口径、M4 撤销状态或 G3 判定。
8. 指标仅来自可信操作结果和平台记录，不采聊天正文、代码行数或模型自报效率。

以上为目标契约用例，**NOT RUN：未建立采集器、无内网摄取端，本文不新增实现或测试**。仓库文档检查不替代事件实现与真实摄取验证。
