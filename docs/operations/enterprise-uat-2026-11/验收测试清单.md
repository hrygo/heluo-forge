## 4. 本轮不验

## 7. 登录取证清单

目标机上做企业账号登录时按项记录，缺项写明原因，不要省略。本节只登记证据，不改变第 2 节必过项的判定。

| 项 | 记录什么 |
|---|---|
| 平台与架构 | 例如 Windows 11 ARM64、macOS 26 arm64 |
| DSH 版本 | `dsh --version` 原文 |
| 提交号 | 被测提交的完整 SHA |
| 诊断导出 | 企业账号面板导出的 `{"format":"forge-iam-diagnostic","version":1,...}` 原文，字段含 `pagePhase/iamState/configured/signedIn/exclusive/gatewayState/errorCode/missingConfigCount` |
| 存储目录 | 默认 `D`：Windows 为 `%LOCALAPPDATA%\HeluoForge`，macOS 为 `~/Library/Application Support/HeluoForge`；记录 `D` 及同级 `D.keys` 是否存在和文件名，不读取或记录密钥内容 |
| 门禁结论 | 登录是否越过原子门禁，即是否返回授权地址 |
| 失败信息 | 失败时的错误码与面板原文；没有失败写「无」 |

判读：`configured:true` 且 `errorCode:null` 表示宿主侧配置与存储门禁都已通过，问题在别处（网络、浏览器、IAM 侧）。

排查顺序（面板写「凭据存储不可用，暂时无法登录。」时）：

1. 插件是否读到 `credentials` 服务。Cordis 禁止读取未 `inject` 的服务，`ctx.get('credentials')` 会抛 `cannot get property "credentials" without inject`；异常被吞成 `undefined` 后凭据恒为不可用。先确认插件版本已改为动态注入。
2. `iam-atomic-store` 是否在位。缺服务或实例不符时 `startSignIn` 返回 `IAM_ATOMIC_STORE_UNVERIFIED`。
3. 后端目录及文件。确认 `D` 及同级 `D.keys` 的权限，检查 `D/credentials.sqlite` 和新布局的 `D.keys/keyring.json` 是否存在；首次写入前这些文件可能尚未创建。发现旧 `D/keyring.json`，或数据库存在但密钥或密钥绑定缺失时，拒绝访问并保留原物、报告，不自动绑定、重建或覆盖。旧 `credentials.json` 和 `credentials.key` 保留原物，不读取、删除或迁移，也不阻止使用 SQLite；旧版用户需要重新登录或录入凭据，已有完整 SQLite 凭据继续使用。目标机权限与隔离行为仍须实测。

Windows 与 macOS 的默认后端为 SQLite 值级加密和文件 keyring，不经过系统钥匙串。数据库与 keyring 分目录，旧同目录 keyring 和未绑定旧库拒绝使用。分目录不提供同账户进程隔离；目标机 ACL、耐久性和该布局仍须实机验证。
