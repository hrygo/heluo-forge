## 1. 定位与效力

本文规定 `@heluo/forge-*` 插件在 DSH 宿主上的跨包硬性要求。规则的参照实现是 [forge-iam](../../packages/forge-iam/README.md)：其结构整改、状态机与安全边界的实践被提炼为可跨包复用的判据。

- 适用范围：本仓库全部 DSH 插件，包括后续新增的包。
- 与包内文档的关系：包自己的设计文档决定字段、错误码与状态编号；本文只决定"哪些性质必须成立、如何证明"。
- 冲突处理：与包实现冲突时，以本文为准并报告差异；不因某个包历来如此而豁免。
- 证据边界：本文规则来自单一参照实现的实践，尚未在第二个插件上完整验证；第 5 节列出待验证项。

## 2. 规则总览

| 编号 | 要求 | 判据（可失败） |
|---|---|---|
| P1 | 装载形态先定，再谈结构 | 浏览器侧仍是单 bundle；边界锚点存在且由符号归属守卫覆盖 |
| P2 | Host 按轴分模块，装配点只装配 | 装配点不出现状态变量与状态机调用；轴之间无互相 import |
| P3 | 准入先于能力，默认拒绝 | 未就绪路径有拒绝用例；拒绝时不提供替代目标 |
| P4 | 自证不是证据，同权不是边界 | 安全声明写明注入方、注入物与防护边界 |
| P5 | 错误码是契约，异常不得被吞 | 错误体只有一个读取口；catch 能说明捕获类型 |
| P6 | 状态机显式，并发必须串行 | 迁移有文档与用例；重复提交被串行化或丢弃 |
| P7 | 单一真源 | 客户端缓存不得反向回写宿主配置 |
| P8 | 安全边界不因"可禁用"而放宽 | 开关关闭时门禁仍生效；敏感值不进日志与视图 |
| P9 | 每条要求都要有一条会失败的判据 | 守卫经变异验证会失败；判据不依赖行号 |

## 3. 逐条规范

### 3.1 P1 装载形态先定，再谈结构

要求：

- 浏览器侧一个包只加载一个 bundle。`client.js` 保持 `window.__ModuleLoader__.load({ id, factory })` 的单文件形态，**不得 `import src/*.mjs`**，也不进 Node 模块图。
- 单文件内部边界用固定锚点（`// §N`）表达，段与段之间单向依赖：纯函数与常量 ← IO 边界 ← 状态所有权 ← 视图与出口。
- **不得为"文件更短"引入打包步骤**：新增构建期产物就要有"生成物与源一致"的校验，否则等于用构建复杂度换取评审便利。

反例：为拆分把 `client.js` 改成多文件并加 esbuild，随后每次改动都要先想"源还是产物"。

判据：`client.js` 仍是单文件；结构守卫按**符号归属**断言（状态字面量只出现在派生函数、`localStorage` 只出现在存储适配、错误码解包只出现在一个函数），而不是按行号区间。

参照：`packages/forge-iam/test/client-structure.test.mjs`。

### 3.2 P2 Host 按轴分模块，装配点只装配

要求：

- 一份状态只有一个可写所有者。会话、凭据、目录、选型、令牌、勘定、退出各自归属一个模块。
- 装配入口（如 `src/service.mjs`）只做装配、委托与出口，不持有状态、不直接推进状态机。
- 跨轴协作只经显式端口（getter、callback）注入；轴模块之间**不得互相 import**，唯一聚合点是装配入口。

反例：把"顺手能用"的 `transition()` 留在装配点，表面拆了模块，实际写者仍有两处。

判据：装配点出现状态变量、状态机调用或跨轴直接调用即失败。

参照：`packages/forge-iam/test/service-state-structure.test.mjs`。

### 3.3 P3 准入先于能力，默认拒绝

要求：

- 每个对外能力（登录、刷新、模型调用、工具执行、写配置）先判定准入；未就绪一律 fail closed。
- 拒绝时**不得给出可绕过的替代目标**，也不得静默放行到公共通道。
- 判定做成纯函数并单测；I/O 层只负责取值，不承担判定。
- 依赖缺失时拒绝，而不是降级继续。降级只能收紧权限，不能放松。

反例：模型门禁在"可用但不属于企业"时放行，等于用可用性换准入。

判据：每个拒绝分支有对应用例；门禁逻辑是纯函数且被直接单测。

参照：`packages/forge-iam/src/model-gate.mjs`。

### 3.4 P4 自证不是证据，同权不是边界

要求：

- provider 或宿主自报的能力标记（`durable`、`transaction`、`crossProcessLock`、自称可用）**不构成证据**。
- 只有组合方在受信代码中显式注入的**同步字面量 `true`** 才算信任声明；异常、Promise、其他值一律拒绝。
- 同一进程内同权 JS 可以绕过任何门禁；文档与 PR 不得据此宣称安全准入。
- 涉及安全声明时必须写清：谁注入、注入什么、能防什么、防不了什么。

反例：依据 provider 自报的 `crossProcessLock: true` 放行新登录。

判据：安全相关字段有注入来源校验；相关文档包含"防不了什么"的明确表述。

参照：`packages/forge-iam/README.md` 的原子存储运行时门禁一节。

### 3.5 P5 错误码是契约，异常不得被吞

要求：

- 对外失败一律映射到固定错误码；错误体只允许**一个读取口**，调用方不得自行解包。
- **禁止**把真实异常与业务失败映射到同一个通用码。把 `ReferenceError`、`TypeError` 渲染成"未登录"或"端点不可达"，会让缺陷伪装成环境问题。
- 新增 `catch` 必须能说出它捕获的是哪一类失败；未知异常保持可见。

反例：`tokenErrorMessage` 把未知异常映射成内部错误码，缺失的 import 因此以"登录态异常"的形式反复出现。

判据：错误码常量集中定义；错误解包只有一个函数；新增 catch 有注释或测试说明捕获范围。

参照：`packages/forge-iam/client.js` 的 `resultCode` / `resultNotice`。

### 3.6 P6 状态机显式，并发必须串行

要求：

- 有生命周期的对象（会话、凭据、目录、默认模型）必须能画出状态与迁移，并在设计文档中可对照。
- 并发写必须串行化：单飞、队列或排他断言。结果不确定时保持 pending 并 fail closed，**不重发请求、不返回旧值、不显示成功**。
- 界面动作与状态机一致：一次提交携带整份集合时，提示必须说明副作用，不得让用户以为只改了一处。

反例：两个快速点击各自发出一次写请求，后到的旧快照覆盖新结果。

判据：每个迁移至少一条用例；重复提交有"只写一次"的断言；不确定态有用例证明不显示成功。

参照：`docs/design/plugins/forge-iam.md` §7.6（SM1–SM4）。

### 3.7 P7 单一真源

要求：

- 宿主持久化是唯一准入真源；浏览器缓存与客户端草稿只是副本，**不得反向回写**。
- view 是快照，改动只能经服务方法；客户端不得直接改宿主状态。

反例：本地缓存过期后覆盖宿主已保存的选择。

判据：存在"缓存反向写"路径即失败；账号切换与配置重载后以宿主为准。

参照：`docs/design/plugins/forge-iam.md` §13.1 第 6 条。

### 3.8 P8 安全边界不因"可禁用"而放宽

要求：

- 凭据、密钥、令牌只经受信存储（钥匙串、宿主 `ctx.credentials`）；日志、视图与错误体不得出现原值。
- 任何可关闭的开关都不得同时关闭授权门禁；配置退化只能收紧。
- 新增字段先回答："会不会进日志、视图或错误体？"

反例：以"该能力可禁用"为由跳过授权检查。

判据：脱敏路径有测试；开关关闭时门禁用例仍通过。

参照：`AGENTS.md` §4 补丁层约束与本文件 P3。

### 3.9 P9 每条要求都要有一条会失败的判据

要求：

- 结构要求必须落成测试，并用变异（故意越界一次）证明它真的会失败。
- 既过不了的守卫要修正实现，不能放宽守卫。
- 判据按符号归属与可观察行为编写；**行数不是判据**——为凑行数拆出的模块没有职责，这是被否掉的方向。

反例：守卫用 `indexOf` 匹配到提前返回的分支，看起来通过，实际没验到目标逻辑。

判据：守卫测试存在且有变异验证记录；新增结构约束同时新增守卫。

参照：`packages/forge-iam/test/service-state-structure.test.mjs`、`client-structure.test.mjs`。

## 4. 复核清单

评审插件改动时按序核对，任一项为否即为不通过：

1. 浏览器侧仍是单 bundle，边界在既有锚点内。
2. 装配点没有新增状态或状态机调用。
3. 新能力的拒绝路径有测试，且没有替代放行通道。
4. 安全声明写清了注入方与防护边界。
5. 错误码固定、单一读取口，且没有把异常映射成业务码。
6. 状态迁移有文档与用例，重复提交只写一次。
7. 客户端没有反向回写宿主配置。
8. 可禁用开关没有放宽门禁。
9. 结构约束有会失败的守卫，未依赖行号。

## 5. 待验证

- 本规范由单一参照实现（forge-iam）提炼；第二个插件接入时应逐条对照，并把不成立或需调整的条目回写本文。
- P1 的锚点制度尚未在含大量内联样式的插件外验证。
- P4 的注入模型依赖宿主提供可注入入口；未提供时需要写明替代判据。
