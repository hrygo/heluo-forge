# What this proposes

第一阶段分开 IAM 会话状态与受管模型运行时。IAM 提供只读上下文和变更信号，模型运行时在明确的启动、会话或模型操作路径上读取上下文，并执行清理或目录刷新。模型视图成为纯投影，由 Host 将同一次会话取样与模型快照组合。目录展示和会话业务各自发布通知。方案沿用现有插件、浏览器 bundle、对外接口和派发授权检查，并以离线回归验证行为。

## How the existing system works, per this document

`service-state.mjs` 的 `view()` 调用模型 `getView()`。后者执行 `sample()`，再读取完整 IAM 视图。采样可能取消请求、清理目录并发布通知。Host 又把目录变化送入会话通知、续期调度和模型订阅。方案记载退出后立即隐藏旧模型的既有用例，并保留管理路由在读取视图前显式执行同步或目录刷新。

## 可理解性发现

- **U6-1 · 重要。** §2 第 42、48 行列出三个代际和三种不同变更。读者尚无法明确每个代际在续期、同主体重新登录和同地址重存网关 Key 时的预期，相应回归断言无法从方案推出。
- **U6-2 · 重要。** §2 第 50 行将独占检查归于 IAM，缺少检查对象和拒绝时机。应定义它如何处理迟到的官方账号服务，以及保留哪些对外行为。
- **U6-3 · 重要。** §2 第 43 行与 §3.3 第 71 行缺少订阅和初次取样的顺序保证。读者无法判断启动时两者之间发生的状态变化是否会被消费。
- **U6-4 · 轻微。** §4 第 84 行要求隔离 `DSH_HOME`。应给出创建临时目录并设置该变量的可复跑命令。
