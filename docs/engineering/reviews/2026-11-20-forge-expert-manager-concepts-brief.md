# DSH 专家智能体管理插件概念简报

> 作者 hrygo · 2026-11-20 · Agent 代拟 · 待详细设计

## 用户体验

DSH 的「设置 → 专家智能体」提供可搜索的专家目录和「可调用」视图。「可调用」列出当前账号在所选组织内至少有一个获准委派范围的全部专家，允许用户调整个人启停状态。目录仍展示获准查看的专家。仅可查看的条目显示调用限制。两种视图复用同一入口、目录数据和详情。[专家 PRD §4](../../requirements/delegra-experts-prd.md#4-功能需求与优先级)

首次使用和新获调用权的专家默认未启用。用户点击「启用」或「停用」，保存完成后更新个人状态与 `@` 候选。暂不接单和个人启用分别显示。用户能在管理页重新启用仍有调用权的专家。已提交任务继续按 Delegra 的任务生命周期执行。[产品确认记录](2026-11-20-forge-expert-manager-working-hypothesis.md#产品确认记录)

无匹配结果、无调用资格、尚未启用专家和目录加载失败分别提示。保存中防止重复提交，失败时显示可重试原因并保留最近一次确认的状态。结果未知时先回读 Host 确认。同名项显示职责等已有区分信息，选择按稳定专家 ID 对齐。验证原生导航后，可在空的专家候选组提供「管理专家」入口，支持用键盘返回原草稿。

## 候选、偏好与授权

| 判断 | 所有者 | 生效条件 |
| --- | --- | --- |
| 查看专家 | Delegra | 当前员工获得 `agent:read` 或受限目录契约定义的等效权限 |
| 在管理页中启停 | DSH Host | Delegra 确认当前员工有调用资格，Host 按当前实例、组织、账号和专家 ID 保存用户明确要求的状态 |
| 出现在 `@` | DSH 专家候选源 | 当前员工在本次会话的有效委派范围内可调用、专家可接新任务且个人已启用 |
| 受理任务 | Delegra | 按实际员工、专家、任务上下文和受理策略复验。DSH 的提交与恢复沿用现有绑定方案 |

员工目录由 Delegra 判定。当前委派使用的项目或其他范围以已核验的员工契约与会话上下文为准。具备项目 A 资格的员工可在管理页启用专家。在项目 B 缺少资格时，该专家退出当前会话的 `@` 候选。若员工契约只提供单一委派范围，管理页与候选可复用该范围的目录判定。目录结果不足以证明完整性时，界面明确标明范围或结果不完整。

Host 使用当前企业身份保存本机偏好。保存请求指定稳定专家 ID 与目标启用状态，Host 串行提交同一作用域的写入，再向 Client 发布已保存状态。Client 使用不含凭据的投影渲染一个设置页面和一个独立的 `@` 候选组。提交前核对当前账号、会话、委派范围、专家资格与启用状态，再按[接入方案 §3](../../plans/2026-11-18-forge-experts-integration-proposal.md#3-dsh-选择与委派绑定)发送。仅凭普通文本中的 `@` 名称无法完成专家选择。

目录按需读取和分页。Host 在授权证据有效期内复用结果，输入时按当前投影本地筛选。账号、组织、委派范围或授权变化时废弃相关旧结果。每次身份切换使用新的会话代次，阻止 A → B → A 时第一轮 A 的回包恢复旧目录。停用或撤权后撤下已开菜单中的旧专家行，点选仍复验当前状态。失效的待发送选择保留草稿并提示重选。

专家在该组织内失去全部调用资格时，作废相关启用状态。重新授权按新获权处理。单个委派范围的权限变化影响该范围的候选和待发送选择。目录加载失败时保留本机偏好并暂停受影响候选。恢复后重读目录，并核对启用状态对应的调用资格是否持续有效。离线期间的撤回与重新授予依目标契约提供的授权连续性证据判断，无法确认时要求用户重新启用受影响的专家。恢复接单后按仍有效的个人偏好重新提供候选。

目录、保存和候选刷新使用阶段、结果原因和请求关联号诊断。委派与受理的审计沿用 Delegra 的服务端记录。

## 取舍

| 比较项 | 采用的方案与依据 |
| --- | --- |
| 全部专家自动进入候选 | 用户确认通过管理页手动启用。首次和新增授权默认关闭候选资格 |
| 独立专家目录或同步服务 | 复用 `forge-experts` 和 Delegra 的目录职责。Host 只持久保存个人偏好，避免同步专家状态、权限及生命周期 |
| 拿目录可读状态直接生成 `@` | 当前读取和任务授权分别判定。候选使用 Delegra 在有效委派范围内给出的调用资格，并单独核对接单状态 |
| 用通用 Client 配置直接保存偏好 | 复用原生设置入口和现有 Host 管理模式。Host 负责员工和组织归属、保存确认以及候选失效 |

### 验收场景

| 场景 | 通过条件 |
| --- | --- |
| 第一次使用与同名专家 | 两位同名且允许调用的专家都在管理页。默认专家候选为空。手动启用其中一位后只出现对应 ID。新增获权专家保持未启用 |
| 偏好保存与回退 | 重启同一实例后恢复已保存的状态。保存失败状态与候选一致。A → B → A 及两个窗口交错时，旧响应无法恢复已停用候选或写入另一账号。停用入口后存量任务仍可按授权回查 |
| 查看、调用和接单分离 | 仅可查看的员工能看到获准披露的目录项，启停视图排除此项。项目 A 可选、项目 B 不可选。专家暂停接单后退出 `@`，恢复接单后重新评估仍有效的个人偏好 |
| 已开菜单、撤权与草稿 | 已选专家停用、撤权或切换委派范围时，旧选择失效，保留原草稿与后续输入，远端新增任务数为零。撤权后重新授予需要手动启用。按约定时限验证旧结果丢弃 |
| 受理结果未知 | 在服务端已受理但回执丢失时，按原请求关联号查询。重试产生的该次任务总数最多为一。用户可区分目录异常、授权拒绝、专家暂停与实际任务受理 |

## Goldfish 评审结果

七个独立上下文完成对[工作假设](2026-11-20-forge-expert-manager-working-hypothesis.md)的评审。设计与实施就绪关注项目范围与撤权复验。代码核验确认原生入口和已开菜单失效边界。可理解性与结构评审补强按钮反馈、账号隔离和状态归属。整体与创新评审收敛为单一目录、按需读取与本机派生候选。产品规则进入 PRD，技术边界进入接入方案，实施继续由现有 Issue 跟踪。
