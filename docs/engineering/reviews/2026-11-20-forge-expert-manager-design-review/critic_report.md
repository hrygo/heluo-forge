# 专家智能体管理插件设计批判评审

> 2026-11-20 · Agent 代拟 · EGM 阶段 7 · 三个独立上下文评审 V0.5.0 第 1–184 行，交叉核对实施计划。

| 编号 | 严重度 | 评审发现 | 去向 |
| --- | --- | --- | --- |
| D1 | 阻断 | 设计允许点选原生引用，实施计划可以先装入候选。原生引用展平和可信提交的时序未钉住，失效选择可能进入普通消息 | 生产可点选候选和真实委派同门禁，候选列表和失效可独立取证。检验提交被拒、草稿保留和原生引用仍可用 |
| D2 | 重要 | SSE 通知与 HTTP 响应没有同一新旧边界，同一身份下的晚到响应可回填旧值。重连未定义先收到通知还是先取快照 | 以同源投影版本和订阅就绪建立屏障。覆盖目录、分页、候选、保存回包及重连间隙 |
| D3 | 重要 | 无偏好记录时 `revision=0`，已撤回并重授后旧启用请求仍可能匹配原修订 | 编辑前置条件包含获悉的授权连续性，重授后的专家默认未启用 |
| D4 | 重要 | 普通 GET 可能早于迟到 PUT，介质重开可读也无法独立证明本次写入持久成功 | 明确单次请求结算和未定期间的读写契约，分别验收未入队、丢回包和介质异常 |
| D5 | 重要 | DSH 连接鉴权与 IAM 身份快照不能证明员工凭据同次绑定。现有角色矩阵缺少取得凭据途中换人、切组织或换实例的负例 | 目录取证加入凭据声明、当前上下文及响应归属复验，拒绝场景下无受限字段 |
| D6 | 重要 | 目录遗漏 FE-FR-02 要求的能力、资源及动作摘要和可披露的调用限制 | 在管理目录的同一投影增加可披露字段与缺失提示 |
| S1 | 重要 | §3 和 §5 的阶段门禁交叠，候选阶段包含预备接缝，但绑定模块在可信委派阶段。范围裁决归 #243 | 明确每阶段文件、探针和可开放的能力 |
| S2 | 重要 | 原生草稿、待匹配选择、Host 提交预备记录及持久回执关联未写清创建时点和归属 | 说明点选、编辑、提交时摘要冻结、出站与回执。按提交前后区分恢复入口，保持原属主和后续输入 |
| S3 | 重要 | 预检后可能等待确认或写回查记录，此间另一窗口完成停用。偏好与实际出站缺少共同生效边界 | 同一 Host 串行边界完成最后复验与交付传输。覆盖出站先后两种顺序 |
| S4 | 重要 | 保存未定时，目录和偏好 GET 仍可让其他窗口把旧修订当作可操作结果 | 输出待确认状态，暂停受影响的管理动作、候选和发送，待确认后发布当前值 |
| S5 | 重要 | `scopeEpoch` 随身份及组织变化。同一会话的委派范围 A → B → A、过期与连接失效缺少明确的候选版本 | 按会话失效，撤下旧组，废弃晚到响应和点选 |
| F1 | 重要 | “调用资格”“调用权”“调用权限”混用。“员工目录”容易读成员工名册 | 统一用“调用资格”和“专家目录”。身份和访问证据按员工身份与凭据描述 |
| F2 | 重要 | §3.3 把目录可见、组织内可调用资格、当前会话资格和接单状态合写 | 分开说明管理页与候选的判定范围 |
| F3 | 轻微 | “本机路由”未清楚指向组件所有者 | 使用“Host 路由” |

设计批判核对 Feature Specification Standard、需求及接入方案。结构核对跨章节门禁和状态迁移。风格评审核对术语和表达。原生引用时序以上游固定版本在接入方案中的证据为准。Forge IAM 的鉴权已核对本地源码，目标员工契约和运行行为仍待验证。 [PRD §4](../../../requirements/delegra-experts-prd.md#4-功能需求与优先级) · [接入方案 §2.3](../../../plans/2026-11-18-forge-experts-integration-proposal.md#23-dsh-基线隔离验证) · [插件高阶规范](../../../engineering/dsh-plugin-conventions.md)
