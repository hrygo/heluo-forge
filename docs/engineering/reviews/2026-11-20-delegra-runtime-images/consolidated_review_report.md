## 阻塞项

### B1 · ARM64 公共层保留 `r2` 远端启动所需的 Node

设计 L320 允许改用原生 Codex 包后把 Node 移出公共层。固定 `r2` 的远端启动器在启动 `paperclip-runnerd` 前执行 `node -e`，子进程身份登记也依赖 Node。无 Node 的镜像可能通过容器内 Codex stdio 冒烟，实际冷启动会在 Codex 启动前失败。保留能从执行环境 `PATH` 解析的 Node，按调用路径决定 npm 和开发工具的层归属。精简候选用实际远端冷启动、进程身份、取消与回收验收。源码定位为 `server/src/services/native-runtime/native-session-executor.ts` L12018–12036、12438–12463、14257–14279。 [设计 §9.2.2](../../../design/delegra-runtime-images.md#922-保留能力并控制体积) · [初步评审](zoom_out_report.md)

### B2 · 确定原生 ARM64 Runner 路径并验证实际制品来源

任务 2（L217–227）尚无可直接配置的目标组合。固定 `r2` 的 Daytona 接缝可传镜像或快照，实际 ARM64 支持待验。Kubernetes 领用传入 `imageOverride: null`，Job 正常入口需要 `paperclip-agent-shim`，与 `paperclip-runnerd` 参考配方有不同启动要求。Native 对预装 Runner 有制品身份校验及外置路径，Codex 的远端兼容区间宽于固定版，部分配置可使用显式路径或 npm 安装。

先记录实际部署版本、提供方、模式、镜像选择字段、ARM64 节点及试验制品源，再冻结部署配方。用同一正常调度入口启动两个不同镜像摘要，或核对不可变快照和来源摘要。验收记录实际执行的 Runner 与 Codex 来源、SHA-256 和版本。固定 `r2` 预装路径验证控制端与镜像的同一 ARM64 Runner 制品，以及缺失预装件、制品错配和非指定 Codex 版本时的结果。依赖源不满足时记录阻塞和补齐范围。 [设计 §6.3](../../../design/delegra-runtime-images.md#63-delegra-如何选用镜像) · [实施就绪度评审](implementation_readiness_report.md)

### B3 · 企业接入先取得可核对的范围和目标网关准入

设计 L53 已指出现行基线的限制。需要将接入方案的阶段 0、可信 DSH 提交和 Delegra 受限员工入口列为任务 3 的确切前置。网关目标契约绑定受管宿主客户端标识，`/responses` 属协议面，客户端 V1 的验收端点另有范围。现阶段的网关侧令牌绑定也有主体比对的证据边界。

以范围决定及基线回写、实际员工入口、网关认可的远端 Harness 标识和来源、开放的 `/responses`、IAM 受众和身份比对阶段作为企业联调输入。正常请求核对实际发起用户及用量。负例包括未准入客户端、错误来源、错配或缺少凭据。合成环境验证可以独立完成。 [需求基线 §2](../../../requirements/requirements-baseline.md#2-范围边界唯一真源) · [接入方案 §6](../../../plans/2026-11-18-forge-experts-integration-proposal.md#6-恢复后的阶段与验收) · [网关契约 §4.1](../../../contracts/gateway-contract.md#41-身份用途与凭据) · [网关契约 §4.4](../../../contracts/gateway-contract.md#44-服务端点契约与流式协议)

### B4 · 双凭据使用专属交接通道及明确的隔离边界

L126–130、233–245 期望只让本次 Harness 使用个人 Key 与 IAM access token。固定 `r2` 的控制端 transport 和 Rust Provider 现有继承名单未覆盖拟用的 IAM 私有凭据通道。Daytona 普通远程执行会将环境值编入送给提供方的命令文本。任务工具的环境继承策略也仅覆盖其自身控制范围。

确定目标提供方的私有投递能力、可信 Provider 配置来源、任务与运行代次绑定和隔离单元，再列从员工受理、持久派发、取用引用、控制端 transport 到 Runner 的完整接线及错误语义。合成双凭据从正常入口测试，只允许对应 Provider 向认可网关发送。检查调度投影、普通任务环境、提供方命令、工作区、进程、出站网络、诊断、日志和产物。 [设计 §6.4](../../../design/delegra-runtime-images.md#64-dsh-网关授权交接) · [固定版本源码对照](implementation_readiness_report.md#固定版本源码对照)

### B5 · 在 Harness 存活时阻断失效授权的新请求

L125–141 在派发、取用及启动复验授权，未定义已启动 `app-server` 持有双凭据后的新调用控制点。关闭引用只控制后续领取。任务取消、任务授权先于 access token 到期、Host 退出或切换、Runner 失联等情况需要分别定义权威状态、执行点及收敛时限。

先测能否复用可信任务租约和出站控制达到要求，再评估新增中转及其可用性、网络开销和流式透传成本。验收让进程在首个推理后继续存活，验证各失效事件及时阻断后续模型请求，在途流按契约处置，并核对其他获权运行及已发生的实际计量。企业时限以目标契约和实测为据。 [设计 §6.5](../../../design/delegra-runtime-images.md#65-排队失败与回收) · [网关生命周期](../../../contracts/gateway-contract.md#411-生命周期与失败约束)
