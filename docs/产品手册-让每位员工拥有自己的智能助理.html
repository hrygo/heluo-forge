产品手册

让每位员工拥有
自己的智能助理

河洛以智能个人助理为核心。员工在自己的 AI 工作台查资料、跟待办、接续工作，也能把专业任务交给获授权的专家。智能研发是这位助理面向研发岗位的专业场景。

01 · 产品价值

河洛解决什么问题

同一件事的通知、待办和审批状态往往分散在邮件、群聊、OA 和业务系统里。员工要找齐资料、重新交代背景，企业则要确保 AI 明确代表谁、能访问什么、哪些操作需要本人确认。

01
让工作接续起来
从一封邮件、一次讨论或一条业务待办出发，助理找齐相关信息、标明依据并整理下一步。跨天跟进时，可以按个人设置接续工作。
02
让助理适配不同岗位
企业可按办公、人力、合同审批、研发等场景装配能力。员工沿用同一个入口，既有系统继续提供业务数据、规则和流程。
03
复用企业已有投入
身份、权限、模型预算和审计沿用已有管理体系。岗位知识可沉淀为 Skill，工具可通过标准接口复用，随模型和工作台演进继续发挥作用。

02 · 个人助理

智能个人助理怎么用

以下场景描述蓝图中的目标体验。交办、查询及执行均遵循员工授权和企业规则。

从邮件和群聊整理周会待办

助理通过 dsh-mail 使用你获准访问的 Coremail 邮件。你可以在工作台与同事单聊或群聊，也可以主动选择有权查看的聊天片段，生成仅本人可见的总结。

企业聊天产品方案

你交办

“找出本周和这个项目有关的邮件，把待办按事项、责任人和截止时间列出来，附上原文依据，帮我起草一封确认邮件。”

工作台汇总与确认
助理交付与确认

助理把你选定的讨论内容和获授权的 OA 待办一起整理，标出仍需核实的事项。你核对收件人、正文和附件后，确认发送邮件。

跨周接续，离开电脑也能交办

个人记忆基于 Hindsight，帮助助理延续工作偏好和任务脉络。你可以选择采集方式、查看或删除记忆，并控制助理何时使用。

员工个人记忆方案

在工作台

“按我常用的周报格式，接着梳理上次留下的三项待办，用最新通知核对进度。”

在企业 IM

“整理今天的项目跟进记录，把待确认的事项发回这个会话。”

跨端委派与回传
处理与边界

企业 IM 的智能助手把任务交给你授权的桌面 DSH，进展、确认请求和结果回到 IM。与同事聊天和交办自己的工作各有独立入口。

03 · 专家智能体

让专家智能体连接企业业务系统

遇到专业制度、审批流程或业务系统问题时，先查看可用专家的职责及权限，再用 @ 选定一位，写清任务和所需资料。个人助理发起委派，呈现进展，返回结论和来源，方便你核对或追问。

04 · 智能研发

智能研发是个人助理的专业场景

研发人员沿用个人助理的沟通、资料整理和任务接续能力。涉及代码交付时，工作台装配 DevOps、Gitee、企业 Skill 和 Teamflow。

你交办

“先查清这条订单校验 Issue 的所属变更、代码仓库和验收条件。信息齐全后按团队规范实现，给我测试和审查结果。”

Issue 交付模型与受控研发目标

  1. 确认交付范围

    助理在授权范围内通过 DevOps 和 Gitee 核实系统变更、关联仓库和验收要求。关联冲突或条件有歧义时，由你确认。跨仓库任务按可独立验收的 Issue 拆分。

    DevOps Gitee

  2. 执行并验证

    信息充分的 Issue 可直接作为交付依据。企业 Skill 提供团队规范，Teamflow 按任务复杂度和风险组织必要的设计、实现、本地验证和独立 AI 审查。

    企业 Skill Teamflow

  3. 核对实际交付

    你根据实际代码版本、测试和审查结果决定是否验收。远端写入遵循实际开放范围、企业规则和服务端权限，推送逐次确认。

    本地验证 逐次确认

05 · 技术架构

按蓝图理解技术架构

日常助理和研发流程共用员工的个人工作台和企业接入边界。研发流程展示了同一位助理怎样通过工具、规范和流程适配专业岗位。

L1 · 入口层个人工作环境
DeepSeek Harness（DSH）提供员工交办、核对资料、确认操作和获取结果的工作台。河洛沿用官方宿主，通过公开接口装配插件，面向 Windows、macOS、银河麒麟和统信 UOS 等工作终端。
L2 · 能力层个人助理及岗位能力
助理组织邮件、记忆、日常办公与专家协作。研发场景在同一助理上叠加企业研发工具和工作流，其他岗位可按业务场景接入专家及其工具。
L3 · 协同层企业 IM
同事沟通侧连接单聊、群聊和个人总结。远程交办侧连接企业 IM 智能助手和员工的桌面 DSH，传递任务、进展、确认请求和结果。
L4 · 生态层能力发现与分发
AIHUB 聚合 MCP、Skills、CLI 和插件目录。Nacos AI 注册中心负责 MCP 注册与发现及 Skills 注册与获取。AIHUB 提供经策展的插件版本索引，DSH 原生市场提供安装入口，企业私有 npm 提供制品。
L5 · 治理层企业接入与控制
企业 IAM 管理身份及授权生命周期，AI 网关负责模型准入、路由、限流及个人和团队预算。终端保护凭据，通过策略、沙箱和人工确认约束助理操作。业务系统在服务端执行资源权限，审计记录重要动作与决策。
L6 · 底座层企业系统与服务
DevOps 和 Gitee 提供研发数据，Coremail、企业 IM、OA 及可扩展接入的 HR、合同审批系统提供业务记录与流程。Hindsight 提供个人记忆服务，Delegra 承载专家配置和任务执行，DSH 插件提供员工侧的发现、委派和结果呈现。
端到端调用示例 · 查询 OA 申请
  1. 1DSH 选择办公流程专家
  3. 2个人助理发起委派
  5. 3工具在授权范围内查 OA
  7. 4AI 网关执行访问控制
  9. 5状态与出处回传工作台

以查询 OA 申请为例，员工在 DSH 选择办公流程专家，个人助理发起委派。专家在授权范围内通过工具查询 OA，助理把 OA 返回的流程状态和出处带回工作台。企业 AI 网关对其中的模型调用执行模型访问控制。

企业治理目标

终端加密托管 个人 / 应用凭据隔离 生产正文零留存目标 最迟 5 分钟撤权验收目标

终端加密托管凭据，网关核验个人凭据及人员归属，个人与应用凭据及用途隔离。高风险动作须确认，关键决策保留审计记录。生产网关以业务正文零留存为验收要求。

当前设备退出时，工作台停止该会话的企业调用。企业侧须验证从 IAM 实际停用或网关实际封禁起，最迟五分钟拒绝受影响的新模型请求。关键授权或安全条件无法确认时，相关企业能力停止开放。

06 · 进展与推广

当前进展与推广路径

首批推广以 Windows 和银河麒麟 ARM 工作终端为主，从真实研发任务切入，帮助员工把需求梳理、代码验证和交付验收串起来。智能邮件提供日常使用入口。后续按岗位需要扩展个人记忆、跨端协作和专业系统接入。

实施与推广方案

智能个人助理邮件已完成 · 其余扩展中
智能邮件（dsh-mail）已完成，支持 Coremail 邮件检索、待办整理、日报和回复草稿，员工确认后可发送。个人记忆、企业聊天、IM 远程交办与 OA 办公是后续扩展方向。
智能研发与企业治理主体基本完成
主体能力已基本完成，覆盖 DevOps 与 Gitee 接入、围绕 Issue 的研发交付，以及企业身份、模型访问和操作管控。
企业能力生态大部分完成
大部分能力已完成。AIHUB、Nacos AI 注册中心和 DSH 原生市场共同支撑企业工具、技能和插件的发现、获取与分发。
专家智能体后续扩展
后续通过 Delegra 扩展专家委派，以插件对接 OA、HR、合同审批等既有业务系统，按场景提供专业查询与协作。 专家接入方向

资料出处与要点
《河洛企业级智能研发平台总体架构设计》§3.1、§4.1
通过公开扩展机制复用企业规则和工具。身份、模型和业务资源分别由对应服务裁决。

单聊、群聊优先与现有企业 IM 互通。员工主动选取聊天文字，个人总结仅本人可见。
《员工智能助理个人记忆产品方案》
员工设置记忆采集方式，管理自己的记忆，并控制助理是否可以调用。
《Forge 专家智能体产品需求文档》与《Forge 专家智能体接入方案》
员工选定专家后，由个人助理发起委派、跟踪任务并综合结果。具体系统接入取决于业务范围和授权。
《河洛企业级智能研发平台需求与场景基线》§2、§2.3
研发以 Issue 为交付单元，保留实际代码版本、本地验证和独立审查证据，由用户验收。企业研发工具以只读查询为接入基线，受控写入按对应规则开放。
《AI 网关契约》
网关承担模型访问、用途校验和配额控制。生产正文零留存与五分钟撤权属于联调验收目标。
《企业插件市场（轻量原生索引模式）》
AIHUB 提供版本索引，DSH 原生市场提供安装入口，企业私有 npm 提供制品。
《企业级智能研发平台推广实施方案》
首批推广从真实研发任务入手，观察员工首次使用和持续使用的体验，为后续岗位场景扩展提供依据。
