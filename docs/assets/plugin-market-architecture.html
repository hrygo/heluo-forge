企业插件市场：整体功能架构

市场 = 一个 DSH 插件 + 一条自动流水线。用户看到的是插件，背后是“名单 → 检查 → 索引 → 官方安装”。

DESIGN-007 V1.2.0 · DESIGN-012 V1.1.3 2026-10-21 目标未实现 · 企业接入未验 接口基线 DSH 0.2.1-rc.2

01它是什么

四块组成，只有第一块是 DSH 插件

市场不是一个新服务，也不是单独一个插件：
它是“市场插件 + 静态索引 + 企业 npm + 官方安装器”的组合。

组成是不是 DSH 插件作用谁提供
@heluo/forge-market 是：Host + Web Client 企业目录的唯一入口：市场页面、安装/更新操作、agent 工具 平台组，随企业 DSH 发行预装
原生索引 + policy/evidence + current 否：静态文件 目录、检查证据、短时安装开关 CI 生成，内网 HTTPS 托管
企业私有 npm 否：企业服务 唯一包体来源，同名同版本不可变 企业仓库 / IT
pluginManager + pnpm 否：DSH 内置 真正执行安装、写入 profile DSH 本体
一个前提：市场插件需随企业发行或由 IT 预置到 profile，不能由市场自己安装自己。profile 里没有它，就要走企业软件分发，而不是“先在市场里装市场”。

02一条主链路

从左到右：谁做、做什么、交给谁

管理员 / 平台

名单与基线

源地址 + 精确包名；每 profile 一个 registry 与目标矩阵。

CI 生成器

自动检查

自包含、双端交集、真实包与显示资源、完整性；不逐版审批。

内网静态托管

索引与开关

不可变快照 + current；校验完整后原子切换。

市场插件 + Host

写前授权

no-store 读当前开关，核 revision/矩阵/单源/版本。

官方 manager / DSH

安装与运行

精确版本安装；分阶段确认到 Host 激活、Client 可用。

60 秒单次准入决定有效期
15 分钟控制许可最长有效期
5 分钟既有 CI 轻量续期
1 个源每 profile 规范 registry

60 秒／15 分钟／5 分钟是本方案约束，不是 DSH 原生字段。原生 format-1 索引只承载版本与入口信息，不含 integrity/OS/policy 字段；完整性、来源、检查结论在独立 sidecar。索引只筛目录，不是强制白名单。

03开发者怎么装插件

入口只有一个：插件页的市场面板，或对 agent 说“装 X”

  1. 进入：「插件」页 → 企业市场；或直接让 agent 安装。
  2. 浏览：名称、来源（内部/镜像）、版本、兼容矩阵、检查状态。
  3. 选择：默认最新合规稳定版；也可选仍合规的旧版。
  4. 安装：点按钮即可；授权检查在后台完成，正常无感。
  5. 执行：看到真实阶段，而不是一个转圈直到结束。
  6. 完成：已可用、需重启 DSH，或失败原因；更新/回退也走这里。

系统在后台做什么

  1. no-store 取 current，核对 revision、矩阵、单源、精确版本。
  2. 判定有效期 = min(60 秒, expiresAt)，过期/不可达直接拒写。
  3. 调官方 installBundle 精确 spec；不自动补 peer、不放行脚本。
  4. 分段核对：取制品 → 包安装 → 启用保存 → Host 激活 → Client 可用。
断网或授权过期时：可看缓存目录，但不能新装。更新是“移除 → 重判 → 安装”，失败会显示“旧版已移除、需要恢复”。

04开发者怎么发布插件

没有“上传”按钮：发到企业 npm + 管理员登记包名，之后自动上架

做包 开发者

  • 在固定 Gitee group 建仓（需管理员批准）。
  • 做成自包含、双端可用：无外部运行依赖、peer 只用基线、无终端脚本/编译。
  • 补 en/zh meta、授权 icon、exports/files、patch。
  • 由企业流水线发布到企业 npm 内部 scope，附 commit/build 证据。

登记 管理员

  • 把精确包名加入 packages，origin: internal。
  • 一次性动作；之后发新版不用再找管理员。
  • 公网镜像包以 origin: public-mirror 登记，不需要内部 Gitee。

上架 CI 自动

  • 发现稳定版 → 自动检查 → 生成索引与证据。
  • 原子切换 current，市场可见、可安装。
  • 新版本重复“发制品”即可；撤回时先发拒绝快照关闭安装。

被拒会给具体原因（外部运行依赖、麒麟目标失败、缺 icon 等）；修正后发新版本。登记名单不等于任何版本获准，发布成功也不等于自动上架。

05四条边界

这四条不能用索引、缓存或 UI 隐藏替代

浏览 ≠ 授权

目录缓存、fetchedAt、pnpm 缓存都不能授权安装；每次写入前都要在线确认当前开关。

索引 ≠ 强制白名单

原生任意 spec、本地/Git/tarball、CLI、其他市场未全部证伪前，只开放浏览，不算门禁通过。

撤回分三层

目录不可装、取包被阻断、已装代码处置是三件事；删索引或 npm deprecate 不等于后两层完成。

物理边界在企业侧

registry ACL、内网与终端策略承担真正阻断；不承诺防恶意本机管理员，也不承诺远程卸载已装代码。

目标能力 企业待核验 失败关闭 图中「目标」均未实现；企业产品、CA、双端矩阵与全通道控制仍待 G1/G2 取证。
