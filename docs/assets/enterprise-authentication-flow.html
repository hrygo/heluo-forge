DSH 企业统一认证与模型访问交互说明

职责边界、总体架构及登录、调用、刷新、异常与退出流程

定位目标方案说明，不代表企业接口已实现或通过联调核对日期2026-10-20

DSH 认证插件负责客户端授权流程与令牌生命周期管理。 IAM 负责用户认证和令牌签发。 AI 网关负责令牌验证、模型访问控制和额度管理。 三者分工协作，不构成依次转发模型内容的代理链。

A

职责与术语：先明确各方承担什么

核心关系

认证与授权控制面：DSH 认证插件与 IAM 交互；AI 网关按配置获取公钥或查询令牌状态。 模型数据面：DSH 模型适配器向 AI 网关发送模型请求，网关再访问机构内模型服务。 提示词和模型输出不经过 IAM。认证插件不充当模型请求代理。

组件 部署位置与角色 主要职责 责任边界
DSH 统一认证插件 员工本机；OAuth 客户端能力 发起企业授权、校验认证结果、保管凭据、刷新和清理令牌 不保存企业登录密码，不签发企业令牌，不决定服务端最终权限
企业身份与访问管理系统（IAM） 企业服务端；授权服务器；支持 OIDC 时兼任身份提供方 按策略认证用户、决定授权范围、签发令牌、处理刷新与撤销 不转发提示词，不提供模型推理，不计算模型调用额度
企业 AI 网关 企业服务端；受保护资源入口 验证访问令牌、执行模型权限和额度策略、路由及计量 不信任客户端自报身份，不向客户端提供后端访问凭据
DSH 模型适配器与凭据层 本机 DSH 的内部组件 解析受控凭据引用、发起模型请求、处理流式响应 它们不是新的 IAM；模型适配器不应持有刷新逻辑和刷新凭据

认证回答“当前用户是谁”；授权回答“允许该客户端访问哪些资源”。 访问控制由网关结合令牌授权和业务策略执行。 登录成功不代表任意模型、任意额度都可使用。

OAuth 2.0 是授权框架。 OpenID Connect（OIDC）在其上提供标准身份认证结果。 当前尚未确认企业 IAM 是否支持 OIDC。 纯 OAuth 模式须另行约定可信主体信息来源。

本方案控制企业资源接入，不将本地 DSH 的启动视为企业登录。 下文是逻辑流程，不定义新的 DSH API 或已存在的企业端点。

B

总体关系：区分控制面与模型数据面

  • 账户界面展示状态；敏感凭据处理位于本机受控逻辑中。
  • 本机 Host 不等于可以保密的中心后端。 分发到员工终端的固定密钥不能充当可靠客户端秘密。
  • 网关的 JSON Web Key Set（JWKS）是验签公钥集合。 使用有效缓存公钥时，不需要逐次调用 IAM。
  • 令牌内省是网关向 IAM 查询令牌状态。 结构化令牌也可以采用内省，不仅限于不透明令牌。
  • 网关到模型服务的认证方式需单独确认。 不默认将用户访问令牌透传到模型服务。

图中实线突出主要交互；虚线用于辅助交互或返回。 所有跨网络认证与模型调用使用 HTTPS。 本机 loopback 授权回调按原生客户端规范使用 HTTP。

C

初次登录与授权：授权码和 PKCE 详细时序

前置条件： IAM 已登记公共客户端、回调规则及网关资源。 DSH 使用系统浏览器，不嵌入页面收集企业登录密码。 本方案采用授权码与 PKCE S256，绑定每次授权事务。

关键校验与输出

  1. state 与本次本地事务绑定，回调必须匹配。 PKCE 的 code_verifier 不通过浏览器传送。
  2. 使用 OIDC 时，本方案拟生成并核对 nonce。 身份令牌还须按协议核验签发者、签名、受众和有效期等。 nonce 不被当作纯 OAuth 的通用必填参数。
  3. 纯 OAuth 模式使用约定的受保护身份查询等可信来源。 客户端不能将任意访问令牌解码结果当作登录证明。
  4. 回调只携授权码和必要事务信息。 访问令牌、刷新令牌不进入回调 URL、日志或模型上下文。
  5. 用户取消、事务超时、绑定或校验失败时，本次授权失败。 不保存本次失败凭据，不将其标为成功。

具体授权地址、回调端口规则及资源表示由 IAM 契约确认。 client_id 是客户端标识，不是保密凭据。

D

每次模型调用：令牌验证、授权与额度检查

前置条件： 客户端取得面向 AI 网关的有效访问令牌。 模型适配器通过受控引用读取令牌，再调用网关。 网关对每次请求独立执行服务端访问控制。

验证、授权与计量是三个不同步骤。

  • JWT 验证按已确认规范检查签名、算法、签发者、受众及时间。 访问令牌须面向网关，不能用客户端身份令牌替代。
  • 内省须取得可信有效状态和本次访问所需授权信息。 active=true 不替代网关自身的模型访问策略。
  • 内省接口的 HTTP 401 可能是网关自身认证失败。 不得直接解释为被查询用户的登录已过期。
  • sub 是可信主体标识；consumer 是网关预算或成本归属主体。 二者映射来自已确认的服务端规则，不由客户端任意声明。
  • 上图是逻辑顺序，不规定网关内部事务实现。 额度预留、结算及取消后的计量规则仍需网关确认。
  • 只记录必要调用元数据，正文日志默认关闭。 IAM 不接收提示词和模型输出。
E

令牌刷新：合并并发、处理轮换并原子更新

触发条件： 访问令牌已过期，或达到获批的提前刷新条件。 具体有效期、刷新窗口和是否签发刷新令牌均待确认。 本地有效期检查仅用于决定是否刷新，不替代服务端鉴权。 刷新只更新凭据，不自动决定是否重放业务请求。

  1. 刷新互斥范围必须覆盖同一组实际刷新凭据。 多个资源共享刷新令牌时，不能各自独立竞争轮换。
  2. IAM 返回新的刷新令牌时，与访问令牌一并提交。 按轮换契约弃用旧值，避免新旧凭据组合不一致。
  3. 网络失败不等于用户授权失效。 刷新响应丢失时，也不能假定重用旧刷新令牌安全。
  4. 所有退出分支都要释放锁；刷新设置总超时。 用户已退出或切换账号时，不允许旧刷新结果重新写回。
  5. 对公共客户端，RFC 9700 要求刷新令牌采用轮换或发送方约束。 IAM 实际采用的机制、恢复规则及支持范围尚待确认。

刷新凭据只发给 IAM，不发给 AI 网关或模型服务。 令牌在本机尚未过期，也可能已被撤销或不再满足访问条件。 每次请求仍须通过网关的令牌、授权和额度检查。

F

异常与重试：先确定执行状态，再决定处理方式

基本原则： 令牌刷新成功，不证明原请求未执行。 HTTP 状态、网络错误和业务执行状态必须分开判断。

结果 说明 处理边界
401 访问令牌未被接受，如过期、资源不匹配或配置错误 先按契约识别原因；不是所有问题都能靠刷新解决；安全前提成立才重试
403 授权范围或模型权限不足 提示申请或调整权限，不循环登录或自动重试
429 当前契约中的额度耗尽 展示额度层级与恢复信息，不自动重试
503 可信验证或配额等依赖不可用 不冒充用户登录过期；仅可证明未执行时按有界策略处理
超时、取消或断流 请求可能已开始生成或消耗额度 不自动重放；按已确认机制核对结果与用量

请求已执行、已输出或状态未知时，不依据客户端推测重复生成。 查单、去重或结果恢复能力须先由网关确认。 本说明不假定存在任何新的查询端点。 用户主动重新发起前，应明确告知原结果可能未知。

G

退出、切换账号与撤销：区分本地和服务端效果

本地退出停止当前客户端继续使用凭据。 服务端撤销影响 IAM 授权及相关令牌。 浏览器 SSO 退出处理 IAM 浏览器会话。 三者不应被描述为同一个动作。

  • 撤销调用须有总超时；失败不妨碍本地清理。 客户端须显示“服务端撤销未确认”，不能冒称全面失效。
  • 是否清除浏览器 SSO 会话、是否显示账号选择，由 IAM 能力决定。 新授权结果不得与旧主体缓存混用。
  • 撤销刷新令牌不必然立即作废已签发的所有访问令牌。 本地删除凭据也不能消除其他位置的令牌副本。
  • JWT 离线验签不天然支持即时撤销。 在线状态、缓存、事件通知或短有效期等策略需联合确定。
  • 已经开始的模型调用如何取消、结算和审计，另按网关契约处理。
H

安全约束、待确认项与依据

凭据或会话 用途与接收方 禁止混用的边界
IAM 浏览器会话 支持浏览器内的身份认证与 SSO 不复制到 DSH 或模型请求中
身份令牌（ID Token，仅 OIDC） 向客户端提供标准认证结果 不用于调用模型 API；不能替代网关访问令牌
访问令牌（Access Token） 授权 DSH 访问指定网关资源 不发给其他目标资源，不写入提示词、URL 或日志
刷新令牌（Refresh Token） 向 IAM 请求新访问令牌 不交给网关、模型、Agent 工具或账户界面
网关后端访问凭据 网关访问模型后端 保留在服务端，不分发到员工客户端

仍需三方确认的契约

确认事项 主要责任方 尚不能假定的能力
OAuth / OIDC、客户端登记、PKCE与loopback规则 IAM、DSH平台组 不能将 OIDC、固定端口或动态端口支持写成已验事实
资源受众、授权范围、可信主体与角色来源 IAM、网关、DSH平台组 不能只靠客户端解码或角色预设完成授权
JWT / 内省、公钥轮换和缓存有效期 IAM、网关 不能承诺离线验证同时具备零延迟撤销
刷新签发、轮换、共享关系和故障恢复 IAM、DSH平台组 不能假定共享刷新凭据可无限并发或任意重试
主体到consumer映射、模型权限及双维度额度 网关及相应业务责任方 不能依赖客户端自报预算归属或本地记账
撤销范围、生效时限、账号切换和在途请求 IAM、网关、DSH平台组 不能将本地退出等同于所有访问令牌立即失效
错误分型、请求关联、安全重试与流式结算 网关、DSH平台组 不能将 401、超时或刷新成功视作安全重放证据
