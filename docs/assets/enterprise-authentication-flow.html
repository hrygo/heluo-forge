A

为什么需要这页

三个系统各自都以为自己不负责的那部分，恰好是事故高发区。开发以为 IAM 会管撤销，IAM 以为网关会校验受众，网关以为客户端不会重放。

因此本页只锁三件事：

  1. 身份真实性由 IAM 负责，网关只验证不推断。
  2. 凭据最小化：客户端只持 IAM 令牌，不持网关 Key，不持模型上游密钥。
  3. 失败可判定：每一种失败都有明确归属与唯一处置，不靠"重试一下"。

阅读顺序建议：先看 C 职责边界与 D 凭据全景，再看 E、F 两条主链路，最后看 L 待确认清单并认领。

C

职责与信任边界

结论：三方的边界按"签发 / 验证 / 记账"切开，任何一方失效都不能被另一方的默认值掩盖。

系统 负责 明确不负责 失效时行为
IAM 身份认证、令牌签发与撤销、角色来源 模型额度、本机准入 取不到有效令牌即不调用该资源
网关 验签、consumer 映射、双维度额度、模型边界 用户身份真实性、客户端策略 kid 未命中返回 503；额度耗尽返回 429
平台开发 登录流程、令牌存储与刷新、工具门禁 企业授权判定 安全依赖缺失即阻断，不静默降级
D

凭据全景

结论：客户端只持两样东西——refresh token，和短期 access token 的镜像引用。网关 Key 与模型上游密钥都不在客户端。

凭据 持有方 生命周期 泄露后果 可否撤销
refresh token 本机受控存储 长期，可轮换 可换新 access token 是，RFC 7009
access token 本机内存与镜像引用 短期，≤60 分钟为要求值 限有效期、限该资源 是，受验签缓存约束
consumer 身份 网关配置 随注册变更 仅身份标识，非凭据 是，改注册
模型上游密钥 仅网关 由网关轮换 客户端不可见 是，网关侧

决策：客户端不持网关 API Key。理由见架构 ADR-2；静态密钥方案作为备选记录在 ARCH-002，未采纳。

E

登录与授权

结论：标准授权码 + PKCE，回调只走 loopback，令牌到手前不写任何本地状态。

步骤 执行方 输入 输出 失败处理
1–2 客户端 用户操作 浏览器会话 用户取消即结束
3 客户端 + IAM client_id、resource、code_challenge 授权码 拒绝即不改状态
4 客户端 回调参数 校验结论 任一不符即丢弃
5 客户端 + IAM 授权码、code_verifier 令牌 invalid_grant 不重试
6 客户端 令牌 受控存储记录 写失败即回滚会话
7 客户端 资源标识 该资源 token 缺资源即不调用
F

首次模型调用

结论：网关只吃一个 Bearer，所有身份从令牌派生；流式返回，正文不进任何日志。

网关侧要求：aud 必须含自身标识、iss 必须为受信签发方、算法在允许清单内、exp/nbf 有效且容差不超过 60 秒（提议值）。

G

刷新与并发

结论：桌面与 Web 两个进程可能同时刷新，必须靠跨进程锁收敛为一次；刷新失败要分清"要重新登录"和"待会儿再试"。

  • 锁内网络请求必须有硬超时，否则本机其他凭据读取会被拖死。
  • 先到者刷新、后到者复用，不允许"两个都刷"。
  • IAM 若做 refresh 轮换，旧值被重用即视为会话失陷，清空并要求重新登录，不重试。
H

工具调用：按资源取令牌

结论：工具链路不共用模型令牌，按 resource 单独取，服务端校验 aud 是否为自己。

形态 凭据来源 校验方 轮换处理
HTTP MCP 按 resource 取 token，经请求头 服务端校验 aud 401 后按未执行边界重试
stdio MCP 进程环境注入 子进程自身 凭据更新即重启子进程
I

失败与重试

结论：先判断"是否执行过"，再判断"是不是鉴权问题"；顺序反了就会重复生成、重复计费。

状态 含义 客户端动作 可重试
401 invalid_token 令牌无效或过期 刷新后至多一次 条件性
403 insufficient_scope 权限不足 提示联系管理员 否
429 额度耗尽 展示 quota_reset 否
5xx / 超时 结果未知 先查单，不盲重放 否
J

退出与撤销

结论：本地退出必须同时清本地状态与通知服务端，否则换人使用时旧会话仍在。

撤销请求失败不阻塞本地退出：本地必须干净，服务端残留按最大有效期兜底并记录审计。

K

存储、日志与边界

项 要求 现状
凭据落盘 优先系统凭据库，回退 0600 并标注 待双端验证
模型上下文 不含令牌、不含凭据文件内容 策略插件硬拒绝 $DSH_HOME/**
日志 只记元数据，不记正文与令牌 网关与模型默认关闭正文日志
审计 主体、模型、结果、耗时 归集在网关，客户端不留正文
L

校验清单与待确认

结论：下表每条都要能判定，做不到就写"未确认"，没有"应该没问题"。

项 要求 责任方 状态
签名算法 白名单，拒绝 none 与对称算法 IAM 发布、网关校验 待确认
受众 网关校验 aud 含自身标识 网关 待确认
时间 exp/nbf，容差 ±60 秒 网关 提议值
吊销 introspection 缓存 ≤60 秒 网关 待确认
键轮换 kid 未命中返回 503，不返回 401 网关 待确认
刷新轮换 重用旧 refresh 按失陷处理 IAM 待确认
资源参数 支持 resource，不支持则按 audience 预注册 IAM 待确认
并发 跨进程锁 + 锁内 5 秒硬超时 平台 待实测

怎么证明这些要求成立

  1. 有效令牌调用成功、过期令牌返回 401。
  2. 伪造 aud 被拒；kid 未命中返回 503 而非 401。
  3. 撤销后在新会话请求被拒（记录实际延迟）。
  4. 两个进程同时刷新只产生一次轮换。
  5. 429 不被自动重试，且展示重置时间。
  6. 退出后本地无残留凭据，服务端撤销成功。
