# PRD — CLI 路径自动发现与插件配置页

## 1. 背景与目标

企业在 Windows 内网实测时暴露的问题不在功能，而在入口：插件要求用户先注入 `FORGE_DEVOPS_DOP_BIN`，否则四个只读工具按 fail closed 直接关闭（`NO_READER`），用户只能退回手工敲 `dop` 命令，插件形同不可用。当前文档也把"设置环境变量"写成前提条件，等于把 CLI 定位这件事转嫁给了普通用户。

这类问题必须在设计源头解决：**普通用户不应知道什么是环境变量。** 目标是让「装好就能用」成为默认路径，让「找不到」成为可自己修好的一次操作，而不是一次排障。

目标（按优先级）：

1. **零配置可用**：`dop` / `gh` 已在本机（PATH 或常见安装目录）时，不设任何环境变量、不改任何文件，安装后只读工具即可工作（Windows 第一优先）。
2. **找不到时可自助修复**：提供**真正的插件配置页面**（Web UI 表单，不是让人改 YAML），让用户选择本地路径；选择结果持久化到活动 profile 配置，重启后仍生效。
3. **环境变量降为兜底**：CI / 无 UI 场景仍可用，但不再是主路径，也不再是唯一路径。
4. **安全语义不放松**：配置缺失仍 fail closed 并如实说明原因；路径与 endpoint 不回显到工具输出/日志/报告；不把本机路径写进版本库；写动作门禁、审计、固定 argv 白名单一律不变。

## 2. 用户故事与验收要点

**US-1（普通开发者，Windows）** 我装好插件、什么都没配，就能让它读系统变更。
- 装完直接问插件读一个变更号，能拿到结构化结果（AC-1）。
- 如果我的机器上同时躺着 `dop.cmd` 和 `dop.exe`，插件不会去跑那个包装脚本（AC-2）。
- 我想知道它到底用了哪个 cli，页面上看得见来源（AC-3）。

**US-2（普通开发者，找不到 cli）** 页面上告诉我没找到，我点一下选文件就好了。
- 错误提示说人话，指向配置页，而不是 `CONFIG_MISSING: FORGE_DEVOPS_DOP_BIN`（AC-5）。
- 配置页 ≤2 次点击可达，一屏能看到 6 个字段和当前发现结果（AC-6/AC-7）。
- 我填错（指到目录、指到 `.cmd`、地址不为 http(s)）时被明确拒绝并告诉我哪一项错（AC-9）。

**US-3（同一个人在换机/重装之后）** 我配过一次的东西不会莫名其妙失效，也不会被悄悄写进代码库。
- 保存后立刻生效，重启后仍生效（AC-8）。
- 仓库里不会多出文件、不会出现我的盘符路径（AC-10）。

**US-4（团队与合规）** 这次改动不能把既有安全边界拆掉，也不能把"能跑"写成"已联调"。
- 门禁、白名单、四状态、幂等、提交信息校验全部回归全绿（AC-14）。
- 每条"已实测"写明命令、时间、宿主版本、来源类型；Windows 实机没跑就标 NOT RUN（AC-13）。

## 4. 范围与非目标

范围内：
- 装配期自动发现（dop / gh 两条），候选与优先级固定、可复查、有界开销。
- 一个真实的 Web 配置页（6 字段表单 + 发现结果可见 + 逐字段校验 + 持久化到 profile 补丁）。
- 失败原因从"环境变量名"改为"类别 + 可操作指引"，fail closed 语义不变。
- 安装/UAT 文档与包 README 的口径改造、回滚步骤、证据表。

非目标（本次不做）：
- **不替用户安装** `dop` / `gh`，不做下载器、打包器或 winget 集成。
- 不改 dop 的接口与字段契约（r2 的 `--json` 口径原样保留），不改 `change view` 的参数形态。
- 不为 `dopEndpoint` 做自动发现（地址无法探测）；不新增凭据管理，`gh` 登录仍走 `gh auth` 自身。
- 不移除环境变量支持，不改环境变量名。
- 不做多 profile 配置同步、组织级统一下发、或无 UI 配置 API（未来可议，本次不做）。
- 不改写动作门禁、审计规则、四状态词表与产物 front matter。

## 5. 反面目标（anti-goals）

**即使测试全绿，出现下列任一情形也应被人判为失败：**

- **AG-1 静默选中了错的那个。** 多候选或候选身份不明时插件自己挑了一个并显示"已配置"，用户第一次真实调用才发现跑到别的程序上（或只得到 `unknown`）。可核对方式：配置页上任何"自动发现"结论都能点开看到命中路径与来源层；存在多个候选时可见地列出备选，不允许选择过程不可见。
- **AG-2 保存成功但仍不可用。** 页面显示"已保存"，工具仍旧 `NO_READER`——值没落到活动 profile、被更高层覆盖，或保存了一个不可执行的路径。可核对方式：保存后 60 秒内不重启即可调用成功；重启后仍成功。
- **AG-3 报错还是环境变量名。** 未找到时提示仍是 `CONFIG_MISSING: FORGE_DEVOPS_DOP_BIN` 这类措辞。可核对方式：让一个没用过本插件的人读这条提示，他能独立走到"打开配置页选路径"这一步；读不出来就是失败。
- **AG-4 把环境变量的痛苦搬进 UI。** 配置页变成 6 个裸必填字段加一屏说明文字，用户仍然不知道该填什么。可核对方式：正常情况下用户只需"看"不需要"填"就能用；只有未找到时才出现"需要你选一个文件"的动作；页面首屏没有必填项。
- **AG-5 路径漏到不该出现的地方。** 报告或日志里出现本机绝对路径 / 内网 endpoint，导致报告不能再转给别人。可核对方式：对报告与日志跑 AC-10 的正则，零命中。

## 6. 交互流程摘要

**正常路径（零操作）：** 安装安装单元 → 装配期自动发现 → 命中 `dop.exe` / `gh.exe` → 只读面 `ready` → 用户直接提问读变更号。

**修复路径（未命中）：** 工具报 `NO_READER` + 一句指引 → 用户开 Web UI 配置页 → 页面顶部显示"自动发现：未找到（已查 J 类位置）" → 用户点"选择文件"或手填绝对路径（也可选清除回落自动发现）→ 保存时逐字段校验 → 写入活动 profile 补丁并即时生效 → 重启后仍生效 → 状态变为 `ready` 且 origin 显示 `config`。

**来源收敛：** 配置页 → 环境变量 → 自动发现，上者覆盖下者，页面标出当前 origin；清空配置即回落到下一层，不需要卸载重装。

## 7. 优先级

- **P0（缺一不可）**：AC-1、AC-2、AC-5、AC-6、AC-8、AC-9、AC-10、AC-13、AC-14 —— 零配置可用、不误执行、可自助修复、可持久、可核对的边界与回归。
- **P1（本轮应做，可在 P0 稳定后补齐）**：AC-3、AC-4、AC-7、AC-11、AC-12、AC-15 —— 来源可解释、开销有界、页面体验、CI 兜底、文档与回滚。
- **P2**：无（本轮不设 P2 项，避免把"能不能用"降级成可选项）。

## 8. 依赖与风险

依赖：
- 宿主配置面：`@deepseek-ai/dsh-settings`（从插件 Config schema 派生可编辑字段与表单写入）+ `@deepseek-ai/dsh-config-editor`（把写入落到活动 profile 补丁，保留 YAML 注释，拒绝陈旧写入）必须在目标 profile 组合中存在；官方配置页（subagent / web search / agent loop / shell）即由同一组合承载。
- 客户端半：本插件当前为 host-only，配置页需要浏览器侧入口（仓库内已有 `forge-iam` / `forge-market` 的 `dsh.client` + `settings.section` 注册先例）。
- 宿主版本：仓库目标 `.dsh-version` 为 `0.2.1-rc.3`，本机实测为 `0.2.1-rc.2`。

风险：
- **R1 profile 未挂配置面**：`settings` / `config-editor` 缺席时表单写入不可用。缓解：配置页检测可写性并可见地说明原因（引导改用环境变量），不静默失败、不假装已保存。
- **R2 自动发现误命中**：同名但不相干的程序被当成 dop。缓解：只认 `.exe`、候选顺序确定、命中路径在页面可见、多候选可见（见 AG-1 与 F1）。
- **R3 Windows 路径与编码**：中文目录、空格、UNC 路径。缓解：只接受绝对路径，作为单个 argv 元素原样传递，绝不拼 shell；页面显示原值不转义改写。
- **R4 宿主 rc.2/rc.3 差异**：client 半装载方式、slot 名称、表单写入行为可能不同。缓解：rc.3 未跑即标 NOT RUN；装载证据以"安装 + 激活 + 工具面 + 页面可用"四段为准，不以 `dump-config` 静态检查代替。
- **R5 既有用户行为变化**：已用环境变量配好的用户，若同时填了配置页，配置将覆盖环境变量。缓解：保持上者覆盖下者并在页面标出来源；默认不改动既有 profile 配置。

## 10. 工程约束

- **分支与提交**：原始需求未给出建分支/提交/打标签的指令，按现状继续——当前分支 `feat/devops-change-flow`，工作区已有 1 处未提交改动（本任务夹 `docs/teamflow/20261029-r3-cli-path-autodiscovery/`，由 host 创建），实现阶段在其上继续，不清理、不回退、不 stash，更不得用 `git reset --hard` / `git checkout --` 覆盖他人改动；提交与推送需当次明确授权，本 PRD 不构成授权。
- **`.gitignore` 审计（开发阶段动作）**：现有条目已覆盖本栈噪声——`node_modules/`、`dist/`、`*.tgz`、`logs/`、`.dsh-devops/`、`.env*`、`.idea/`、`.vscode/*`、`*.local.json`。本需求若引入运行期发现缓存或临时文件，**必须落在 `$DSH_HOME` 之下**，并在 `.gitignore` 补对应条目；同时保证实现后 `git status --short` 不因运行插件而多出文件。
- **不写本机绝对路径**：测试夹具、文档示例、页面文案一律用通用形态或 `corp.example`；证据里需要指代路径时写"用户本机 dop 路径"而不贴实值（与 AC-10 同源）。
- **测试**：新增/修改必须带离线用例并进入 `node --test` 自动发现范围；Windows 专项行为（PATH、PATHEXT、`.exe`/`.cmd`）用可注入的平台/文件系统桩覆盖，实机结论另行标注来源类型。
- **不新增外部依赖**：企业内网无法访问 registry；client 半为纯 JS，页面不得引用外部 CDN 资源。
- **验证口径**：仓库根 `pnpm check` + `git diff --check`；本地通过不等于远端 CI、企业联调或双端实机已验证。

## 11. 假设与待澄清

**已按仓库既有事实设定的假设（无需用户裁决，供实现阶段对齐）**

- 配置优先于环境变量：沿用既有实现（装配层的显式 camelCase 配置覆盖环境解析），本次只在其后追加"自动发现"层。
- 只做 `.exe`：因为固定 argv 的 `execFile` 在 `shell: false` 下无法执行 `.cmd`/`.bat`，放开它们等于重新打开 shell 通道，与基线 AC-22 冲突。

- 工具面维持 9 个不变，配置页只写配置，不新增工具/命令。
