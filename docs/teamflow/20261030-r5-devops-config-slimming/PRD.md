# PRD — 企业 DevOps 配置页瘦身（去 .exe 后缀 / 改名 / 移除连接与事实来源）

## 1. 背景与目标

配置页（`packages/forge-devops/client.js`，宿主 `settings.section`）当前的 6 个字段里，只有两个路径字段是普通用户真的能判断的。`dop 服务地址`、`gh 组织 / 用户` 要用户知道自己所在企业的服务地址与组织名；`事实来源（mock / enterprise）` 更是把「这批结论算不算企业实测」的判断推给了最没有依据的人。用户在内网试用后指出四处，并明确选了「两块都删，只留路径与超时」。

这类问题必须在产品面解决而不是靠文档解释：**页面只问用户能回答的问题，机器能推导的由机器推导。** 同时这是一次"减法"，减掉的部分不能顺手带走既有能力——自动发现、保存即重建、逐字段报错、写回 profile 补丁层的行为一项都不能回退。

目标（按优先级）：

1. **页面上只剩能判断的三项**：dop 可执行文件、gh 可执行文件、超时（毫秒）；能自动发现时用户什么都不用填。
2. **文案去术语后缀**：用户可见文案不再出现 `.exe`（占位符、帮助句、包装脚本拒收句、en 镜像），实际路径值不改写。
3. **身份改名**：侧栏条目与页面标题统一为「企业 DevOps」，工具失败指引同源同句，不出现"按指引找不到入口"。
4. **事实来源由后端推导**：优先显式配置，其次环境变量，最后按入口就绪情况推导；普通用户既看不到也不需要判断。
5. **零回退**：自动发现、保存增量、409/422、补丁层写回与隐藏键保留全部保持 r3 行为。

## 2. 用户故事与验收要点

**US-1（企业内网普通用户，装好就打开设置页）** 我只想告诉插件 dop 和 gh 在哪，别的别问我。
- 页面上只有两张入口卡与一个超时，没有服务地址、没有组织限定、没有事实来源（AC-2）。
- 自动发现命中时我什么都不用填，页面直接显示"已找到"（AC-4）。
- 侧栏叫我点进去的那个名字，和我看到的标题是同一个（AC-1）。

**US-2（同一个用户，装之前先扫一眼文档/文案）** 我刚从 Windows 资源管理器复制路径，文案别让我对着 `.exe` 猜。
- 占位符只说「粘贴 dop 的完整路径」，帮助句说"右键 dop →复制文件地址"，不写 `.exe`（AC-3）。
- 我要是错选了 `.cmd`/`.bat`，它明确说"请指向可直接执行的文件"，而不是让我去分辨后缀（AC-3、AC-6）。

**US-3（配过一次的老用户 / 企业侧运维）** 我以前的配置不能因为我打不开那两项就消失。
- 保存后我原来的 `dopEndpoint` / `ghOwner` / `sourceType` 原样留在 patch 里（AC-5）。
- 我仍可用环境变量或配置文件设这三项，非法值照样被拒且给原因（AC-6）。
- 我声明的 `sourceType` 压过推导；没声明时由插件按入口就绪情况推导（AC-7）。

**US-4（验收方 / 合规）** 减字段不能把证据纪律减掉。
- 推导不得把 mock 结果标成企业实测：缺 gh 或缺 dop 时结论必须是 mock（AC-8）。
- 只读信封、来源列表、补丁层、HTTP 契约的形状与状态码不变（AC-9）。
- 本轮属组件级 mock 实测，真实浏览器走查没跑就标 NOT RUN（AC-13）。

## 4. 范围与非目标

**非目标**：

- 不动门禁、命令白名单、写动作四状态/幂等/回读、审计、提交信息校验、`[变更号]` 边界（r1 语义一行不改）。
- 不在页面新增任何设置项，包括"事实来源"的只读回显。
- 不改补丁层键名、存储位置、重置即整段删除的回滚流程（r3 AC-15 保留）。
- 不改 `dopEndpoint` / `ghOwner` / `sourceType` 三个键的服务端语义与环境变量名，不删除契约字段。

## 5. anti-goals / 反面目标

1. **页面还在问用户判断不了的事**：改完仍能看到服务地址、组织限定或事实来源任一项（哪怕是只读灰显的"仅展示"）——测试可以全绿，但用户打开页面照样不知道该怎么填。核对：页面文本对「dop 服务地址」「gh 组织」「事实来源」「mock」「enterprise」零命中。
2. **去 `.exe` 去过头**：把真实路径里的 `.exe` 一起改写，或顺势让自动发现接受 `.cmd`/`.bat`，Windows 上静默选到包装脚本、运行时启动失败。核对：路径值与候选文件名逐字回显不变；包装脚本拒收用例仍全绿；`shell:false` 仍无 `shell:true`。
3. **改名只改一半**：侧栏叫「企业 DevOps」，工具失败提示还写「设置 → DevOps 变更流程」，用户照指引找不到入口。核对：运行期字符串与用户可见文案对旧名零命中（历史任务夹除外）。
4. **隐藏键被静默清空**：保存一次后 profile 里原有的 `dopEndpoint` / `ghOwner` / `sourceType` 消失，企业侧依赖的服务地址与仓库范围悄悄失效，而页面看起来"保存成功"。核对：保存前后补丁层 diff 只含改动字段，三键逐字不变。
5. **推导过度声称**：只找到 dop 就给出 `enterprise`，把本机 mock 结论写成企业实测。核对：缺 gh 的桩态下只读信封 `sourceType` 恒为 `mock`，来源列表同。

## 6. 交互流程摘要

1. **进入**：首页 → 左下「设置」 → 侧栏「企业 DevOps」（两次点击）；标题同为「企业 DevOps」。
2. **只读态（默认）**：标题 + 一句引导「插件会自己找 dop 与 gh；只有找不到时才需要你指定位置」+ 状态行（ready/missing/unavailable，附 dop/gh 来源）+ 两张入口卡（只读展示命中路径、origin 标记、候选数）+ 「命令行入口」分组下的超时行 + 保存按钮（未改动时禁用）。
3. **编辑态**：任一入口卡「改为手动指定」或直接改超时 → 保存可用；入口卡 blur 即校验（存在、非目录、非包装脚本、长度），超时 blur 校验区间。
4. **保存**：POST 增量字段 → 200 回新快照（状态行更新、脏态清零）/ 409 提示"配置已被其它窗口改动 · 刷新后重试"/ 422 聚焦首个非法字段并逐字段显示原因；补丁层未涉及的键保持原样。
5. **回落**：入口卡「重置为自动发现」→ 保存后该键从补丁层移除；两键都重置即整段删除，回到"未配置即自动发现"。
6. **事实来源**：页面全程不出现；由后端推导（显式配置 > 环境变量 > 入口就绪推导）并只在只读信封与来源列表中体现，供证据核对使用。

## 8. 依赖与风险

- **依赖 r3 基线链路**：装配期自动发现、`GET/POST /api/forge-devops/cli`、`buildCliPatch` 写回 profile 补丁、409/422 语义、回滚步骤均按原样复用，本需求只删页面字段并新增一处推导。
- **风险 1 · 推导误判**：把入口指到本机 mock 脚本时推导会给出 `enterprise`。缓解：判据取"宁可少标"的双入口；显式 `dopEndpoint`/`sourceType` 仍可纠偏；证据表仍以人工标注为准。若要求零误判，需引入显式企业指纹（另开需求）。
- **风险 2 · 隐藏键静默清空**：客户端误发 `null` 或保存逻辑整段覆盖。缓解：请求体字段断言 + 补丁层 diff 用例（AC-5）。
- **风险 3 · 改名遗漏**：`CLI_PAGE_HINT`、README、测试文案、en 字典各写一处。缓解：`CLI_PAGE_HINT` 单点断言 + 旧名全库 grep（AC-1、AC-10）。
- **风险 4 · 可发现性下降**：页面不再提供地址/组织入口，用户不知道还能用环境变量。缓解：README 表格标注 + 工具失败文案给键名（不含值）；本页不新增解释段落（避免又把术语搬回页面）。
- **风险 5 · 去后缀后的歧义**：Windows 上 `dop` 与 `dop.cmd` 常同名共存，用户可能选到包装脚本。缓解：拒收句明确"请指向可直接执行的文件"；候选卡仍显示真实文件名与路径。
- **风险 6 · 测试连带修改面大**：client-shape / client-rule-parity 中"六字段"断言成组存在。缓解：约束为"改写不删除"（AC-12），改后用例数只增不减。

2. **M2 保存与校验收敛**（AC-5、AC-6、AC-9）：确认隐藏键零丢失、服务端不放宽。

5. **M5 回归与人工补测**（AC-12、AC-13）：`pnpm check`、真实浏览器走查（未跑即 NOT RUN）。
