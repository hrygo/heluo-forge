# 企业研发设置与 IAM 正式 UI 设计

## 0. 视觉与观感意图（实施先读）

**意图：像现有宿主设置，而不是新增企业管理门户。** 新增总览采用紧凑分项清单，只有编辑字段与操作按钮形成视觉重心；IAM 原页继续采用已有卡片，不重绘、不新增品牌。以下为本轮新增总览/配置分区规格，不覆盖已有 IAM 样式及旧 DevOps 页度量。

### 0.1 表面、字体与密度

| 组件类 | 可实施规格 |
|---|---|
| 页面 | 继承宿主字体、背景与水平内距；width:100%、min-width:0，不加整页卡片、阴影、渐变或发光；区块间距16px |
| 标题/说明 | 标题16px/500/24px；分区标题13px/500/20px；字段13px/500/20px；正文/提示12px/400/18px；标签11px/400/16px。正文用 `--dsw-alias-label-primary`，说明 secondary，补充信息 tertiary；关键阻塞原因不得只用 tertiary |
| 分项清单 | 行 padding:12px 0，行间0.5px solid `--dsw-alias-border-l2`，首行无分隔线；无圆角外框、无行悬浮底色、无整行点击。标题、状态、下一步分层，具体按钮可点击 |
| 说明/回执面 | padding:10px 12px；`--dsw-radius-md`；底 `--dsw-alias-interactive-bg-hover`；无阴影。错误面加1px error 混色22%边框；不得仅靠红底表示失败 |
| 输入框 | 高34px、水平内距10px、1px `--dsw-alias-border-l4`、`--dsw-radius-sm`、透明底；13px/20px；只读用 readonly、不用 disabled，以便选择复制；超时宽220px/max-width:100% |
| 主/次按钮 | 最小高32px，padding:6px 16px，文字12px/500/18px，边框1px计入盒模型；主按钮底 `--dsw-alias-state-business-primary`、字 `--dsw-alias-label-primary-inverted`；次按钮透明底、border-l4；圆角sm；本分区只有一个主操作 |
| 状态标签 | min-height:22px，padding:2px 8px，1px边框，圆角sm；11px/16px，6px点、gap:5px。成功/警告/错误用 `--dsw-alias-state-success-primary` / warn-primary / error-primary；背景对应色10%、边框22%；未知/过期用中性底及明确文字 |
| 来源/版本/时间 | 12px/18px；数字 tabular-nums，版本标识可用 ui-monospace；允许断行；不通过截断隐藏“未知”“已过期”或操作结果 |

所有新样式使用 box-sizing:border-box。标签最小高度核算：16文字+4内距+2边框=22px；按钮18+12+2=32px。标签无固定宽度，长版本另占一行，长中文状态可换行并增长高度，不塞入定宽徽章。输入可水平移动光标查看实值，但只限获准编辑上下文。圆角直接用宿主token，不假定其当前像素值。

### 0.2 反馈与动效

- 按钮 hover：主按钮 opacity .92，次按钮底 interactive-bg-hover；pressed opacity .86，无位移；100ms `var(--ds-ease-in-out)`。禁用 opacity .4、无hover/pressed，旁边显示禁用原因，不让原因只存在于tooltip。
- 输入 hover 边框变 border-l3；focus 边框 business-primary；所有交互元素 focus-visible 为2px business-primary outline、offset:2px；invalid 边框error+关联文本原因。上述过渡100ms，无抖动。
- 折叠按钮 hover 改 label-primary，箭头旋转180deg/100ms；展开内容 opacity 0→1/160ms，不动画高度。非交互行无hover反馈，避免误导。
- 加载用与目标分项数量一致的静态骨架条，行最小高72px；可选1.2s opacity 1↔.55呼吸。加载文字始终可见，不以骨架代替“正在读取/检查中”。加载慢时保留标题及已有结果并标“正在更新”，禁止把旧结果伪装成当前结果。
- 完成后就地保留回执直到下次修改/操作，不用自动消失的toast承载唯一证据。错误、未知、空态均使用对应行的原因+下一步，不画插图；退出无额外动画。reduced-motion关闭呼吸、旋转和过渡，瞬时替换。
- 无画布、游戏对象、hit-flash或庆祝动效。任何状态下，分项名称、状态文字、“不代表业务授权”持续可见。

### 0.3 本产品明确禁止

不做大号总绿灯、百分比准备分数、模拟账号或维护角色切换；不在总览摆路径/endpoint、原始CLI错误或IAM主体；不把隐藏配置变成“高级设置”；不把保存、应用、检查合成一个含混的“连接成功”。不新增品牌色、字体、龙纹背景或装饰性卡片。未知不涂绿，未配置不自动等同失败；成功标签不得写“企业联调通过”。

## 2. 页面/模块与信息架构

在**现有设置壳**内增加“企业研发”，不建独立网页、不迁移账号入口：

- 企业研发（新增）：准备总览 → 本机差异 → 只读检查 → 公共参数（独立折叠区）。首次只展开总览；本机配置按需展开；错误不强制把维护面全部撑开。
- 企业账号（保留）：现有IAM页面，唯一承载登录/取消/退出、onboarding、个人网关凭据与模型设置。本轮只导航，不复制表单或储存。
- 企业 DevOps（保留）：原有效配置入口继续工作，与新页使用同一真实配置读写能力；不静默改成无配置能力的说明页。跳转若可用则直达对应分区；不可用时在原页保留能力，不猜路由。
- 公共参数（新增分区，默认只读）：来源、版本、作用域、权限依据及维护入口；无可核验权限/作用域/接口时不展示可编辑控件。

“企业研发”及首屏简洁密度采用PRD推荐默认，属于本轮设计建议，不冒称用户已批准入口取代。若技术接线要求删除旧入口或改变既有字段/应用语义，先回报并调整需求，不能自行实施。

## 3. 关键页线框与尺寸

### 3.1 准备总览（默认展开）

```text
企业研发
查看身份、配置与工具准备情况，不代表业务授权。
公共参数：来源名称 / 版本或未知 / 当前作用域
────────────────────────────────
企业身份       [已登录/其他真实状态]   [前往企业账号]
  身份与CLI绑定相互独立；这里不显示主体信息。
网关凭据       [已配置，未验证等]      [前往凭据设置]
模型设置       [真实状态/未知]         [前往模型设置]
DevOps         [未检查等]              [检查 DevOps]
  原因或下一步；配置来源摘要
Gitee          [未知：目标尚未证实]    [检查 Gitee]
  原因或下一步；配置来源摘要
业务写权限     [保持关闭/本页不提供授权]
────────────────────────────────
▸ 本机差异      ▸ 检查详情      ▸ 公共参数（只读）
```

身份、凭据、模型状态按真实视图分别读取，缺项显示未知，不从IAM登录推导。只显示非敏感状态摘要，不展示账号名、工号或凭据。业务写项是明确边界提示，不制造全局权限查询事实；没有权威读接口时不得声称“已验证关闭”，文案使用“本页不提供业务授权；沿用原写门禁”。

页面不设“全部连接”按钮；分项检查可定位失败与来源。每项默认显示状态、最多两行摘要、一个下一步；更多脱敏细节展开，不隐藏关键错误。没有检查能力时按钮禁用且旁显“未提供已批准的只读检查”。

### 3.2 本机差异（按插件分组）

```text
DevOps                          生效来源：配置/环境/发现/未知
命令行入口 [来源标签]           [重新自动发现（若支持）]
[只读继承值 / 手动覆盖输入]
[改为手动指定] / [恢复继承]
超时（毫秒） [数值]             来源：…
[保存 DevOps 配置]
保存：未保存 / 成功 / 冲突 / 失败
应用：已应用 / 未应用 / 失败 / 未知

Gitee                           （独立同构分组）
命令行入口、超时
[保存 Gitee 配置]
```

初始值来源未知时显示“无法读取，未改动原配置”，不画空白可保存表单。仅编辑已核验非敏感字段。字段提示解释作用，不将路径复制到汇总。自动发现仅对实际提供该能力的插件显示，不能为Gitee套用DevOps发现能力或包装脚本规则。

### 3.3 公共参数与检查详情

公共参数展开顺序：作用域（例如“当前profile”，只能来自真实接口）→ 来源/基准 → 已核验白名单字段 → 权限说明 → 回执。默认“只读：尚无可核验公共维护权限/接口”，本机分区仍可用。只读公共区展示非敏感来源摘要，不露隐藏键；仅获准维护编辑上下文可显示已核验且获准的endpoint实值。

检查详情按 DevOps/Gitee 独立展示四层：文件存在、可启动、目标服务、只读业务访问；每层状态+脱敏证据类型+下一步。无证据层标“未知/未执行”，通过一层不自动点亮后续层。详情页脚显示检查时间、对象别名、配置基准标识、来源类型（本地诊断/夹具/企业真实证据），不含路径、地址和主体。

### 3.4 响应式与几何边界

以r5历史564px内容宽作为参考测试点，不宣称当前宿主实测宽高；内容始终100%适配宿主。宽≥520px行首flex布局：标题flex:1/min-width:0、状态自适应、操作自适应、gap:8px；宽<520px状态和动作换至下一行。字段永远一列。宽320px、200%缩放仍无页面横向滚动；长来源/版本 `overflow-wrap:anywhere`。

总览不强求全部一屏：每行min-height:72px而非固定高，标题说明及来源约96px、六行≥432px、折叠操作≥48px，基础内容≥576px（另含区块间距），小屏正常纵向滚动。禁止沿用r5“501px整页”承诺。操作区不fixed，不遮最后一项；32px按钮容纳单行，换行后高度自增，22px标签同理。焦点轮廓预留4px空间，任何容器不以overflow:hidden裁掉焦点。

## 4. 字段、作用域与权限表

| 对象 | 本机编辑白名单 | 公共区/隐藏策略 | 来源与作用域 |
|---|---|---|---|
| IAM | 本页无 | 登录、凭据、模型配置全部跳原页；无凭据值输入 | 真实IAM非敏感视图；读取失败未知 |
| DevOps | `dopBin`、`timeoutMs` | `dopEndpoint`、`sourceType`不进入普通本机DOM；公共维护未核验前不渲染字段 | 复用现有逐字段配置/环境/自动发现规则；作用域从接口读取 |
| Gitee | `cliPath`、`timeoutMs` | `host`仅在获准维护上下文可编辑；`authEnv`最多显示获准变量名，不读取值；`persistentToken`不开放新编辑、不放宽策略 | 复用既有五键解析；不推断与DevOps同源或同权限 |

公共维护的最终字段白名单、授权来源、实际基准和应用接口为**技术阶段阻断项**：上表不是新授予写能力。IAM公共参数如需维护，使用已有获权入口而不在本页复制字段定义。版本缺失显示“未知”，不自增一个前端版本冒充公共版本。来源标识与基准若包含路径/地址，先投影成安全名称，不把原串当标签。

## 5. 交互、失败及并发语义

1. **进入/返回**：分别读取身份与配置；一项失败不阻断其他项。跳IAM后返回重新读摘要，不存第二份会话。未保存草稿导航时提供“继续编辑/放弃修改”，默认保留；此确认不触发写入。
2. **身份状态**：未配置→前往企业账号查看设置；未登录→前往登录；登录中→回到现有流程取消/完成；已登录→管理账号；过期→重新登录；不可达/安全拒绝→查看现有原因；退出结果未知→前往原页核对。未知不自动清记录。取消与退出不在准备页另实现。
3. **编辑/恢复继承**：切为手动仅生成本地草稿；“恢复继承”先显示“保存后只移除此字段本机覆盖”，预览继承来源（无法解析则未知），可撤销。保存前不改变运行时。自动发现按既有能力执行；若会立即重建，按钮旁事先说明，不伪装成纯草稿操作。
4. **保存**：仅提交当前插件已改已知字段及真实基准；无改动/正在保存时禁用。逐项校验失败将焦点放首个错误，零写入。冲突保留草稿并显示“配置已更新，请重新读取并核对”，不自动覆盖；刷新前确认将如何处置草稿。
5. **应用**：独立呈现保存/应用/检查三行回执。保存即重建的接口：按钮说明“保存后会更新运行时”，成功写“已保存；运行时已应用”，无假“应用”按钮。只有真实分阶段接口才提供“应用到运行时”。应用失败/未知显示已保存和当前生效基准（无法取得则未知），只提供读取核对，不自动重放。
6. **检查**：点击仅运行既有白名单只读能力；检查中显示目标和文字并禁用同项重复操作，不锁其他插件配置。使用当前生效而非未保存草稿；有草稿时先提示“检查使用当前生效配置”。无可用白名单保持未知，不临时拼命令。
7. **失效**：保存/应用或身份上下文变化即将相关历史检查标“已过期”，保留时间与旧基准。以配置基准+身份上下文代次+请求序号识别回包；旧响应丢弃，不能让退出后旧绿灯复活。应用失败降级且仍可读配置，不用新的成功保存覆盖旧失败记录。
8. **复制诊断**：仅复制安全投影：插件名、状态、通用原因码、时间、安全基准、来源类型；不复制编辑值、原始异常、endpoint、绝对/相对路径、IAM主体、token、Key或授权URL。无脱敏保证时禁用并显示原因；复制失败在原位提示，不回显复制内容。保留既有失败面零泄漏保证。

## 6. 状态词与可访问性

| 状态 | 标签/语气 | 下一步 |
|---|---|---|
| 未检查 | 中性“未检查” | 检查对应插件（若有能力） |
| 检查中 | 信息“检查中…” | 等待；无无限成功假象 |
| 通过 | 绿“本项检查通过” | 查看证据；不声称授权/联调 |
| 失败 | 红“检查失败”+脱敏原因 | 修正本机配置或查看安全指引 |
| 未知 | 中性“未知”+证据缺口 | 读取核对/查看能力限制 |
| 已过期 | 中性“已过期”+旧时间 | 重新检查，不直接复用 |
| 未配置/能力不可用 | 警告或中性具体子原因 | 配置对应插件/查看缺失能力 |

- 使用原生button、label/input、details/summary或等价aria-expanded；焦点顺序与视觉从上到下一致。字段提示/error用aria-describedby，invalid设置aria-invalid。
- 每插件回执一个aria-live="polite"区域，结束时播报完整“对象+结果+下一步”；加载容器aria-busy；表单阻断错误用alert一次，不逐帧播报旋转/骨架。
- 状态始终有文字而不只色点。正文对比度≥4.5:1，控件边界/焦点≥3:1；浅/深主题均验证，不用降低透明度让原因不可读。若主题token不达标，报告并选宿主更高对比别名，不硬编码品牌色。
- 独立操作命中区至少24×24px、主要按钮32px高；换行时保持8px间距。折叠后焦点不得落在隐藏内容；对话框关闭返回触发按钮。页面滚动可见全部操作，未检查/未知不强制转移焦点。
- 中文文案为主，英文资源以语义对应同一状态键；不可将unknown译成not configured、applied译成saved。

## 7. 设计验收与技术交接

| PRD | 必须可观察的设计结果 |
|---|---|
| AC-1～3 | 唯一IAM跳转；身份/凭据/模型/CLI分别显示；安全拒绝、退出未知与迟到回包不产生绿灯 |
| AC-4～6 | 来源/版本未知真实可见；两插件独立草稿和保存；恢复继承只删字段覆盖；错误与冲突不丢草稿 |
