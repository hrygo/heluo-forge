# 企业研发设置与 IAM 正式 UI 整合 PRD

> Agent 代拟。需求范围依据本轮用户澄清已确认；技术接线、生产准入与最终验收仍待验证。本文件仅细化本任务，不替代[产品范围唯一真源](<../../requirements/requirements-baseline.md#2-范围边界唯一真源>)。

## 1. 背景与目标

用户需要在现有 DSH 内完成企业研发环境准备，而不是体验另一套模拟账号体系。正式 IAM 已有企业账号入口、登录/退出、onboarding、个人网关凭据与模型设置；企业研发设置应回答“公共参数来自哪里、本机哪里不同、工具检查到哪一步、下一步做什么”。身份已登录、凭据已配置、本机工具可用与业务获权是四件不同的事。

这是已有插件与 Demo 的迭代整合，不是新建身份系统。产品目标：保留 IAM 唯一身份与凭据真源，以真实配置接口连接准备工作，让保存、运行时应用、主动检查各自可见且结果可追溯。

### 现状自查与证据界限（2026-11-06）

- 已阅读[结合核验记录](<../../../demos/enterprise-settings/verification/README.md>)与[Demo 说明](<../../../demos/enterprise-settings/README.md>)：Demo 的三账号、公共版本、应用与检查均为内存 fixture；不能迁移其“应用清空个人连接”行为至正式 IAM。
- 已阅读[IAM 用户指南](<../../../packages/forge-iam/docs/user-guide.md>)：默认安全存储门禁仍可能拒绝登录、刷新及网关写入；既有引导、退出及未知结果处理必须复用，不能为呈现完整流程而解除门禁。
- 已检查[DevOps 配置实现](<../../../packages/forge-devops/src/cli-config.mjs>)：现有普通页仅编辑 dop 入口和超时，隐藏键和来源规则必须保留；保存与自动发现已有真实能力，不应重建第二套解析规则。
- 已检查[Gitee 配置实现](<../../../packages/forge-gitee/src/runtime-config.mjs>)：五键为 `cliPath/host/timeoutMs/authEnv/persistentToken`，默认不注入凭据变量；CLI 名 `gh` 本身不能证明连接的是企业 Gitee。Gitee 包装脚本限制与 DevOps 不完全一致，不在本轮静默放宽。
- 核验记录记载旧全库结果为 2726 项、2723 通过、2 失败、1 跳过，两个宿主探针报 `Cannot read properties of undefined (reading '0')`；本轮仅核对记录，未复跑，不是本轮测试结论。记录中的宿主版本也不得当作当前环境版本。
- 当前工作区实际在 `feat/plugin-workflow`，与启动提示中的 `docs/devops-stage-handoff` 不同；以用户澄清与实际工作区为准。近期 Issue 交付/返工摘要不是本轮 IAM 设置的完整实现证据，不因记录缺失而补造历史依赖。

## 2. 用户故事与验收标准

### 故事 A：研发人员只管理一个企业身份

作为研发人员，我希望从准备页进入已有企业账号能力，而不是再次注册、登录或填写 Key。

| 编号 | 优先级 | 可测试验收标准 |
|---|---|---|
| AC-1 | P0 | 正式 UI 中登录、退出、onboarding、网关凭据、模型设置均复用现有 IAM 能力；新准备页只展示非敏感身份摘要并导航至原入口。新增身份/凭据存储及三个模拟登录入口数量均为 0；取消、退出、未知与安全拒绝走既有语义。 |
| AC-2 | P0 | 覆盖“已登录但 CLI 未配置”“CLI 可读但 IAM 未登录”“Key 已配置但未验证”“检查通过但业务写关闭”四组反例，界面分别显示真实状态，不以任何一项推导其余三项成功；准备汇总始终明确“不代表业务授权”，不得标记真实企业联调已通过。 |
| AC-3 | P0 | 未配置、未登录、登录中、已登录、过期、不可达、退出结果未知均有对应状态与可执行下一步；新页面不得把未知当未配置而清空既有记录。迟到响应不得在退出或切换配置后恢复旧就绪状态；IAM 不可用不阻断查看本机配置。 |

### 故事 B：研发人员只处理本机差异

作为研发人员，我希望预置的企业参数直接可用，仅修正自己电脑上的工具入口，并知道哪一层正在生效。

| 编号 | 优先级 | 可测试验收标准 |
|---|---|---|
| AC-4 | P0 | 展示公共参数来源及版本标识、本机覆盖和最终生效来源；来源/版本无法取得时标“未知”而不编造。字段映射复用 IAM、DevOps、Gitee 真实配置定义，不以 Demo 的地址校验、版本计数或 fixture 作为正式规则。普通研发流程不要求重复填写已预置公共参数。 |
| AC-5 | P0 | 本机差异支持 DevOps/Gitee 既有可配置的非敏感入口与超时；自动发现、手动覆盖、恢复继承均明确说明作用对象。凭据值不进入本页；`authEnv` 仅可能显示允许的变量名，`persistentToken` 策略不因整合放宽。修改一个插件不得修改另一个插件或 IAM 配置。 |
| AC-6 | P0 | 保存仅提交用户修改的已知字段增量；以含隐藏键、未知嵌套键、兄弟插件、注释的夹具验证，无关值及非目标文本不变。恢复继承只移除对应本机覆盖，不删整段配置；非法字段返回逐项原因且零写入。基于过期基准的保存可见冲突，不静默覆盖。 |

### 故事 C：维护者维护公共参数但不取得虚构管理权限

作为获授权的配置维护者，我希望维护既有公共参数，并知道草稿与运行时当前值是否一致。

| 编号 | 优先级 | 可测试验收标准 |
|---|---|---|
| AC-7 | P0 | 公共参数预置与维护接入已有真实配置读写和权限校验，不新增身份/凭据存储，不用 Demo 的“维护者”开关授权。字段白名单、来源、基准标识与实际作用域在设计/技术阶段列明。无可核验维护权限时，显示只读及原因，直接请求写接口同样拒绝且零变更；不得把单机 profile 保存描述成已向企业分发。 |
| AC-8 | P0 | 界面分别呈现“保存配置”“应用到运行时”“运行检查”的作用与结果。保存成功不推导应用成功，应用成功不推导检查成功；既有接口若保存即重建，则明确显示实际已应用而不假造待应用草稿。应用失败/未知保留可核对的保存和生效基准，不自动重放；检查不改配置、不申请业务权限。公共参数更新不清空 IAM 会话、个人 Key 或 onboarding 标记。 |
| AC-9 | P0 | 配置保存/应用或身份上下文变化后，先前检查标“已过期”；检查结果关联当时配置基准、检查时间、对象和来源类型，迟到旧结果不得覆盖当前状态。DevOps 重新发现保留响应前重建的既有保证；应用后下一次读取/工具调用与当前生效状态一致，重建失败显示降级而不是假成功。 |

### 故事 D：研发人员能据证排错而不泄密

作为研发人员，我希望知道 DevOps/Gitee 的准备阻塞在哪一步，而不是看到一个无法解释的总绿灯。

| 编号 | 优先级 | 可测试验收标准 |
|---|---|---|
| AC-10 | P0 | DevOps 与 Gitee 分项给出未检查、检查中、通过、失败、未知、已过期及下一步；可呈现未配置/能力不可用子原因。文件存在、可启动、目标服务及只读业务访问分别按实际取得的证据显示；未取得目标平台证据时，不能仅凭 `gh` 名称判企业 Gitee 就绪。无已批准只读探测命令的项目保持未知，不临时发明命令或执行写探测。 |
| AC-11 | P0 | 主动检查只调用既有白名单只读/本地诊断能力；不得运行建 Issue、评论、push、merge、close、发布或触发流水线。默认写门禁、唯一安全执行出口、超时/输出上限不放宽；用拒绝和成功夹具均断言业务写调用数为 0，IAM token 注入 CLI 次数为 0。 |
| AC-12 | P0 | 路径及 endpoint 实值仅在获准的配置编辑上下文可见，汇总、工具结果、错误、复制诊断、日志与报告不泄漏令牌、Key、授权 URL、原始 CLI 错误或本机绝对路径。脱敏失败反例延续 r9 的 EINVAL/ENOENT/EACCES、相对路径 bin、绝对路径/UNC/URI 六类扫描；不把 IAM 主体或凭据草稿混入研发诊断。 |
| AC-13 | P1 | 在现有设置壳内提供正式入口、分项结果及账号跳转；不以独立网页或 Demo 入口交付。键盘可达全部操作，异步状态可播报；中文主文案与已有英文键保持语义一致，沿用当前主题，不新增品牌体系。旧“设置 → 企业 DevOps”指引仍能到达有效配置能力，不遗留死链或出现第二套身份入口。 |
| AC-14 | P0 | 新增正反例及配置/身份交错回归进入既有 Node 测试发现范围；执行 `pnpm check`、`git diff --check` 并报告真实结果，不删测、降门禁或把既有失败写成通过。独立 profile 的真实浏览器验证覆盖账号导航、保存/应用/检查差异、未知降级与恢复继承；未执行项明确 NOT RUN。证据列出命令/操作、时间、当前宿主版本、目标和来源类型；mock/本地 UI、真实企业联调及双端结果分列。 |
| AC-15 | P1 | 交付可核对的独立 profile 安装及回滚步骤、正式设置使用说明和受影响索引；先盘点既有改动，打包不得包含本地环境、凭据、缓存、测试 profile 或运行日志。未改日常 profile、未推送、未双端验证分别明示；源码提交与否如实报告。 |

## 3. 范围与非目标

本任务范围为上述正式设置整合，具体包含 IAM 复用、公共参数预置/维护、本机差异、DevOps/Gitee 准备诊断和真实配置操作反馈。原有普通 DevOps 页隐藏字段原则继续成立：公共参数维护是独立作用域，不将所有参数塞回普通用户页。现阶段不声明取代既有 AC；若设计决定删除旧入口或更改字段/应用语义，必须先明确新增取代条款，不自行扩张。

非目标：新身份/凭据库、第二套登录、CLI 凭据统一托管或 IAM token 自动注入；开放真实写权限；重做 IAM 安全存储或生产授权协议；企业公共配置分发服务、Demo 维护权限上线；双端验证、推送、发布及真实业务验收。不要求为了完成 UI 而调用收费模型或输入真实凭据。

## 4. anti-goals / 反面目标

1. 用户看到 IAM 已登录或“准备通过”，随即误以为 CLI 已绑定、模型可用或可以写企业业务；即使各接口返回成功也拒收（AC-2、10、11）。
2. 用户点击“保存”看到成功，实际运行时仍用旧值且没有任何提示，或点击“检查”后未知配置/个人 Key 被清空（AC-6、8、9）。
3. 使用者必须在三个模拟登录或两个企业身份页中反复操作，退出后准备页又显示迟到的旧账号绿灯（AC-1、3）。
4. 维护页面自称已更新企业公共配置，实际只改了自己的 profile，或普通用户切换“维护者”就能写公共参数（AC-7）。
5. 排错时复制一份诊断就暴露本机路径、企业地址或凭据，或一眼总览无法定位具体失败项（AC-10、12、13）。

这些失败阈值由用户已明确的身份、安全、保存/应用/检查及证据约束导出，不新增口味性门槛。

## 5. 交互流程摘要

1. 打开正式企业研发设置：读取公共参数来源、本机差异、IAM 非敏感状态；尚未检查的项目不冒充失败或成功。
2. 需要身份或模型操作：跳转既有 IAM 入口，沿用 onboarding 与受控流程；返回后重新读取摘要，不缓存第二份会话。
3. 修正本机差异：编辑 → 字段校验 → 基准核验 → 增量保存 → 独立显示实际应用结果；恢复继承展示将移除哪项覆盖。
4. 获授权维护者：查看公共作用域及来源 → 编辑非敏感白名单 → 保存 → 按真实接口呈现应用结果；权限缺失则只读。
5. 主动检查：明确目标 → 执行已有只读诊断 → 分项结果及下一步 → 汇总准备状态；上下文改变后标过期。失败与未知不触发自动重试写动作。

## 9. 假设与待澄清

- **事实：公共配置作用域与维护授权来源。** 现有 Demo 仅有内存维护视角，尚不能确认哪一真实宿主接口可维护公共预置、权限如何取得及版本由谁提供。推荐默认：先复用已有配置权限与基准；不能核验时公共区只读、保留来源和阻塞说明，本机可维护部分继续；不得宣称公共维护 AC 已完成。若用户要求企业级集中分发或新管理角色，需另行扩范围并调整 AC-4、7、8 与 M1。
- **口味：正式入口的信息架构。** 推荐默认“企业研发”作为准备总览，保留“企业账号”及原“企业 DevOps”有效入口，公共维护单独分区；理由是既能聚合准备状态又不打断现有操作习惯。若用户希望直接替换旧 DevOps 页或将所有设置收在 IAM 下，须调整 AC-13、历史取代条款与导航验收，不能由开发者静默决定。
- **口味：汇总首屏的信息密度。** 推荐默认首屏只显示分项状态、阻塞原因、下一步和来源/版本摘要，参数与原始技术细节按需展开；理由是避免把普通研发页变成维护控制台。若用户更希望全量表格常显，调整 AC-4、10、13 的布局验证，不改变脱敏与授权边界。沿用现有主题，不另设视觉风格问题。
