# AC 证据表模板 · 企业组合包验收（r2）

**适用**：`docs/teamflow/20261106-r2/` 的 14 条 AC（判据见 [PRD](PRD.md) §2 与附录 A）
**数据模型**：与 [TECHNICAL](TECHNICAL.md) §2.4 一致；步骤编号与 `RUNBOOK.md` §0–§8 对齐
**版本**：v1 · 2026-11-06（代拟） **状态**：待验收执行人复制填写
**性质**：只定义结构、字段与判定口径，不含真实证据；`<…>` 为占位符，正式表必须逐项替换。

> 使用本模板产出的证据表，是本单 `ACCEPTANCE.md` 的唯一证据来源。示例（§7）可被 ACCEPTANCE 直接引用为格式与口径依据，但示例中的数值、哈希不得当作本单实测结果。

## 1. 使用顺序

1. 复制本文件为本次验收的证据表（建议 `<evidence-root>/AC-EVIDENCE.md`），保留本文件原样。
2. **先写明细块**（§4）：每条证据一个块，命令、输出摘要、环境、哈希当场记录，不凭记忆补填。
3. **再写汇总台账**（§3.3）：一条证据一行，10 列，与明细块证据ID一一对应。
4. 填 **AC 判定索引**（§3.2）：14 条 AC 逐条给判定与依据证据ID。
5. 填 **顶部四态计数与总判定**（§3.1）：按 §5 的 R13/R14 计算，不手工“看着像通过就写 PASS”。
6. 跑 **机械自检**（§9），全部通过后交复核人签字。

## 2. 术语与判定口径

### 2.1 四种结果（结果列只能取这四值之一）

| 结果 | 含义 | 退出码列 | 是否计入通过 | 后续动作 |
|---|---|---|---|---|
| `PASS` | 命令已在本表声明的环境中真实执行，退出码与预期一致，关键输出与预期关键行一致 | 实际退出码（通常 `0`） | 是 | 继续 |
| `FAIL` | 已执行，但退出码或关键输出与预期不一致 | 实际退出码（非 0） | 否 | 停止该分支，按 RUNBOOK 该段失败分支回滚/清理，记录回滚结果后进入证据归档 |
| `NOT RUN` | 未执行（环境、平台、企业依赖或权限不具备） | `—` | **否**（不得计入通过） | 可继续后续不依赖该项的步骤，但必须留在未关闭项清单 |
| `BLOCKED` | 前置条件不满足导致无法开始（如目标 profile 不可写、pnpm 缺失、磁盘不足） | `—` | 否 | 停止依赖该项的后续步骤，其余不依赖项可继续 |

### 2.2 来源类型（四选一）

| 来源类型 | 定义 | 可作为哪些 AC 的证据 |
|---|---|---|
| `本机实测` | 当前工作机（macOS arm64 / Node v24.13.0 / DSH rc.5）本次真实执行 | 实现类 AC（AC-2/3/4/10/11/12/13 等）；**不得**用于目标机专属项 |
| `目标机实测` | 企业内网目标机（Linux aarch64 / Node v24.15.0 / DSH rc.3）本次真实执行 | 关闭 AC-1、AC-14 的目标项，及 AC-5–AC-9 的企业执行面 |
| `历史实机记录` | 引用既往任务夹或已归档实测记录，本次未复跑 | 仅作旁证；必须写明原日期、原宿主版本与来源文件，且不得单独关闭 AC |
| `未执行` | 与 `NOT RUN` 一一对应；未执行项不得出现 `PASS` | 无 |

> **mock / 夹具**：用 mock、夹具或 dry-run 得到的输出，来源类型仍记 `本机实测`，备注必须写「夹具（mock）；不计企业证据」；若该 AC 要求企业环境，该 AC 判定仍是 `NOT RUN`，不得因为夹具“跑通”记为 PASS。

### 2.3 NOT RUN 原因类别（备注列必填其一）

`宿主版本`（如本机无 rc.3 / v24.15.0）、`平台`（如 Windows、UOS、Kylin）、`企业依赖`（IAM、Gitee、dop、AI 网关、私有 registry）、`权限`（宿主不提供 `stateRoot`/`commitRoot`、应用独占 profile 等）。

原因类别必须与 `RUNBOOK.md` 的 NOT RUN 预判清单条目对应；预判不等于已发生，执行后按实际回填。

### 2.4 步骤编号

| 编号 | 对应 `RUNBOOK.md` 段落 |
|---|---|
| `S0`–`S8` | 0 前置检查 → 1 产物校验 → 2 目标机重建与比对 → 3 安装 → 4 装载检查 → 5 功能抽查 → 6 升级/回退 → 7 卸载/残留 → 8 证据归档 |
| `T-<命令简称>` | 非手册类实现证据（`node --test …`、`pnpm check`、`git diff --check`、构建自检等） |

子步骤写 `S3.2`；同一步骤多条证据按 §5 R2 拆行，不合并。

## 4. 明细块（第二部分）

### 4.1 字段规范

| 字段 | 必填 | 取值 / 格式 | 规则 |
|---|---|---|---|
| 证据ID | 是 | `E-AC<两位AC号>-<两位序号>`，如 `E-AC03-01` | 全局唯一；一条证据只归属一个主 AC |
| AC | 是 | `AC-1`…`AC-14`，兼证多个写 `AC-2, AC-3` | 主 AC 决定证据ID |
| 步骤 / 用例 | 是 | `S0`–`S8` 或 `T-<命令简称>` | 与 RUNBOOK 步骤号对齐 |
| 命令 | 是 | 逐字可复制执行，含子命令、参数、环境变量赋值 | 一行一条；写明工作目录；禁止“见手册”“同上” |
| 预期关键行 | 是 | 命令应出现的关键输出（1–3 行） | 从 RUNBOOK 或契约取原文，不臆造 |
| 实际输出摘要 | 是 | ≤5 行，保留关键行与失败首行 | 完整输出存证据文件；摘要不得改写结论 |
| 退出码 | 是 | `0` / `1` / `2`；`NOT RUN`/`BLOCKED` 写 `—` | 取 `$?` 或 CI 结果，不推断 |
| 结果 | 是 | `PASS` / `FAIL` / `NOT RUN` / `BLOCKED` | 见 §2.1；与退出码、输出一致 |
| 来源类型 | 是 | 见 §2.2 | 与结果列联动：未执行 ⇒ NOT RUN |
| 执行时间 | 是 | `YYYY-MM-DDTHH:MM:SS±HH:MM` | NOT RUN 记登记时间 |
| OS / arch | 是 | 如 `darwin-arm64`、`linux-aarch64` | 取 `uname -sm` 实测；不写主机名 |
| node / npm / pnpm / dsh | 是 | 四个独立字段，各带版本号 | dsh 不可执行时写 `—（dsh 不可执行）` |
| 工作目录 | 是 | `<workspace>` 等占位形式 | 不写个人绝对路径 |
| tarball | 条件 | 文件名 · SHA-256 · 字节数 | 不涉及产物写 `—（本用例不涉及产物）` |
| manifest 摘要 | 条件 | `formatVersion=1 · entry=<name>@<version> · members=<n> · files=<n> · tarball.sha256=<hex>` | 无 manifest 写 `—`；不涉及写 `—（本用例不涉及产物）` |
| 证据文件 | 是 | 相对 `<evidence-root>` 的路径 | 见 §5 R7；无文件写 `—` 并在备注说明原因 |
| 证据文件 SHA-256 | 条件 | 64 位小写 hex | `shasum -a 256 <file>`（macOS）或 `sha256sum <file>`（Linux） |
| 执行人 / 复核人 / 日期 | 是 | 人名或角色代号，日期 `YYYY-MM-DD` | 复核人不得空、不得与执行人相同（单人验收须在备注说明并经用户确认） |
| 脱敏 | 是 | `无` 或 `<规则>（位置：…）` | 凡涉及地址、账号、token、路径必须写明脱敏位置 |
| 备注 | 否 | 原因类别（NOT RUN 必填）、回滚结果（FAIL 必填）、兼 AC、示例标记 | 每条证据一行说明，不写叙事 |

- 工作目录：<workspace>
- 命令：`<逐字命令>`
- 预期关键行：`<…>`
- 实际输出摘要（≤5 行）：
      <关键行 1>

- manifest 摘要：formatVersion=1 · entry=<name>@<version> · members=<n> · files=<n> · tarball.sha256=<64-hex>

## 5. 填写规则

| 编号 | 规则 | 执行要点 |
|---|---|---|
| R1 | 先明细、后汇总 | 明细块是原始记录，汇总表是索引；禁止先填汇总再补明细 |
| R2 | 一行一命令 | 同一命令不同参数/不同环境分两行；复合命令拆成多条证据，不把 `&&` 链当一条 |
| R3 | 结果与退出码绑定 | `PASS` 必须退出码符合预期且关键行出现；退出码非 0 不得写 `PASS`；`FAIL` 不得省略实际退出码 |
| R4 | 环境必须具体 | os/arch + node/npm/pnpm/dsh 五项实测；禁止“同上”“同前”“本机”而无版本 |
| R5 | 来源类型如实 | 本机结果不得冒充目标机；mock 按 §2.2 处理；历史记录标原日期与原版本 |
| R6 | 时间统一 | ISO 8601 带时区；跨时区记录换算后的同一时刻 |
| R7 | 证据文件可追溯 | `<evidence-root>` 在表头声明一次（推荐 `$DSH_HOME/teamflow/<workspace>/logs/<runId>/evidence/`，宿主归档保留；需要随仓库交付时才用 `docs/teamflow/20261106-r2/evidence/` 并经用户确认）；文件只增不改，改一次算新证据新 ID |
| R8 | 产物字段条件必填 | 只要证据涉及 tarball 或 manifest，就必须填 SHA-256 与摘要；断言“核验通过”而无哈希的证据无效 |
| R9 | 空值规则 | 仅允许 `—` 表示 N/A，且必须带原因；空单元格一律视为“未填写”，**不得视为 PASS**；结果列、退出码列、环境列、证据文件列不得为空 |
| R10 | 证据ID 与兼证 | 主 AC 定 ID；一条证据支撑多个 AC 时 AC 列全列、备注写 `兼: AC-x`；一个 AC 至少一条证据 |
| R11 | 脱敏 | 见 §8；脱敏后仍需可复核（保留版本、退出码、关键行与非敏感路径） |
| R12 | 引用旧证据 | 必须标“原日期 + 原 node/pnpm/dsh 版本 + 来源任务夹或归档路径 + 非本单复跑”，且不得单独关闭 AC |
| R13 | AC 判定归并 | 该 AC 任一证据 `FAIL` → `FAIL`；否则任一 `BLOCKED` → `BLOCKED`；否则全部证据 `PASS` → `PASS`；否则有 `PASS` 且其余为本 AC 的环境受限 `NOT RUN` → `PASS（受限）`；否则（无 PASS 或存在实现类缺口）→ `NOT RUN` |
| R14 | 总判定决策顺序 | ① 任一 AC `FAIL` → `FAIL`；② 任一 AC `BLOCKED` → `BLOCKED`；③ 14 条 AC 全 `PASS` → `PASS`；④ 无 FAIL/BLOCKED、14 条 AC 每条至少一条 `PASS` 证据、所有 `NOT RUN` 均属 §2.3 四类原因且已在 RUNBOOK 预判清单登记 → `PASS（受限）`；⑤ 其余（含某条 AC 只有 NOT RUN）→ `NOT RUN`，并在“未关闭 AC”列出全部缺口，不得写成 PASS |
| R15 | 失败与阻塞留痕 | `FAIL` 必须在备注写回滚/清理命令与结果；`NOT RUN` 必须写原因类别；`BLOCKED` 必须写阻塞的前置条件与解除条件 |

## 6. 反例（出现任一项即判证据表不合格）

| 编号 | 反例 | 为什么不合格 | 正确做法 |
|---|---|---|---|
| N1 | `｜ E-AC02-01 ｜ AC-2 ｜ S1 ｜ PASS ｜ ｜ 本机实测 ｜ ｜ ｜`（退出码、环境、时间、证据文件为空） | 空单元格被当成通过；无法复跑，也无法证明执行过 | 补齐五项；无法补齐就改 `NOT RUN` 并写原因 |
| N2 | 四态计数 `NOT RUN：2` 而总判定写 `PASS` | NOT RUN 不计通过；总判定与计数矛盾 | 按 R14 判为 `PASS（受限）` 或 `NOT RUN`，并列出未关闭 AC |
| N3 | 用本地 mock 的 200 响应记为「企业 IAM 联调 PASS」 | mock 不是企业证据，来源类型被伪报 | 来源记 `本机实测` + 备注「夹具（mock），不计企业证据」；该 AC 记 `NOT RUN`（企业依赖） |
| N4 | 引用 r12 任务夹的 rc.5 输出，写成 `本机实测 / 2026-11-06` | 旧证据冒充本单复跑，日期与版本失真 | 写 `历史实机记录` + 原日期 + 原版本 + 来源路径 + 「非本单复跑」 |
| N5 | 结果 `PASS` 但退出码 `1`，或输出摘要首行为 `Error:` | 结论与原始信号矛盾 | 结果改 `FAIL`，记录失败首行与回滚结果 |
| N6 | 命令列写「见 RUNBOOK」「同前」「按文档执行」 | 不可复跑，验收人无法独立复核 | 逐字写命令、参数、工作目录与环境变量 |
| N7 | 环境列写「本机」「同上」「Linux」 | 缺版本与架构，跨机差异无法归因 | 写 `linux-aarch64；node v24.15.0；pnpm 11.28.5；dsh 0.2.1-rc.3` |
| N8 | 证据文件指向个人目录，或备注粘贴通道 token / 内网地址 | 触发敏感扫描，文档不可提交 | 用 `<workspace>`、`corp.example` 占位，按 §8 脱敏并注明规则 |

## 8. 脱敏与占位符

### 8.1 统一占位符

| 对象 | 占位写法 | 禁止写法 |
|---|---|---|
| 企业域名 / 制品源 | `corp.example`、`registry.corp.example` | 任何真实内网域名 |
| 主机 / IP | `<target-host>`、`127.0.0.1:9`（仅用于离线测试场景） | 真实主机名、内网 IP 段 |
| profile / 安装目录 | `<profile>`、`<workspace>`、`<outdir>` | 个人目录绝对路径 |
| 账号 / token | `svc-ci`、`<token>`、`<redacted:token>` | 明文凭据、Cookie、通道密钥 |
| 日志根 | `<evidence-root>`、`$DSH_HOME/teamflow/<workspace>/…` | 个人机器的绝对路径 |

### 8.2 脱敏规则

1. 地址类：保留协议与占位域名，路径只保留到组件级（如 `https://corp.example/<api>/issues`）。
2. 凭据类：整体替换为 `<redacted:token>`，不保留前后缀；命令中的凭据用环境变量名代替（如 `$IAM_TOKEN`）。
3. 路径类：仓库用 `<workspace>/…`，日志用 `<evidence-root>/…`；版本号与文件名保留。
4. 脱敏后必须仍可复核：保留退出码、关键行、版本、错误类型；只删敏感值，不改结论。
5. 每条脱敏证据在 `脱敏` 字段写规则与位置，例：`规则 2（命令内 token）；位置：命令、输出第 3 行`。

### 8.3 敏感自检命令（在填写后的证据表上执行，期望无输出）

```sh
grep -nE '(gh[p]_|glpa[t]-|Beare[r] |/Use[r]s/|/hom[e]/|10\.[0-9]+\.[0-9]+\.[0-9]+|192\.168\.)' <evidence-root>/AC-EVIDENCE.md
```

> 正则中的 `[]` 仅用于避免本模板自身命中；证据表内**不得出现**这些字面量。另可用仓库既有 `node scripts/sensitive-scan/verify.mjs --base origin/main --head HEAD` 复核随仓库提交的文档。

## 9. 机械自检（复制后执行，全部满足再交复核）

在证据表副本上逐项执行（`<file>` 替换为证据表路径）：

1. **汇总表 10 列** —— `awk -F'|' '/^\| 证据ID \|/{print NF-2; exit}' <file>`，期望输出 `10`。
2. **证据ID 无重复** —— `grep -oE '^\| E-AC[0-9]{2}-[0-9]{2}' <file> | sort | uniq -d`，期望无输出。
3. **四态计数与行一致** —— `awk -F'|' '/^\| E-AC[0-9]{2}-[0-9]{2} /{gsub(/^ +| +$/,"",$5); c[$5]++} END{for(k in c) printf "%s=%d ",k,c[k]; print ""}' <file>`，输出须与 §3.1 的计数逐项相等。
4. **无空单元格** —— `grep -nE '^\| E-AC[0-9]{2}-[0-9]{2}.*\|[ ]*\|[ ]*\|' <file>`，期望无输出（`—` 占位不算空）。
5. **NOT RUN 均带原因** —— `grep -nE '^\| E-AC[0-9]{2}-[0-9]{2} .*\| NOT RUN \|' <file> | grep -v '原因：'`，期望无输出。
6. **FAIL 均带回滚记录** —— `grep -nE '^\| E-AC[0-9]{2}-[0-9]{2} .*\| FAIL \|' <file> | grep -v '回滚'`，期望无输出。
7. **敏感信息** —— 执行 §8.3 命令，期望无输出。
8. **AC 索引齐全** —— `grep -cE '^\| AC-[0-9]+ ' <file>`，期望 `≥14`（14 条 AC 不得缺行）。

任一检查不通过：回到明细块补齐真实值，不得为了过检查改判定或删行。

## 10. 与 RUNBOOK / ACCEPTANCE 的衔接

- `RUNBOOK.md` §0–§8 每条命令对应至少一行证据；手册未执行的命令在表中必须是 `NOT RUN` 且有原因，不允许“只有预期、没有记录”的第三态。
- `ACCEPTANCE.md` 的逐 AC 判定必须能由本表 §3.2 逐行复现（同一 AC、同一判定、同一依据证据ID），总判定引用 §3.1；验收报告如需附证据，整体粘贴 §3.1–§3.3，不复制明细全文。
- 本单已知的目标专属缺口（AC-1 目标机 v24.15.0 重建、AC-14 的 rc.3 执行结果）在本机只能记 `NOT RUN`；实现类证据全部 PASS 时按 R14 得 `PASS（受限）`，不得写成 `PASS`。
- 模板自身的一致性由 §9 检查；模板修改须同步 [PRD](PRD.md) AC-10/AC-11 与 [TECHNICAL](TECHNICAL.md) §2.4 的字段口径。
